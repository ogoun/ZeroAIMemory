# BM25: смысл параметров k1 и b

Разбирал формулу Okapi BM25 заново, потому что в обсуждении гибридного поиска все ссылались на «дефолты» и никто не мог объяснить, что они делают. Записываю, чтобы не разбирать в третий раз.

## Формула

Для запроса Q из термов q и документа D:

```
score(D, Q) = Σ IDF(q) · tf(q,D)·(k1 + 1) / ( tf(q,D) + k1·(1 − b + b·|D|/avgdl) )
IDF(q)      = ln( (N − n(q) + 0.5) / (n(q) + 0.5) + 1 )
```

- `tf(q,D)` — сколько раз терм встретился в документе;
- `|D|` — длина документа в токенах, `avgdl` — средняя длина по коллекции;
- `N` — число документов, `n(q)` — сколько документов содержат терм.

Вариант IDF с «+1» внутри логарифма взят из Lucene: он не даёт отрицательных весов у очень частых термов. В классической записи Робертсона «+1» нет, и терм, встречающийся больше чем в половине документов, штрафует документ.

## k1 — насыщение частоты

k1 управляет тем, как быстро растёт вклад повторов терма. При k1 = 0 частота вообще не важна (булево совпадение с весом IDF). При больших k1 поведение приближается к линейному росту по tf. Типичный диапазон 1.2–2.0; в Lucene и Elasticsearch по умолчанию 1.2. Предел вклада одного терма при tf → ∞ равен IDF·(k1 + 1), то есть насыщение есть всегда.

## b — нормализация длины

b задаёт, насколько длинный документ «разбавляет» совпадения. b = 0 — длина игнорируется, b = 1 — полная нормализация относительно avgdl. Стандарт 0.75. Для коллекций, где длина почти не связана с релевантностью (короткие карточки, заголовки), b стоит уменьшать; для смеси коротких заметок и длинных выгрузок логов — оставлять высоким, иначе длинный лог выигрывает просто числом совпадений.

## Наблюдения

- Подбор k1/b даёт обычно единицы процентов nDCG, не десятки. Токенизация и стемминг влияют сильнее.
- В SQLite FTS5 функция `bm25()` использует жёстко зашитые k1 = 1.2 и b = 0.75, менять можно только веса столбцов. Знак у неё отрицательный: чем меньше число, тем лучше совпадение.
- Если документы режутся на фрагменты, avgdl считается уже по фрагментам — нормализация длины фактически теряет смысл при равных размерах фрагментов.
