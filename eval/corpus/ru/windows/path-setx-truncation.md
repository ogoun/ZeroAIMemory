# PATH на Windows: почему setx обрезает его до 1024 символов

Инцидент: после установки очередного инструмента по инструкции из README выполнили

```
setx PATH "%PATH%;C:\tools\bin"
```

и получили предупреждение `WARNING: The data being saved is truncated to 1024 characters.`
После перезапуска терминала половина команд перестала находиться: хвост пользовательского
PATH был отрезан.

## Что пошло не так

1. **Лимит setx.** `setx` записывает значение не длиннее 1024 символов и молча (только с
   предупреждением) обрезает остальное. Сам лимит переменной окружения в Windows — 32 767
   символов, так что ограничение именно в утилите.
2. **Смешение уровней.** `%PATH%` в cmd — это уже объединённый PATH: системный плюс
   пользовательский. `setx` без `/M` пишет в пользовательский. В результате весь системный
   PATH копируется в пользовательский, дублируется, и длина быстро уходит за 1024.
3. **Потеря `%VAR%`.** В реестре PATH хранится как `REG_EXPAND_SZ` с конструкциями вроде
   `%USERPROFILE%\.cargo\bin`. Через `%PATH%` они приходят уже раскрытыми, и ссылка
   превращается в жёсткий путь.

## Где PATH хранится

- пользовательский: `HKCU\Environment`, значение `Path`;
- системный: `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment`, значение `Path`.

## Как добавлять правильно

Через PowerShell, работая только с пользовательским уровнем:

```powershell
$user = [Environment]::GetEnvironmentVariable('Path', 'User')
if ($user -notlike '*C:\tools\bin*') {
    [Environment]::SetEnvironmentVariable('Path', "$user;C:\tools\bin", 'User')
}
```

Тонкость: этот способ записывает значение как `REG_SZ`, и переменные внутри (`%USERPROFILE%`)
перестают раскрываться. Если в PATH есть такие ссылки — редактировать через окно
«Переменные среды» (`rundll32 sysdm.cpl,EditEnvironmentVariables`), где у каждого элемента
своя строка и тип значения сохраняется.

## Почему новое значение «не видно»

Изменение попадает в реестр и рассылается сообщением `WM_SETTINGCHANGE`. Проводник его
получает, а уже открытые терминалы, IDE и их дочерние процессы — нет: они живут со своей
копией окружения. Нужно перезапустить терминал, а иногда и саму IDE, если терминал открыт
внутри неё.

## Как восстановить после обрезки

Старое значение лежит в резервных копиях реестра только если их делали. Практичнее
собрать PATH заново: посмотреть, какие каталоги нужны (`where git`, `where python` на
другой машине, установщики инструментов), и вписать их через окно «Переменные среды».
