# Длинные пути: MAX_PATH, LongPathsEnabled и префикс \\?\

Классическое ограничение Win32 API — `MAX_PATH` = 260 символов на полный путь, включая букву
диска и завершающий ноль. NTFS сама по себе хранит пути до ~32 767 символов, ограничение
живёт в слое API и в приложениях, а не в файловой системе.

## Как проявляется

- `git clone` или `git checkout` падает с `error: unable to create file ...: Filename too long`.
- Распаковка архива с глубоко вложенными каталогами (`node_modules`, вендоринг) обрывается.
- Удалить каталог через Проводник невозможно: «Слишком длинное имя файла».
- Сборка падает с «The system cannot find the path specified», хотя файл есть.

## Включить длинные пути в системе

Начиная с Windows 10 1607 ограничение можно снять, но только для приложений, которые явно
объявили поддержку в манифесте (`longPathAware`). Включение в реестре:

```powershell
New-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem' `
  -Name LongPathsEnabled -Value 1 -PropertyType DWORD -Force
```

То же самое — через групповую политику «Включить длинные пути Win32». Нужны права
администратора, процессы подхватывают настройку после перезапуска. Важно: без манифеста
приложения ничего не изменится — например, Проводник до сих пор работает с коротким
лимитом.

Для git отдельно:

```
git config --system core.longpaths true
```

## Префикс \\?\

Если путь начинается с `\\?\`, Win32 API передаёт его почти без обработки, и лимит 260 не
действует (до ~32 767 символов) даже без настройки реестра:

```
\\?\C:\very\deep\path\file.txt
\\?\UNC\server\share\deep\path
```

Ограничения префикса:

- путь должен быть абсолютным;
- разделители — только обратные слеши, `/` не преобразуется;
- `.` и `..` не раскрываются;
- не все утилиты принимают такой путь.

Удобный трюк для удаления «неудаляемого» дерева: `rd /s /q "\\?\C:\path\to\dir"`.

## Обходные пути без настроек

- Клонировать в короткий корень: `C:\s\` вместо `C:\Users\имя\Documents\GitHub\...`.
- `subst X: C:\Users\me\Documents\very\long\root` — виртуальный диск, укорачивающий путь.
- `robocopy` умеет работать с длинными путями — им можно перенести или «зачистить» дерево
  (копированием пустого каталога с `/MIR` поверх).
