# WSL2: почему проект на /mnt/c работает медленно

Наблюдение: в WSL2 `git status` в репозитории на `/mnt/c/src/app` идёт несколько секунд,
установка зависимостей — в разы дольше, чем на Linux, сборка с тысячами мелких файлов
тормозит. Тот же репозиторий, склонированный в `~/src/app` внутри WSL, работает с нормальной
скоростью.

## Почему так

WSL2 — это настоящая виртуальная машина с ядром Linux и собственной файловой системой ext4
в виртуальном диске (`ext4.vhdx`). Диски Windows видны внутри как `/mnt/c`, `/mnt/d`, но
доступ к ним идёт по сети через протокол 9P между виртуальной машиной и Windows. Каждое
обращение к метаданным файла — это сетевой запрос. На операциях вида «прочитать stat у 50
тысяч файлов» задержки складываются в секунды.

В WSL1 ситуация обратная: там нет виртуальной машины, и `/mnt/c` относительно быстр, а
«родная» файловая система медленнее.

## Что делать

1. Держать исходники внутри WSL: `~/src/...`. Это главная рекомендация.
2. Открывать их из Windows по пути `\\wsl.localhost\Ubuntu\home\me\src\app` (старый вариант
   `\\wsl$\Ubuntu\...`). Теперь медленным становится доступ со стороны Windows, но
   редакторы с удалённым режимом (VS Code + расширение WSL) работают на стороне Linux и
   этого не замечают.
3. Не запускать один и тот же репозиторий одновременно из Windows-git и Linux-git: у них
   разные настройки переводов строк и прав, индекс будет постоянно пересчитываться.

## Сопутствующие проблемы /mnt/c

- **Права.** По умолчанию все файлы на `/mnt/c` выглядят как `rwxrwxrwx`, `chmod` ничего не
  меняет, и git видит изменение режима у каждого файла. Включить хранение Linux-прав в
  расширенных атрибутах NTFS:

  ```ini
  # /etc/wsl.conf
  [automount]
  options = "metadata,umask=22,fmask=11"
  ```

  После правки нужно выполнить `wsl --shutdown` из Windows и открыть дистрибутив заново.
- **Слежение за файлами.** inotify не получает событий об изменениях, сделанных
  Windows-программами в `/mnt/c`, поэтому dev-серверы с автоперезагрузкой не видят правок.
  Либо переносить проект внутрь WSL, либо включать опрос (polling) в инструменте.
- **Регистр имён.** NTFS по умолчанию нечувствительна к регистру, а Linux-инструменты на это
  рассчитывают. Для каталога можно включить чувствительность:
  `fsutil.exe file setCaseSensitiveInfo C:\src\app enable`.

## Как измерить

```bash
time git status            # в /mnt/c и в ~ — разница обычно на порядок
time find . -type f | wc -l
```

Если разница огромная, вопрос решается переносом проекта, а не тюнингом.
