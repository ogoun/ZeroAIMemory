# Фоновые задачи на Windows: службы (sc.exe), планировщик (schtasks), robocopy и icacls

Разбор того, как мы поставили на Windows-сервер ночное зеркалирование каталога данных и
долгоживущий агент. По пути собралась вся типовая обвязка: служба, задание планировщика,
копирование и права на каталоги. Записываю, чтобы в следующий раз не наступать на те же
грабли.

## Когда служба, а когда задание планировщика

| Нужно | Выбор |
|---|---|
| Процесс работает постоянно, перезапускается при падении | служба |
| Запуск по расписанию, отработал и завершился | задание планировщика |
| Запуск при входе конкретного пользователя, с доступом к его рабочему столу | задание планировщика с триггером входа |
| Запуск до входа любого пользователя | служба или задание с `/SC ONSTART` от SYSTEM |

## Службы и sc.exe

### Важная мелочь про PowerShell

В PowerShell `sc` — это псевдоним `Set-Content`, а не управление службами. Команда
`sc create ...` в PowerShell молча создаст файл с именем `create`. Всегда писать `sc.exe`.

### Создание

```
sc.exe create MyAgent binPath= "C:\apps\agent\agent.exe --config C:\apps\agent\agent.toml" start= auto DisplayName= "My Agent"
sc.exe description MyAgent "Фоновый агент синхронизации"
sc.exe start MyAgent
sc.exe query MyAgent
```

Синтаксис `sc.exe` капризный: после `binPath=`, `start=`, `obj=` **обязателен пробел**, а
перед `=` пробела быть не должно. Ошибка в этом месте даёт невнятную справку вместо
создания службы. Путь с пробелами внутри `binPath` нужно заключать в экранированные кавычки:
`binPath= "\"C:\Program Files\agent\agent.exe\" --flag"`.

### Ошибка 1053

```
Error 1053: The service did not respond to the start or control request in a timely fashion.
```

Самая частая причина — в `binPath` указана обычная консольная программа, которая не
реализует протокол диспетчера служб (SCM): она не сообщает о запуске, и через 30 секунд SCM
считает старт неудачным. Варианты:

- реализовать в программе обработчик службы (во многих языках есть библиотеки для этого);
- запускать через обёртку: WinSW или NSSM — они сами разговаривают с SCM и держат дочерний
  процесс, перенаправляя его вывод в лог.

Вторая частая причина — программа падает при старте, потому что служба работает с другим
текущим каталогом (`C:\Windows\System32`) и не находит относительные пути к конфигам.
Всегда передавать абсолютные пути.

### Учётная запись

| Учётная запись | Права |
|---|---|
| `LocalSystem` | полный доступ к машине, в сети выступает как компьютер |
| `NT AUTHORITY\LocalService` | минимальные права, в сети анонимен |
| `NT AUTHORITY\NetworkService` | минимальные права, в сети как компьютер |
| виртуальная `NT SERVICE\MyAgent` | своя изолированная учётная запись службы |

Задать: `sc.exe config MyAgent obj= "NT AUTHORITY\LocalService"`. Мы используем
виртуальную учётную запись службы и выдаём ей права точечно через `icacls` (ниже).

### Перезапуск при падении

```
sc.exe failure MyAgent reset= 86400 actions= restart/5000/restart/5000/restart/60000
sc.exe qfailure MyAgent
```

Счётчик сбоев сбрасывается через сутки (`reset=` в секундах), первые два перезапуска — через
5 секунд, дальше через минуту.

Удаление: `sc.exe stop MyAgent` и `sc.exe delete MyAgent`. Если оснастка `services.msc`
открыта, служба помечается на удаление и исчезает только после закрытия оснастки.

## Планировщик и schtasks

```
schtasks /Create /TN "Backup\NightlyMirror" /TR "C:\apps\backup\mirror.cmd" /SC DAILY /ST 02:30 /RU SYSTEM /RL HIGHEST
schtasks /Query /TN "Backup\NightlyMirror" /V /FO LIST
schtasks /Run /TN "Backup\NightlyMirror"
schtasks /Delete /TN "Backup\NightlyMirror" /F
```

- `/RU SYSTEM` — задание работает без входа пользователя и без пароля.
- Если нужен конкретный пользователь, но без интерактивного входа, в графическом интерфейсе
  это флажок «Выполнять для всех пользователей»; через `schtasks` — `/RU user /RP *`.
- `/TN` с обратным слешем кладёт задание в папку библиотеки планировщика — удобно
  группировать свои задания.

«Результат последнего запуска» `0x1` или другой ненулевой код — это код выхода программы.
Планировщик считает успехом только 0, а это важно для robocopy.

## robocopy и его коды выхода

```
robocopy D:\data \\backup01\mirror\data /MIR /R:2 /W:5 /NP /LOG+:C:\logs\mirror.log
```

- `/MIR` — зеркало: копирует новое и **удаляет** в приёмнике всё, чего нет в источнике.
  Перепутать источник и приёмник — значит стереть данные. Проверять первым запуском с `/L`
  (только список, без действий).
- `/R:2 /W:5` — два повтора с паузой 5 секунд. По умолчанию миллион повторов по 30 секунд,
  и задание «висит» сутками на одном занятом файле.
- `/NP` — без процентов, иначе лог раздувается.
- `/Z` или `/J` — режим перезапуска или небуферизованный ввод-вывод для больших файлов.

Коды выхода robocopy — битовая маска, а не «0 = успех»:

| Код | Значение |
|---|---|
| 0 | ничего не скопировано, всё совпадает |
| 1 | файлы скопированы |
| 2 | в приёмнике есть лишние файлы |
| 4 | обнаружены несовпадения |
| 8 и выше | были ошибки копирования |

Коды меньше 8 — успех. Обёртка для планировщика:

```bat
@echo off
robocopy D:\data \\backup01\mirror\data /MIR /R:2 /W:5 /NP /LOG+:C:\logs\mirror.log
if %ERRORLEVEL% GEQ 8 exit /b %ERRORLEVEL%
exit /b 0
```

## Права на каталоги: icacls

Служба под виртуальной учётной записью по умолчанию не может писать в каталог данных.
Выдать изменение с наследованием на подпапки и файлы:

```
icacls D:\data\agent /grant "NT SERVICE\MyAgent:(OI)(CI)M"
icacls D:\data\agent
```

- `(OI)` — наследуют файлы, `(CI)` — наследуют подкаталоги.
- `M` — изменение, `RX` — чтение и выполнение, `F` — полный доступ.
- `/inheritance:r` — убрать унаследованные права (оставить только явные); полезно для
  каталога с секретами.
- `/T` — применить рекурсивно к существующему содержимому.
- `icacls D:\data /save acl.txt /T` и `/restore` — сохранить и восстановить ACL перед
  экспериментами.

## Итоговый чек-лист

1. Агент — служба через WinSW, учётная запись `NT SERVICE\...`, перезапуск через
   `sc.exe failure`.
2. Каталоги агента — права через `icacls` с `(OI)(CI)`.
3. Резервное копирование — задание `schtasks` от SYSTEM, robocopy через обёртку, которая
   переводит коды меньше 8 в 0.
4. Первый прогон robocopy — с `/L`; лог — с `/LOG+` и ротацией на стороне задания.
5. В PowerShell — только `sc.exe`, никогда `sc`.
