# Исключения Microsoft Defender для каталогов сборки

Сборка крупного проекта на Windows заметно медленнее, чем на Linux на том же железе. Одна из
главных причин — проверка в реальном времени: Defender сканирует каждый создаваемый
компилятором объектный файл и каждый распакованный пакет. В диспетчере задач это видно как
высокая загрузка процесса `MsMpEng.exe` во время сборки.

Добавить исключение (PowerShell от администратора):

```powershell
Add-MpPreference -ExclusionPath 'D:\src'
Add-MpPreference -ExclusionPath "$env:USERPROFILE\.cargo"
Get-MpPreference | Select-Object -ExpandProperty ExclusionPath
```

Есть ещё `-ExclusionProcess` — исключает файлы, которые открывает указанный процесс. Это
шире и опаснее: под исключение попадает всё, что этот процесс тронет.

На Windows 11 альтернатива — Dev Drive: отдельный том ReFS, на котором Defender работает в
асинхронном режиме производительности. Выигрыш близок к исключению, но защита сохраняется.

Риски: исключённый каталог перестаёт проверяться, и вредоносный пакет из зависимостей
пройдёт незамеченным. Исключать только каталоги с исходниками и кэшами сборки, а не весь
профиль или диск. В корпоративной сети исключения обычно управляются политикой, и локальная
команда будет проигнорирована.
