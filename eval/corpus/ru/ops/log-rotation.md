# Ротация логов через logrotate: copytruncate или postrotate

Диск на сервере отчётов заполнился за ночь: `app.log` вырос до 40 ГБ. logrotate был
настроен, файл переименовывался в `app.log.1`, но приложение продолжало писать в старый
дескриптор — то есть в переименованный файл, а новый `app.log` оставался пустым.

Два рабочих варианта:

```
/var/log/myapp/*.log {
    daily
    rotate 14
    compress
    delaycompress
    missingok
    notifempty
    postrotate
        systemctl kill -s HUP myapp.service
    endscript
}
```

- **postrotate + сигнал** — приложение по SIGHUP переоткрывает файл. Правильный способ, если
  приложение это умеет (nginx переоткрывает логи по USR1).
- **copytruncate** — logrotate копирует файл и обрезает исходный до нуля. Работает с любым
  приложением, но строки, записанные между копированием и обрезкой, теряются, а писатель
  должен открывать файл в режиме дозаписи (`O_APPEND`), иначе после обрезки появится «дыра»
  из нулей.

`delaycompress` оставляет вчерашний файл несжатым — на случай, если процесс ещё дописывает
в него. Проверка конфига без действий: `logrotate -d /etc/logrotate.d/myapp`.
