# Теги: аннотированные и лёгкие

Лёгкий тег (`git tag v1.2.0`) — просто имя, указывающее на коммит, как ветка, которая не
двигается. Аннотированный (`git tag -a v1.2.0 -m "Релиз 1.2.0"`) — отдельный объект в базе:
автор, дата, сообщение, по желанию подпись (`-s`).

Для релизов используем только аннотированные:

- `git describe` по умолчанию учитывает только их (лёгкие — с флагом `--tags`);
- `git push --follow-tags` отправляет вместе с коммитами только аннотированные теги;
- видно, кто и когда поставил релиз.

Лёгкие — для личных пометок вроде `before-big-refactor`.

```bash
git push origin v1.2.0                 # теги по умолчанию не уходят с обычным push
git tag -d v1.2.0                      # удалить локально
git push origin --delete v1.2.0        # удалить на сервере
git cat-file -t v1.2.0                 # tag — аннотированный, commit — лёгкий
```

Переставлять опубликованный тег (`git tag -f`) не стоит: у тех, кто его уже скачал, `git fetch`
старый тег не обновит, а отклонит с `would clobber existing tag`. Лучше выпустить `v1.2.1`.
