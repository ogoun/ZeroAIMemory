# git clean -fdx: чистка рабочего каталога без сюрпризов

После переключения между старыми и новыми ветками в каталоге копится мусор: сгенерированные
файлы, старые артефакты сборки, забытые черновики. Иногда сборка ведёт себя странно именно
из-за них. Для «как после свежего клона» есть `git clean`.

## Флаги

| Флаг | Значение                                                                  |
|------|---------------------------------------------------------------------------|
| `-n` | пробный прогон: только показать, что будет удалено                        |
| `-f` | действительно удалять (без него git откажется при `clean.requireForce`)   |
| `-d` | заходить в неотслеживаемые каталоги и удалять их целиком                  |
| `-x` | удалять и то, что попадает под `.gitignore` (сборка, зависимости, `.env`) |
| `-X` | удалять **только** игнорируемое, неотслеживаемые свои файлы оставить      |
| `-i` | интерактивный выбор                                                       |
| `-e <шаблон>` | дополнительно исключить из удаления                              |

## Грабли

`git clean -fdx` удаляет **всё**, чего нет в индексе: локальные `.env` с ключами, настройки
IDE, файлы, которые вы только что создали и ещё не добавили через `git add`. В корзину они не
попадают, и git восстановить их не может: их никогда не было в репозитории.

Был случай: разработчик запустил `git clean -fdx` в корне монорепозитория, чтобы починить
сборку, и потерял неделю работы над новым модулем — файлы просто не были добавлены в индекс.

## Как пользуемся

```bash
git clean -ndx                          # сначала всегда смотрим список
git clean -fdx -e .env -e .idea/        # сохранить локальные настройки
git clean -fdX                          # снести только сборку и кэши, свои новые файлы не трогать
```

Для полной очистки со сбросом правок в отслеживаемых файлах:

```bash
git reset --hard && git clean -fdx
```

Это два независимых шага: `reset --hard` возвращает отслеживаемые файлы, `clean` удаляет
неотслеживаемые. Ни один не делает работу другого.

Вложенные репозитории (каталоги со своим `.git`) `clean -d` не трогает — нужен двойной `-f`
(`git clean -ffdx`). Для подмодулей: `git submodule foreach --recursive git clean -fdx`.

Перед любой «генеральной уборкой» полезно сделать `git stash push -u` — неотслеживаемые файлы
окажутся в stash, и их можно будет вернуть.
