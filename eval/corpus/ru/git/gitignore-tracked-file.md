# .gitignore не игнорирует файл, который уже в репозитории

Типичная ситуация: в репозиторий случайно закоммитили `config/local.toml` с паролем к базе,
потом добавили его в `.gitignore`, а git продолжает показывать изменения в нём.

## Почему так

`.gitignore` влияет только на **неотслеживаемые** файлы: решает, показывать ли их в
`git status` и добавлять ли через `git add .`. Если файл уже есть в индексе, правила игнора
к нему не применяются вовсе.

Проверить, почему файл игнорируется или нет:

```bash
git check-ignore -v config/local.toml     # какое правило и из какого файла сработало
git ls-files config/local.toml            # если выводит путь — файл отслеживается
```

## Решение

Убрать файл из индекса, оставив на диске:

```bash
git rm --cached config/local.toml
git commit -m "Перестать отслеживать локальный конфиг"
```

Для каталога — `git rm -r --cached build/`. Чтобы после правки `.gitignore` разом применить
его ко всему репозиторию:

```bash
git rm -r --cached .
git add .
git commit -m "Применить .gitignore"
```

Важно: у коллег после `git pull` этот файл **удалится** с диска, потому что в истории это
выглядит как удаление. Перед пушем предупредить, чтобы сохранили свои копии, и положить в
репозиторий шаблон `config/local.example.toml`.

## Если в файле был секрет

`git rm --cached` убирает файл только из следующих коммитов, в истории он остаётся. Пароль
считаем скомпрометированным и меняем. Вычистить историю можно через `git filter-repo
--invert-paths --path config/local.toml`, но это переписывает все хеши, и всем придётся
переклонировать репозиторий; копии на сервере и в форках так не удаляются.

## Не путать с assume-unchanged и skip-worktree

Иногда хотят, чтобы файл остался в репозитории, но локальные правки в нём не мешали:

```bash
git update-index --skip-worktree config/settings.toml
git update-index --no-skip-worktree config/settings.toml   # вернуть
git ls-files -v | grep '^S'                                 # список таких файлов
```

Это локальная пометка, она не передаётся другим и может слететь при переключении веток, если
файл там отличается. `--assume-unchanged` по документации — оптимизация производительности, а
не способ игнорировать правки; для этой цели правильнее `--skip-worktree`. Надёжнее всего —
шаблон в репозитории и реальный файл в `.gitignore`.

## Глобальный игнор

Мусор конкретного редактора или ОС (`.idea/`, `.DS_Store`, `*.swp`) не тащим в `.gitignore`
проекта, а кладём в личный файл:

```bash
git config --global core.excludesFile ~/.config/git/ignore
```

Для игнора только в своей копии репозитория есть `.git/info/exclude`.
