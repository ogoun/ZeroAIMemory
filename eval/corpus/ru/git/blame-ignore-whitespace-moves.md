# blame сквозь переформатирование и перенос кода

После массового `cargo fmt` и разнесения модуля на несколько файлов `git blame` показывает
автором каждой строки того, кто форматировал. Что помогает:

```bash
git blame -w src/report.rs          # игнорировать изменения пробелов
git blame -w -M src/report.rs       # плюс строки, перемещённые внутри файла
git blame -w -C src/report.rs       # плюс строки, пришедшие из других файлов того же коммита
git blame -w -C -C -C src/report.rs # искать источник во всех файлах любых коммитов (медленно)
```

Для коммитов, которые только переформатируют код, заводим файл со списком их хешей:

```bash
git config blame.ignoreRevsFile .git-blame-ignore-revs
```

В `.git-blame-ignore-revs` — по хешу на строку, с комментарием `#`. GitHub читает этот файл
автоматически. Строки, у которых не удалось найти другого автора, помечаются `?` или `*` при
включённых `blame.markUnblamableLines` / `blame.markIgnoredLines`.

Для вопроса «когда исчезла эта строка» blame не подходит — лучше `git log -S 'текст' -p` или
`git log -L 10,30:src/report.rs`.
