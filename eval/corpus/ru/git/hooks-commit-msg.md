# Хуки git: pre-commit и commit-msg своими руками

Нам нужно было две вещи: не пускать в репозиторий коммиты с несобирающимся форматированием и
требовать номер задачи в сообщении. Сторонние фреймворки не хотели тащить, сделали на
встроенных хуках.

## Как устроены хуки

Хук — исполняемый файл в `.git/hooks/` с определённым именем. Git запускает его в нужный
момент; ненулевой код возврата у «pre»-хуков отменяет операцию. Каталог `.git/hooks` не
версионируется, поэтому хуки храним в репозитории в `githooks/` и подключаем так:

```bash
git config core.hooksPath githooks
```

Эту команду каждый выполняет один раз после клона (она есть в README и в скрипте настройки).
На Linux и macOS не забыть `chmod +x githooks/*`, иначе хук молча не запустится — git выдаст
лишь подсказку `hint: The '...' hook was ignored because it's not set as executable`.

## pre-commit

Запускается до создания коммита, аргументов не получает. Проверять надо **то, что в индексе**,
а не рабочий каталог, иначе неиндексированные правки повлияют на результат.

```bash
#!/bin/sh
# githooks/pre-commit
files=$(git diff --cached --name-only --diff-filter=ACM -- '*.rs')
[ -z "$files" ] && exit 0
if ! rustfmt --check --edition 2021 $files; then
    echo "pre-commit: запустите cargo fmt" >&2
    exit 1
fi
```

Скрипт проверяет файлы на диске; если у файла есть и проиндексированные, и
непроиндексированные правки, результат может не совпасть с коммитом. Для строгой проверки
используют `git stash push --keep-index` перед проверкой и `git stash pop` после, но это
отдельный источник проблем, мы на это сознательно не пошли.

## commit-msg

Получает первым аргументом путь к файлу с сообщением (`.git/COMMIT_EDITMSG`). Может его
проверить или даже переписать.

```bash
#!/bin/sh
# githooks/commit-msg
msg_file="$1"
first_line=$(head -n1 "$msg_file")
case "$first_line" in
    Merge*|Revert*|fixup!*|squash!*) exit 0 ;;
esac
if ! echo "$first_line" | grep -Eq '^[A-Z]+-[0-9]+: .+'; then
    echo "commit-msg: первая строка должна начинаться с номера задачи, например PAY-123: ..." >&2
    exit 1
fi
```

## Другие полезные хуки

| Хук                  | Когда                         | Для чего мы используем                      |
|----------------------|-------------------------------|---------------------------------------------|
| `prepare-commit-msg` | перед открытием редактора     | подставить номер задачи из имени ветки      |
| `pre-push`           | перед отправкой               | быстрые тесты, запрет пуша в main           |
| `post-checkout`      | после смены ветки             | напомнить обновить зависимости              |
| `post-merge`         | после слияния/pull            | то же                                       |

## Ограничения

- Хуки локальные и обходятся флагом `--no-verify` (`-n` у commit). Поэтому всё важное
  дублируется проверками на сервере и в CI; хук — только быстрая обратная связь.
- Хук должен работать быстро: всё, что дольше пары секунд, люди начинают обходить.
- При `commit --amend` хуки срабатывают как при обычном коммите, а при rebase и cherry-pick
  pre-commit, как правило, не вызывается — ещё одна причина держать проверку в CI.
