# Уровни L0, L1, L2: сводка, обзор и полный текст

У каждого узла дерева три уровня детализации. Нужны они, чтобы агент тратил меньше контекста:
сначала смотрит короткую сводку, а полный текст тянет только если без него никак.

| Уровень | Что это | Предел |
|---|---|---|
| L0 | абстракт, одно предложение | до 50 токенов |
| L1 | оглавление + ключевое предложение каждой секции | до 300 токенов |
| L2 | полный Markdown | без предела |

## Откуда берётся L0 заметки

Приоритет такой:

1. Ручной `l0` во frontmatter.
2. Сводка от агента: при записи он может передать `l0` (в CLI — `zam write … --l0 "текст"`).
   Она сохраняется с `l0_source = agent`, и автоматика её не трогает, пока не изменится
   содержимое. Изменился текст, а новой сводки не прислали — L0 снова считается сам.
3. Автоматически (`l0_source = 'auto'`): экстрактивно берём предложение, ближайшее к центроиду
   эмбеддингов чанков заметки, и обрезаем до 50 токенов. Пока векторов ещё нет (воркер не
   дошёл), временно используется первый абзац.

Генеративной модели здесь нет — только выбор готового предложения.

## L0 папки

Папка своего текста не имеет, её L0 — свёртка L0 детей, не больше 50 строк. Если детей больше,
строки ранжируются по свежести (позже и по `usage`). Свёртка пересчитывается воркером с
дебаунсом 2 с (`[index] rollup_debounce_ms = 2000`), пишется в `nodes.l0` без новой ревизии.

## Индексация уровней

L0 и L1 заметок и секций индексируются как отдельные чанки уровней `note`, `section`,
`folder`. Широкий запрос («что у нас про деплой») цепляет тему целиком через такой чанк. Но в
выдачу вместо сводки потом подставляется лучший листовой чанк той же заметки, чтобы агент
получил конкретику.

## Как читать по уровню

```
zam read <id> --tier L0      # одна строка
zam read <id> --tier L1      # оглавление и ключевые фразы
zam tree "knowledge:Инструменты" --depth 2   # дерево с L0 у каждого узла
```

В API то же самое: `GET /nodes/{id}?tier=L0|L1|L2`.
