# Токен агента и блок zeroaimemory в CLAUDE.md

Агенту не нужны логин и пароль — только адрес сервера и bearer-токен пользователя. Решение
владельца: оба значения лежат прямо в инструкции агента, в CLAUDE.md или AGENTS.md.

## Токены

- Формат `zam_…`, передаётся как `Authorization: Bearer <токен>`.
- Режимы: `rw` (по умолчанию) и `ro` — только чтение.
- В базе хранится только sha256 секрета; в WebUI видны префикс (первые 8 символов), время
  последнего использования и IP.
- У пользователя может быть несколько токенов; их выпускают, отзывают и перевыпускают в WebUI.
  Утёк токен — отзыв в один клик.
- Токен открывает всю память своего пользователя, кроме пространства Human.

При самом первом старте сервер один раз печатает в stderr (не в журнал) рамку с первым
токеном администратора — строку `ZeroAIMemoryToken=…`. Потом он не показывается, сохраните.

## Блок в файле инструкции

```
<!-- zeroaimemory:begin v1 -->
ZeroAIMemoryUrl=http://<хост>:7700
ZeroAIMemoryToken=<токен>
<!-- zeroaimemory:end -->
```

`v1` — версия шаблона. На этапе M4 блок будет генерировать страница WebUI «Подключение агента»
и `zam init`; если версия в файле отстала, агент получит одно напоминание обновить блок.
Сам блок намеренно короткий (до 500 токенов): CLAUDE.md грузится в каждую сессию.

Личный токен лучше класть в `CLAUDE.local.md` — его обычно не коммитят.

## Где `zam` ищет адрес и токен

По порядку, первое найденное побеждает:

1. флаги `--url` / `--token`;
2. переменные `ZAM_URL` / `ZAM_TOKEN`;
3. блок в файлах проекта от текущего каталога вверх; ближайший каталог важнее, а внутри
   каталога порядок `CLAUDE.local.md` → `CLAUDE.md` → `AGENTS.md`;
4. `~/.zeroaimemory/config.toml`.

Адрес и токен ищутся независимо: URL может прийти из общего `CLAUDE.md`, а токен — из личного
`CLAUDE.local.md`.

## Проверка

```
zam status --url http://127.0.0.1:7700 --token <токен>
```

Коды выхода: 0 — всё хорошо, 1 — конфигурация, 2 — сервер недоступен, 3 — токен отклонён.
