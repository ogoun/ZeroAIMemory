# Vault: где агент хранит креды

Vault — журнал решения (и Knowledge) для секретов: тип записи `password`, `token`, `ssh_key`,
`connection_string`, `url`, `repo` или `note`. Появится на этапе M3.

- Открытые поля — `title`, тип, `username`, `url`, `description`. Само значение лежит в поле
  `secret`, зашифрованное XChaCha20-Poly1305.
- Мастер-ключ сервера — файл `data_dir/master.key` (создаётся при первом запуске, права 0600)
  или переменная `ZAM_MASTER_KEY`. У каждого пользователя свой ключ данных, зашифрованный
  мастер-ключом.
- Бэкап без мастер-ключа секреты не раскрывает. Мастер-ключ в бэкап не входит — его надо
  резервировать отдельно, иначе после восстановления vault не прочитать.
- Агент по своему токену читает и пишет vault своего пользователя: список и поиск по открытым
  полям без значений, значение — `GET /vault/{id}?reveal=1` или инструмент `memory_vault`.
- Значения не индексируются нигде: ни в FTS, ни в Qdrant.
- Каждое раскрытие пишется в аудит (токен, сессия, машина, время); частоту не ограничиваем.
- Сканер секретов перед индексацией любой заметки заменяет похожее на секрет на `‹secret›`
  и возвращает предупреждение `secrets_detected` с предложением перенести значение в vault.
