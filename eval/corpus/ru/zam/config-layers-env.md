# Слои конфигурации zam-server и переменные ZAM_*

Своя реализация вместо `figment` (у того последний релиз в 2024-05): `serde` + `toml` и слой
переопределений. Порядок, поздний побеждает:

1. значения по умолчанию;
2. файл `config.toml` (`--config`; образец — `config.example.toml`, в нём ровно умолчания);
3. переменные окружения `ZAM_<РАЗДЕЛ>__<КЛЮЧ>` — двойное подчёркивание между разделом и ключом;
4. аргументы командной строки (`--bind`, `--data-dir`).

Примеры:

```
ZAM_SERVER__BIND=127.0.0.1:9000
ZAM_DATA_DIR=/srv/zam            # ключ верхнего уровня, без раздела
ZAM_QDRANT__API_KEY=...          # ключ внешнего Qdrant, лучше так, чем в файле
```

Разделы файла: `[server]`, `[admin]`, `[log]`, `[qdrant]`, `[ml]`, `[index]`, `[search]`,
`[limits]`.

## Особые переменные

- `ZAM_ADMIN_PASSWORD` — пароль администратора для пробного запуска, если в `[admin]` не задан
  `password_hash`; хэшируется в памяти. Для постоянной работы — `zam-server hash-password`.
- `ZAM_MASTER_KEY` — мастер-ключ vault вместо файла `master.key`.
- `ZAM_URL`, `ZAM_TOKEN` — для клиента `zam`, не для сервера.

## Только для разработки

- `ZAM_REQUIRE_ML=1` — тесты ML падают, а не пропускаются, если нет ORT или модели (так в CI);
- `ZAM_TEST_QDRANT_MAX` — предел одновременных Qdrant в тестовом бинарнике (по умолчанию 4);
- `ZAM_WEB_REBUILD=1` — пересобрать сервер после первого `npm run build`, чтобы build-скрипт
  заметил `web/dist`;
- `ZAM_VC_CRT_DIR` — каталог MSVC runtime для упаковки, если vswhere его не нашёл.
