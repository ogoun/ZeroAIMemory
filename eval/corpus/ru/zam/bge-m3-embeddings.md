# bge-m3 у нас: int8 на CPU, fp16 на GPU, sparse-голова и model_id

Эмбеддинги считает одна модель — bge-m3 (MIT). Это XLM-RoBERTa large: 24 слоя, hidden 1024,
словарь 250 002. За один проход по `last_hidden_state` мы получаем два представления: dense и
sparse. ColBERT-векторы в v1 не храним: на миллион чанков это сотни гигабайт.

## Какие веса берём

| Вариант | Файл | Размер |
|---|---|---|
| CPU | `Xenova/bge-m3`, `onnx/model_int8.onnx` (per-channel QInt8) | ~568 МБ |
| GPU | `Xenova/bge-m3`, `onnx/model_fp16.onnx` (вход и выход fp32) | ~1,13 ГБ |
| sparse-голова | `BAAI/bge-m3`, `sparse_linear.pt` | 3516 байт |

`tokenizer.json` берётся из того же репозитория Xenova. Ревизии (коммит Hugging Face) и SHA-256
каждого файла закреплены в `deploy/models.toml`; при несовпадении загрузка падает.

## Пулинг в Rust

- **dense** — CLS-токен (`h[:, 0]`) и L2-нормировка, размерность 1024;
- **sparse** — `max(0, h·w + b)` для каждого токена, затем max-pool по token-id, спецтокены
  0–3 (`<s>`, `<pad>`, `</s>`, `<unk>`) пропускаются.

`sparse_linear.pt` — это zip с torch-pickle, но без сжатия: внутри `data/0` — веса fp16 формы
[1, 1024], `data/1` — bias fp16. Файл закреплён хэшем, поэтому читаем сырые байты через `zip` +
`half`, без Python и разбора pickle.

Усечение: запрос — 512 токенов, пассаж — 1024 (чанк по нашим правилам и так не больше 800).

## Что такое model_id и зачем он

Идентификатор модели (`<id>@<sha8 model.onnx>`) пишется в метаданные коллекции Qdrant и в
ключ таблицы `embeddings`. При старте сервер сравнивает его с текущим. Не совпало —
векторный канал выключается до reindex, поиск честно отвечает «degraded» с причиной
`model_mismatch`. Векторы разных моделей никогда не смешиваются.

Векторы int8 и fp16 немного различаются. Политика: считать их одной моделью, только если
dense-косинус между ними на eval не ниже 0,99, иначе это разные `model_id`.

## Гейт качества int8

Против эталона fp32 `BAAI/bge-m3`:

- средний dense-косинус ≥ 0,99, минимальный ≥ 0,97;
- recall@5 и nDCG@10 на eval падают не больше чем на 1 п. п.;
- sparse — корреляция Спирмена весов ≥ 0,95.

Не прошли — квантуем сами (per-channel или SmoothQuant, без квантования `word_embeddings`).

## Грабли динамического квантования

В int8-графах Xenova масштаб активаций (`DynamicQuantizeLinear`) считается по всему тензору
батча, так что вектор текста зависит от соседей по батчу. Поэтому такие модели
(`dynamic_quant = true` в `[model.spec]`) прогоняем по одному тексту, без паддинга. Скорость
почти та же. fp16 на GPU батчится спокойно — результат совпадает с одиночным прогоном.

## Замеры

- CPU Ryzen 9 5900X, int8: 3,7 чанка/с на 24 потоках, эмбеддинг запроса ≈ 29 мс.
- RTX 3090, fp16: 141 чанк/с, запрос ≈ 14 мс.
- RSS после загрузки на CPU — 1393 МБ (токенизатор ≈ 230 МБ, две сессии ORT), бюджет 1,1 ГБ
  пока не выполняется; решение будет в ADR.
