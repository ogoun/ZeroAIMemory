# SQLITE_BUSY: database is locked при параллельной записи

Ошибка `SQLITE_BUSY` (код 5, текст `database is locked`) означает: нужная блокировка занята
другим соединением, и SQLite не стал ждать. По умолчанию ожидание нулевое — ошибка
возвращается мгновенно.

Первое, что делаем в любом приложении:

```sql
PRAGMA busy_timeout = 5000;  -- ждать до 5 с, повторяя попытки
```

Или через API: `sqlite3_busy_timeout(db, 5000)`, в rusqlite — `conn.busy_timeout(...)`.
Настройка действует на соединение, задаётся при каждом открытии.

Почему ошибка остаётся даже с таймаутом: транзакция начата как `BEGIN` (отложенная), сначала
прочитала, потом пытается записать. Если за это время другой писатель изменил базу, апгрейд
до записи невозможен, и SQLite в WAL сразу возвращает `SQLITE_BUSY` (точнее,
`SQLITE_BUSY_SNAPSHOT`), не дожидаясь таймаута — ожидание не поможет, снимок устарел.

Лечение: транзакции, которые будут писать, начинать с `BEGIN IMMEDIATE` — блокировка записи
берётся сразу, и конкуренты ждут на `busy_timeout`. Плюс держать транзакции записи короткими
и по возможности писать из одного потока-писателя.
