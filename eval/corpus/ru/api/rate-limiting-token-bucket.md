# Ограничение частоты запросов в API

Публичный API ограничивает частоту запросов, чтобы один клиент не мог занять сервис целиком.
Лимиты проверяет сам сервис, а не только шлюз: правила зависят от тарифа клиента.

## Алгоритм

Используется «ведро токенов»: у клиента есть ведро на N токенов, оно пополняется со скоростью R
токенов в секунду, каждый запрос забирает один токен. Пустое ведро — ответ 429 с заголовком
`Retry-After`.

## Хранение счётчиков

Состояние вёдер лежит в Redis: ключ — клиент и маршрут, значение — число токенов и время
последнего пополнения. Проверка и списание — один Lua-скрипт, поэтому экземпляры сервиса не
спорят за одно ведро.

## Лимиты по тарифам

Базовый тариф — 10 запросов в секунду и ведро на 50, расширенный — 100 и 500. Тяжёлые маршруты
(поиск, выгрузки) стоят несколько токенов.

## Заголовки ответа

Сервис отдаёт `RateLimit-Limit`, `RateLimit-Remaining` и `RateLimit-Reset`, чтобы клиенты могли
замедляться сами, не дожидаясь 429.
