# Повторы запросов в HTTP-клиенте сервиса

Сервис заказов ходит во внешние API — платёжный шлюз, службы доставки, сервис скидок — через
общий HTTP-клиент. Повторы в нём настроены централизованно, чтобы каждый обработчик не
изобретал свою политику.

## Что повторяется

Повторяются только сетевые ошибки до получения ответа и ответы 502, 503, 504. Ответ 4xx не
повторяется никогда: запрос с ошибкой в теле не станет правильным со второй попытки. Ответ 500
повторяется только для методов, помеченных идемпотентными.

## Бюджет повторов

На один входящий запрос приходится не больше двух повторов исходящего, а общий бюджет повторов
клиента — 10 % от числа запросов за последнюю минуту. Когда бюджет исчерпан, клиент отдаёт
ошибку сразу: лавина повторов при сбое зависимости только продлевает сбой.

## Задержки

Между попытками — экспоненциальная задержка 100, 400 и 1600 мс с полным джиттером. Заголовок
`Retry-After` от сервера имеет приоритет над расчётной задержкой, но не больше 5 секунд.

## Методы с побочным эффектом

`POST` к внешнему API считается неидемпотентным, пока у запроса нет ключа идемпотентности.
Ключ формируется из идентификатора операции заказа и передаётся заголовком
`Idempotency-Key`; клиент подставляет один и тот же ключ во все попытки.
