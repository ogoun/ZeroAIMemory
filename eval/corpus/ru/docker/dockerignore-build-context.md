# .dockerignore и размер контекста сборки

Сборка стартовала с «transferring context: 2.3GB» и минутной паузы. Причина — в контекст
улетало всё содержимое каталога: `node_modules`, `.git`, дампы базы в `tmp/`.

Контекст — это каталог, переданный последним аргументом `docker build`. Он целиком
отправляется сборщику, даже если Dockerfile из него ничего не копирует. BuildKit передаёт
только то, что реально нужно для `COPY`, но `.dockerignore` всё равно влияет на кэш и
на то, что попадёт в образ через `COPY . .`.

Минимальный `.dockerignore` для Node-проекта:

```
node_modules
.git
tmp/
coverage/
*.log
.env
.env.*
!.env.example
```

Синтаксис похож на `.gitignore`, но не идентичен: шаблоны отсчитываются от корня
контекста, `!` возвращает исключённое. Файл должен лежать в корне контекста; для
нестандартного Dockerfile можно положить рядом `имя.Dockerfile.dockerignore`.

Отдельный плюс — секреты: `.env` с паролями без игнора оказывается в слое образа и
уезжает в реестр.
