# Именованные тома: где лежат, как бэкапить и как не потерять

Заметка после того, как `docker system prune --volumes` на стенде унёс данные Postgres,
который кто-то запустил без compose и без имени тома.

## Анонимный против именованного

Если в образе есть `VOLUME /var/lib/postgresql/data`, а при запуске том не указан, Docker
создаёт **анонимный** том со случайным хешем вместо имени. При пересоздании контейнера
(`docker rm` + `docker run`) новый контейнер получает новый пустой анонимный том, старый
остаётся висеть «ничейным» — и первым уходит при очистке. `docker run --rm` удаляет
анонимные тома вместе с контейнером.

Поэтому для данных — всегда явное имя: `-v pgdata:/var/lib/postgresql/data`. В compose
имя тома получает префикс проекта (`myapp_pgdata`); если проект переименовать или
запустить из другого каталога, compose создаст новый пустой том, а старый останется.
Чтобы этого не было — `name: pgdata` в секции `volumes:` верхнего уровня.

## Где физически

```sh
docker volume ls
docker volume inspect pgdata --format '{{ .Mountpoint }}'
# /var/lib/docker/volumes/pgdata/_data
```

Лазить туда руками на работающем контейнере не стоит, а в Docker Desktop этот путь
вообще внутри виртуальной машины.

## Бэкап и восстановление через временный контейнер

```sh
docker run --rm -v pgdata:/src:ro -v "$PWD":/dst alpine \
  tar czf /dst/pgdata-$(date +%F).tar.gz -C /src .

docker volume create pgdata-restore
docker run --rm -v pgdata-restore:/dst -v "$PWD":/src alpine \
  tar xzf /src/pgdata-2024-05-01.tar.gz -C /dst
```

Для баз данных копия файлов работающего сервера не консистентна. Либо останавливать
контейнер на время `tar`, либо делать логический дамп (`pg_dump` через `docker exec`).

## Что проверяю перед очисткой

- `docker volume ls -f dangling=true` — тома без контейнеров; просмотреть глазами;
- `docker system df -v` — сколько места занимает каждый том;
- `prune` без `--volumes` тома не трогает, с ним — удаляет все неиспользуемые, в том числе
  именованные, если ни один контейнер на них не ссылается (в свежих версиях Docker
  `docker volume prune` по умолчанию берёт только анонимные, нужен `-a`).
