# ZeroAIMemory: возможности по этапам

Подробный перечень возможностей с этапом появления (перенесено из README 2026-11-28). Короткий обзор — [README](../README.md).

Работает в выпущенных версиях (M0, M1):

- **Заметки и папки** в пространствах Knowledge, Rules, Human и в пространствах решений
  (проектов). Чтение целиком, по уровню (L0 — сводка, L1 — оглавление) или по секции
  (`Установка > Linux`). Замена с проверкой ревизии: при конфликте приходит 409 с диффом.
  PATCH секций меняет только байты своей секции, переводы строк и BOM сохраняются.
- **История.** Каждая правка — неизменяемая ревизия с автором, машиной и сессией. Есть дифф,
  откат, мягкое удаление в корзину и аудит.
- **Markdown на сервере** (comrak): GFM, сноски, формулы, callout в стиле GitHub и Obsidian,
  вики-ссылки, подсветка кода, Mermaid. HTML проходит санитизацию ammonia.
- **Вложения** до 200 МБ с дедупликацией по SHA-256 и выдачей с Range.
- **Полнотекстовый поиск** FTS5 (слова и trigram для идентификаторов) с бюджетом токенов,
  режимами `brief`/`chunks`/`notes` и выводом в JSON или Markdown-карточками.
- **Доступ.** Bearer-токены `rw`/`ro` для агентов, вход администратора и пользователей в WebUI (пароль пользователю задаёт администратор, при первом входе — смена). Пространство
  Human по токену недоступно, Rules агент только читает (если не включено `rules.agent_write`).
- **WebUI** (Svelte 5): дерево, просмотр документа с медиа, редактор с предпросмотром, история,
  поиск Ctrl+K, пользователи и токены.
- **CLI `zam`** без рантайма tokio: холодный старт около 6 мс.

Добавлено в M2 (`v0.0.3-m2`):

- **Векторный индекс.** Модель bge-m3 даёт dense- и sparse-векторы (int8 на CPU, fp16 на
  CUDA). Индексирует воркер в фоне, а запись заметки индексацию не ждёт. Векторы кэшируются в
  SQLite, поэтому индекс Qdrant пересобирается без инференса.
- **Гибридный поиск.** Каналы vector, bm25 и trigram сливаются через weighted RRF с затуханием
  по свежести и лимитом карточек на узел. Опционально включается серверный реранк
  cross-encoder (`"rerank": "on"`).
- **Деградация вместо отказа.** Если нет модели, ONNX Runtime или Qdrant, поиск идёт по FTS и
  отвечает с `degraded: true` и кодом причины. Запись при этом работает. WebUI пишет причину
  над результатами Ctrl+K, CLI — в stderr.
- **Состояние индекса в WebUI** (раздел «Индекс», `#/admin/index`): модель, устройство,
  Qdrant, очередь, неудавшиеся задания, повреждённые и исключённые из пересборки базы,
  причина выключения векторного поиска с командой для администратора, переиндексация из кэша
  или полная. У результатов поиска — метки каналов `vector`/`fts`, у заметок в дереве и в
  документе — значки «в очереди» и «ошибка индексации».
- **Управляемый Qdrant.** Нативный бинарник из комплекта, без Docker. Сервер сам его
  запускает, перезапускает при падении и завершает вместе с собой.

Добавлено в M3 (`v0.0.4-m3`):

- **Совместный доступ к решению.** Первый зарегистрировавший решение — владелец; другие
  пользователи получают доступ `rw` или `ro` после одобрения и видят в базе владельца только
  пространство решения. Отзыв действует со следующего запроса.
- **Журналы.** Changelog, Releases со сравнением и Insights: замещение старого вывода новым без
  потери истории, отзыв с причиной, дедупликация, триггеры вспоминания. Поиск по умолчанию
  показывает только действующие записи, `include_history` — всю историю.
- **Надёжность записей.** `axiom` — установлено человеком: в WebUI или агентом по прямому
  указанию пользователя (агенту смена статуса — только с причиной); `theorem` агент ставит только
  с доказательством, `hypothesis` — по умолчанию; надёжное поднимается в поиске выше гипотезы.
  Правка записи журнала — с ревизией (`If-Match`): параллельная правка не затирает чужую.
- **Граф.** Связи из wiki-ссылок, Markdown-ссылок и `relations:`, явные рёбра, обратные
  ссылки, `expand=graph` в поиске.
- **Секреты.** Сканер маскирует ключи и пароли до индексации; Vault хранит их зашифрованными
  (XChaCha20-Poly1305, мастер-ключ сервера), каждое раскрытие — в аудите.
- **WebUI**: журналы, Vault, связи, страница «Решения» и настройки, диаграммы Mermaid с
  раскладкой ELK.

Добавлено в M4 (`v0.0.5-m4`):

- **MCP.** `/mcp` по streamable HTTP и stdio-прокси `zam mcp`: `memory_search`, `memory_read`,
  `memory_cache_put`, `memory_tree`, `memory_write`, `memory_log`, `memory_update_entry`,
  `memory_link`, `memory_recall`, `memory_vault` — те же права и атрибуция, что у REST.
- **Хуки агента.** `zam hook session-start|prompt|pre-tool|post-tool|checkpoint` для Claude Code и
  Codex: дайджест на старте сессии, подсказки к запросу и к ошибке инструмента, локальная
  подсказка перед записью файла или командой (без сети, по кэшу триггеров), напоминание
  записать итоги, снимок сессии из журнала агента (M6: `Stop`, сжатие, `SessionEnd`, обрыв —
  без LLM, с маскировкой секретов). Хук никогда не блокирует агента: при любой ошибке — тишина
  и код 0.
- **Экономия токенов.** Протокол «кэш → карточки → чтение пачкой → `cache_put`»: выжимка агента
  с источниками выдаётся первой в поиске и устаревает (`stale`) при изменении источника; в общем
  решении выжимки общие, с автором.
- **Подключение агента.** `zam init` и страница WebUI «Подключение агента» пишут блок
  инструкции, `solution.toml`, хуки и `.mcp.json`; токен — только в `~/.zeroaimemory/config.toml`
  и `ZAM_TOKEN`. Клиент `zam` раздаётся сервером (`/downloads/zam/…`).
- **Пользователи и служба.** Вход пользователей в WebUI со своими токенами и решениями; режим
  службы Windows (SCM) и systemd (`zam-server service install|start|stop|status`).

Добавлено в M4.5 (`v0.0.6-m4.5`):

- **Словарь домена.** Термины с определением и псевдонимами (`zam log term`, `zam glossary`):
  поиск по псевдониму находит заметку с каноническим словом (канал `alias`, «summary» →
  «выжимка»), хук подсказывает определение термина из промпта, запись с псевдонимом вместо
  имени получает предупреждение `term_alias`.
- **Задачи и передача работы.** `zam task new|claim|status`: захват сессией агента, `next_step`,
  длительность; после сжатия контекста или в новой сессии агент видит задачи в работе первыми.
- **Вопросы к человеку.** Агент задаёт вопрос (`zam question ask`, MCP), человек отвечает в
  WebUI одним кликом или в чате — ответ становится решением `axiom` и приходит в следующий
  дайджест.
- **Решения и противоречия.** ADR-поля решения (`data.decision`), предупреждение о близкой
  аксиоме, связь `contradicts`: возражение не стоит в выдаче выше надёжной записи.
- **Знание о коде.** Записи ссылаются на файлы (`--ref`, `refs:` во frontmatter) с хэшем;
  правка файла помечает знание «возможно устарело» (хук или `zam refs check`), а при чтении
  файла хук без сети подсказывает, что о нём есть в памяти.
- **Окружение в Vault.** Хосты и стенды (`zam vault set --type host`): открытые поля ищутся
  `vault?q=` и видны в дайджесте, секрет — только раскрытием с аудитом.
- **Рабочая память хуков.** Локальный журнал событий сессии (только метаданные), пакет
  восстановления после `/compact`, пакет под задачу субагента (`SubagentStart`, `brief`),
  напоминание записать «ошибка → исправление», учёт выданных токенов; агентам без хуков — те же
  функции через MCP (`memory_recall event=recovery|brief`) и блок инструкции (v4 — с M5.5, v5 —
  с M5.6).

Работает с `0.0.7-m5` (M5):

- **Документы.** Вложения DOCX, PPTX, XLSX, XLS, ODS, CSV, PDF и текстовые файлы разбираются в
  фрагменты со ссылкой на место — `page:12`, `slide:3`, `sheet:Итоги!A1:F40`, `para:40`; поиск
  (`zam search`, MCP) находит фрагмент карточкой `a:<фрагмент>` с файлом и `locator`, `zam read
  a:<фрагмент> --locator …` читает ровно эту часть, без `locator` — оглавление документа.
- **Изоляция разбора.** Все документы разбираются в рабочем процессе `zam-server doc-worker`
  (тот же бинарник) с лимитами памяти, срока и объёма: zip-бомба, XXE, битый PDF дают `failed` с
  причиной или частичный результат, сервер работает дальше. Human-вложения — только в
  полнотексте.
- **Просмотр в WebUI.** Вкладка «Вложения» заметки: PDF (pdf.js, переход к странице из поиска),
  DOCX (в песочнице без скриптов), таблицы с листами и переходом к диапазону, текст слайдов.

Работает с `0.0.8-m5.5` (M5.5):

- **Отчёты.** Итог исследования или задачи для человека: `zam report report.md` загружает
  Markdown вместе с картинками и файлами по относительным ссылкам (`![потери](figs/loss.png)`) и
  печатает ссылку на страницу; MCP — `memory_log kind=report` с картинками в base64. В WebUI —
  журнал решения «Отчёты»: лента с миниатюрами, фильтры, поиск, страница с формулами, Mermaid,
  таблицами и кодом, «PDF / печать» (печать браузера: A4, светлая тема, ждёт загрузки картинок и
  формул). Отчёт неизменяем (повтор — новый отчёт), удаляет его только владелец решения, агенту
  он не виден — ни в поиске, ни в подсказках. С M6 ссылки отчёта — только `http`, `https`,
  `mailto`, `vscode` и `file` (`zam report` отклоняет прочие до отправки): ссылка на код
  `vscode://file/<путь>:<строка>` открывается в VS Code, у неё и у `file:` — кнопка «копировать
  путь».

Работает с `0.0.10-m5.7` (M5.7):

- **Идеи.** `zam idea new "Экспорт отчётов в PDF" --priority high` (в WebUI — журнал «Идеи»)
  записывает замысел; агент получает до трёх идей решения в дайджесте первого старта сессии и
  подходящую идею — подсказкой к запросу, предлагает одну (`memory_update_entry action=propose`,
  `zam idea propose`) — вопрос «начать / отложить / отказаться» на странице «Вопросы» или в чате.
  «Начать» создаёт задачу со связью на идею, «отложить» — до даты (UTC), «отказаться» — больше не
  предлагается. Идеи, записанные агентом для себя (`--origin agent`), не предлагаются, пока
  человек не примет их как свои. Если задачу из идеи сняли или удалили, агент может предложить
  вернуть идею (`zam idea propose w:<id> --text "почему пора"` — вопрос «вернуть / отказаться»);
  решает человек. Выключатель — флажок «Идеи: раздел дайджеста и подсказки (разбор и предложения)»
  в «Подключение агента» → «Подсказки хуков» (`ideas.proactive`). С `0.0.12-m6.5` так работает
  режим `propose` (там же — «Идеи: … предлагать мне»); по умолчанию (`review`, «разбирать сам»)
  новые идеи человека агент разбирает сам (см. «Добавлено в M6.5»).

Работает с `0.0.9-m5.6` (M5.6):

- **Карта кода.** `zam code sync` разбирает рабочую копию на машине агента (tree-sitter: Rust,
  TypeScript/TSX, JavaScript/JSX, Python, Go, Java, C#) и отправляет на сервер только метаданные —
  имена, виды и строки символов, сигнатуры (≤ 160 символов, секреты маскируются; выключатель
  `code.send_signatures`) и агрегированные ссылки; тела файлов на сервер не уходят. Повторная
  синхронизация загружает только изменившиеся файлы (отпечатки git). `zam code map [--focus …]
  [--task …]` — ключевые файлы и символы в бюджете токенов (PageRank по ссылкам), `zam code sym` —
  карточка символа (кто ссылается, привязанные знания), `zam code refs`, `zam code impact` — что
  затронет правка; то же — MCP `memory_code`.
- **Знание о функции.** Ссылка `путь#Тип::метод` (`refs.files`, `refs:` заметки, `--ref`)
  устаревает только при изменении тела этого символа (`symbol_changed`, `symbol_removed`), а не при
  любой правке файла; знание о файле в хуках называет символ.
- **Хуки и WebUI.** Строка карты в дайджесте старта (≤ 80 токенов), раздел `### Код` в пакете
  субагенту, фоновая синхронизация из `session-start`/`checkpoint` (не чаще раза в 30 мин или при
  смене `HEAD`; тип подсказок `code_map`). В WebUI — пункт решения «Код»: состояние карты, поиск
  символа, таблица файлов, карточка, «Обзор» зависимостей Mermaid.

Добавлено в M6 (`v0.0.11-m6`):

- **Честный бюджет и короткие карточки.** Бюджеты ответов агенту (`budget_tokens`, строка
  `~N tok`) считаются в токенах bge-m3 — и без модели: `tokenizer.json` лежит в комплекте сервера.
  Карточка поиска — строка с коротким хвостом `[.82] r7 · th · 2026-10-10 14:03:22 · 340t`
  (оценка, ревизия, надёжность, дата UTC, размер источника) и фрагмент под ней.
- **Фокусное чтение — по явному запросу.** `memory_read {items: [{id, focus: "…"}]}` или `zam read
  --focus "…"` отдаёт оглавление и ближайшие к запросу части длинной записи, пропуски помечены
  адресом `[пропущено: range:r<rev>:S-E …]` — дочитать их можно `range` (`zam read --range`). По
  умолчанию чтение по-прежнему целиком: фокус нужен длинным записям и дорогим моделям.
- **«Уже выдавалось».** В пределах сессии повторное чтение отдаётся целиком с пометкой «уже
  выдавалось в этой сессии», карточка поиска — с `(выдавалось)`; после сжатия контекста начинается
  новая эпоха сессии, и пометки сбрасываются. MCP Claude Code подключается stdio-прокси `zam mcp`,
  который сам находит сессию агента (привязку пишет хук `session-start`); свой клиент передаёт
  сессию заголовком `X-Zam-Session` или аргументом `session_id`.
- **Дайджест старта по разделам.** Правила Rules выдаются всегда и сверх бюджета дайджеста, затем
  задачи, ответы человека и идеи, в остатке — окружение, словарь, карта кода (строкой-указателем),
  ловушки, изменения строками-индексами; пороги подсказок, бусты вида и области и вес вложений
  подобраны сетками eval.
- **Учёт выданного.** `zam sessions tokens` и страница WebUI «Сессии»: сколько токенов память
  выдала каждой сессии агента по событиям и доля повторных чтений; выданное без сессии — в общем
  счётчике пользователя (`zam sessions tokens --unattributed`).
- **Снимок сессии.** Хуки снимают из журнала агента (без LLM) хвост конспекта сжатия, последние
  запросы, изменённые файлы и первую строку команд, маскируют секреты и хранят снимок на сервере
  14 дней. Если сессия оборвалась, следующая получает его разделом «Последнее известное
  состояние». Выключатель — `[hooks] session_snapshot = false` в `~/.zeroaimemory/config.toml`.
- **Перенос памяти.** `zam-server backup` снимает согласованную копию без остановки сервера
  (каталог или один zip, опись с SHA-256; автокопии — `[backup] schedule = "daily"`),
  `zam-server restore` восстанавливает её на чистой машине любой из двух ОС, индекс Qdrant
  пересобирается из кэша эмбеддингов. Одно пространство — `zam export` в zip с `.md` и
  `zam import` на другом сервере (свой архив — `--own`); в WebUI — «Экспорт (.zip)» в меню
  пространства. Пошагово — «Перенос на другую машину» в
  [deploy/README-install.md](../deploy/README-install.md).
- **Свои клиенты.** `GET /api/v1/health` перечисляет возможности сборки в `features`; правило
  совместимости `/api/v1` и все флаги — [docs/api-compat.md](api-compat.md). Срок сбора
  `/recall` — поле `timeout_ms`, повтор записи заметки без дубля — `Idempotency-Key`.

Добавлено в M6.5 (`v0.0.12-m6.5`):

- **Разбор идей агентом.** Идея, которую человек записал в WebUI (или агент со слов человека),
  приходит «Непросмотрено». Агент узнаёт об очереди из дайджеста старта сессии (раздел `### Идеи
  на разбор`), когда закончит текущий шаг, берёт пакет разбора (`memory_recall
  event=idea_review`, `zam idea queue`: идея, прежние разборы и доводы человека, похожие записи —
  в том числе отклонённые идеи), сверяет идею с планом, ТЗ и сделанным и выносит исход с разбором
  (`memory_update_entry action=review`, `zam idea review`): «В плане» — задача в «Задачах» со
  связью на идею и планом шагов, «На доработку» — что дописать, «Отклонена» — почему, «Сделано» —
  ссылка на сделанное. Пункт плана из идеи агент берёт сам, когда закончит текущую работу.
- **Что видит человек.** В ленте «Идеи» — чипы статусов со счётчиками, группировка и строка
  решения, в карточке — разбор агента и история разборов. Возвращённую идею человек дописывает
  («Изменить» — она снова уходит на разбор), отклонённую удаляет, оставляет или возвращает на
  разбор с доводом; решение человека агент не пересматривает. В «Задачах» — пометка «из идеи» и
  фильтр «Из идей». Режим — «Подключение агента» → «Идеи: разбирать сам / предлагать мне»
  (`propose` — поведение 0.0.10-m5.7).

Добавлено в M7.1 (`v0.0.14-m7.1`):

- **Секреты агенту — меткой.** Запрос по токену (MCP, хуки, `zam`) получает вместо значений,
  похожих на секреты, `‹secret›` — в чтении, поиске, подсказках, выжимках, предпросмотре и

  есть, и сервер возвращает значения на место (и на второй правке подряд из того же текста; после
  обновления сервера текст перечитывают); правка, которая выводит значение из-под маски (снят
  блок кода, переписан `ключ: значение`), отклоняется с номерами строк. `zam export` по токену
  пишет в stderr, что архив без значений секретов: полная копия — экспорт из WebUI или
  `zam-server backup`.
- **Сканер точнее.** Русские слова-ключи («токен: …», «пароль = …», «с паролем `…`») без ложных
  срабатываний на прозе («Тип токена: OAuth», «Хэш пароля: sha256»), значение `response` у
  `Authorization: Digest`, флаги `-pXXX`, `--password X`, `-u user:pass` внутри блоков кода и
  `` `…` ``; повторная маскировка ничего не меняет.
- **Токен для каждого сервера.** `~/.zeroaimemory/config.toml` хранит токены ключами
  `[servers."<адрес>"]`: `zam init --token` второго сервера не трогает токен первого, а токен
  одного сервера на другой не отправляется; прежний конфиг работает без `zam init`.
- **Подсказки к ошибкам по делу.** Код 1 у `grep`, `diff`, `cmp`, `test` без stderr — не ошибка;
  на 401, 403, квоту, нехватку места, 429, 400 и 422 — одна строка «… не повторяй …»; подсказка
  к ошибке засчитывает только предметные слова (не «No such file», не имена каталогов команды).
- **Сборка и эксплуатация.** ONNX Runtime 1.31.0 — из пакетов NuGet (те же библиотеки),
  `cargo xtask fetch-deps` проверяет размер архива, `--prune-cache` чистит прежние версии из
  `target/deps-cache`; reindex на Windows повторяет удаление коллекции Qdrant при сбое
  переименования каталога; строка очереди идей — одна за эпоху; подсказка к запросу быстрее.
