### Задача 1 — пересборка таблиц в миграциях, миграция 0015, виды `term`/`task`/`question`, связь `contradicts` (2026-10-28)

- **Загрузчик (`zam-store/src/migrate.rs`, спецификация §1.1).** `Migration { version, sql, rebuild }`; у всех прежних миграций (user 0001–0014, system 0001–0007, тестовые) `rebuild: false`. Для `rebuild: true` — процедура SQLite «Making Other Kinds Of Table Schema Changes»: прежнее значение `foreign_keys` запоминается, `PRAGMA foreign_keys=OFF` вне транзакции, SQL миграции в транзакции, `PRAGMA foreign_key_check` (любая строка — откат и `StoreError::InvalidMigrations` с первыми пятью нарушениями «таблица rowid → родитель»), `user_version`, `COMMIT`, восстановление `foreign_keys` (и при ошибке). Копия `bak-v<N>` — как раньше, до всех миграций.
- **Миграция user `0015_entries_kinds` (`rebuild`).** Фактическая схема базы на 0014 снята с `sqlite_master` (база из миграций 0001–0014 в `.tmp/m45/`): у `entries` — индексы `entries_feed`, `entries_title`, `entries_pending` и автоиндексы PRIMARY KEY и UNIQUE `idempotency_key`; триггеров и представлений на `entries` нет (append-only триггеры — у `entry_revisions`, они не пересоздаются); FK на `entries` — `entry_revisions.entry_id`, `triggers.entry_id` и самоссылки `supersedes_id`/`superseded_by_id`; `chunks.entry_id` — без FK. У `edges` — `edges_src`, `edges_dst`, `edges_unresolved`, `edges_explicit`, `edges_derived_raw`, автоиндекс PRIMARY KEY; FK на `edges` нет. Пересборка обеих таблиц со списками столбцов в `INSERT … SELECT`; сверка `sqlite_master` до и после — совпадает (и в тесте `rebuild_migration_preserves_m4_db`).
- **CHECK статусов.** `CHECK ((status IS NULL) = (kind IN ('changelog','release')))` и отдельный CHECK множества статусов по виду. NULL отсекается первым CHECK явно: `status IN (…)` с NULL даёт NULL, а CHECK с NULL проходит — одно выражение с `OR` пропустило бы insight/term/task/question без статуса.
- **Типы (`zam-store`).** `EntryKind::{Term, Task, Question}`, `EntryKind::ALL`; `EntryStatus::{Open, InProgress, Blocked, Done, Dropped, Answered, Obsolete}` (`open` общий у task и question); serde перечислений `text_enum!` — `snake_case` (`in_progress`; у прежних однословных значений строки те же); `allowed_statuses`, `initial_status`, `has_certainty` (insight и term, спецификация §1.3); `EdgeType::Contradicts` (`ALL` — 10 типов; `relations:` и `links` разбираются через `EdgeType::parse` и принимают его без правок).
- **Буквы ссылок — один источник.** `EntryKind::ref_letter()` (`i`, `c`, `r`, `t` — term, `k` — task, `q` — question), `EntryKind::from_ref_letter`, `ENTRY_REF_LETTERS` и `is_entry_ref_letter` (с общей `e`). Сервер берёт их в `/recall` (`entry_ref`), `/read` (`split_ref`, ссылка карточки), карточке поиска, `POST /cache` (источники), MCP (`entry_id`, `graph_ref`, `entry_line`). Клиент `zam` от `zam-store` не зависит (хуки без SQLite): `zam-cli/src/target.rs` держит копию `ENTRY_REF_LETTERS`, совпадение проверяет тест `entry_ref_letters_match_store` (dev-зависимость); ею пользуются `target::entry_ref` и `zam link`.
- **Поиск.** `ENTRY_KINDS` (`zam-store/src/search.rs`) и `KINDS` (`filters.kinds`) включают новые виды; `DEFAULT_KINDS` не менялся (задача 3). `STATUSES` (`filters.status`) расширен всеми статусами видов **[решение исполнителя]**: иначе `filters.status: ["open"]` — 400, а `excluded_statuses` (векторный `must_not`) пропускал бы задачи, которые FTS при статусах по умолчанию отсекает; умолчания статусов по виду (`question` — `answered`, `task` — только явным `kinds`) — задачи 3–5.
- **Запись (`entries/write.rs`) [решение исполнителя].** Без явного статуса — `initial_status` вида. При создании insight — `active` или `revisit` (как раньше); term, task, question — только начальный статус (замещение, отзыв и переходы — задачи 2, 4, 5); статус у changelog/release или чужой виду — `BadInput`. `certainty` при создании и правке — у insight и term; `default_certainty` для term не задан (агентский term без явного `certainty` — без статуса), правило решит задача 2. Смена статуса правкой (`PATCH`) — по-прежнему только у insight.
- **REST.** `POST /spaces/{space}/entries` с `kind: term|task|question` — 422 «вид <kind> появится в задаче N этапа M4.5» (term — 2, task — 4, question — 5) до разбора тела; временно, без теста (бриф). MCP `memory_log` принимает новые виды в `enum` и проверке (ответ REST — тот же 422). Qdrant: payload несёт `kind` строкой, виды нигде не перечислены — правок нет.
- **WebUI.** `EntryKind`, `EntryStatus` (`web/src/lib/api.ts`), подписи всех статусов в `STATUS_TEXT` (`journals.ts`); `STATUSES` — по-прежнему статусы insight (фильтр списка Insights). Экраны «Словарь», «Задачи», «Вопросы» и переход по связи к ним — задача 14.
- **Отложено в свои задачи.** Блок инструкции и `guide.{ru,en}.md` перечисляют типы связей без `contradicts` — задача 13 (бюджет 500 токенов); справка `zam link` дополнена `contradicts`.
- **Проверки.** `tests/migrate_rebuild.rs`: `rebuild_keeps_child_rows` (заодно — без `rebuild` тот же SQL падает на FK), `rebuild_fk_violation_rolls_back`, `rebuild_restores_foreign_keys_on`, `rebuild_migration_preserves_m4_db` (база на `USER_MIGRATIONS[..14]` через API хранилища: 300 записей трёх видов, каждая пятая с правкой, 50 триггеров, рёбра всех девяти типов M4, 5 замещений, удалённая запись, 50 строк `usage`; открытие через `UserDbs::get`: строки всех таблиц, кроме `meta` (отметки разовых задач открытия), прежние, индексы и триггеры совпадают, FTS по слову заголовка находит запись, `foreign_key_check` пуст, `foreign_keys` включены, `bak-v14` есть, самоссылки замещений целы), `entries_kind_status_check`; `tests/entries.rs`: `allowed_statuses_per_kind`, `new_kinds_via_create_entry`; юниты `edge_type_names` (с `contradicts`), `enums_round_trip` (`in_progress`), `entry_ref_letters` в `api/read.rs` и `mcp/tools.rs`, `entry_ref_letters_match_store` и `entry_refs` в `zam-cli`. Прежние тесты, поправленные под 0015: `filters_defaults_and_validation` (`excluded_statuses` теперь исключает и статусы task/question — ожидание вычисляется из `STATUSES`), `migrate_v13_to_v14` (итоговая версия — `USER_MIGRATIONS.len()`, а не 14). ### Задача 2 — словарь: запись терминов, уникальность, предупреждения псевдонимов, wiki-ссылки (2026-10-28)

- **Хранилище (`zam-store/src/glossary.rs`).** `TermData::parse` разбирает и нормализует `data` (пределы §2.1): `definition` обязательна (1..=300), `aliases` до 32 по 200, `not_to_confuse` до 16, `code` до 32 по 200; строки без пробелов по краям, без пустых и повторов; псевдоним без букв и цифр и неизвестное поле — ошибка `data.<поле>: …`; имя — 1..=200 символов с буквой или цифрой (`check_term`). `GlossaryEntry`, `active_terms`, `glossary_version`, `find_term`, `find_alias_uses` (по границе слова, без регистра, до 5; граница проверяется только у буквенно-цифрового края псевдонима, поэтому «C++17» находит «C++»).
- **Уникальность в транзакции записи.** `ensure_names_free` (вызывается из `insert_entry`, `update_entry` при смене имени или `data` и `restore_entry`): нормализованные (`normalize_title`) имя и псевдонимы нового термина не пересекаются с именами и псевдонимами `active` терминов пространства; нарушение — `StoreError::TermConflict(Vec<TermConflict {id, title, matched}>)` → `409 /problems/term-conflict` с `conflicts`. `matched` — имя или псевдоним **нового** термина как он задан **[решение исполнителя]**, `id`/`title` — существующий термин. Замещаемый термин при замещении и сам правимый исключаются. Удалённый, замещённый и отозванный термины имя освобождают; восстановление при занятом имени — 409.
- **Замещение и отзыв term.** `supersede_entry` и `retract_entry` принимают insight и term (новая запись того же вида); REST — те же `POST /entries/{id}/supersede|retract` и `supersedes_id` при создании. Правка замещённого и отозванного термина — 409, как у insight. Статус при создании — только `active`; `triggers` у term — 422.
- **Версия словаря.** `meta.glossary_version` растёт в транзакции любой записи term (создание, правка, замещение, отзыв, удаление, восстановление; при замещении — на 2: запись новой и смена старой). Отклонённая запись версию не меняет. Кэш словаря в процессе сервера (поиск, подсказки) — задача 3.
- **Нарезка только у `term`.** Источник чанков: `# имя`, `Псевдонимы: a, b`, определение, тело; псевдонимы и `code` добавлены к тегам префикса контекста (FTS находит термин по ним, а также по определению). Нарезка прочих записей и отпечаток `entry_chunker_fingerprint` не менялись — перенарезки не будет. L0 термина в `/read` — определение (`summary_of`), у прочих записей — заголовок.
- **Предупреждения `term_alias`.** `api/glossary.rs`: `alias_warnings` (имя и текст в пространстве записи) и `attach_warnings` дописывают `warnings` в ответ создания, замены и PATCH заметки, создания и PATCH changelog/release/insight, замещения insight. Запись не отклоняется; у `term` предупреждений нет; пустой словарь — один запрос.
- **Wiki-ссылки.** `links::resolve_target`: `[[Имя]]` без заметки (заметка приоритетнее) разрешается в `active` термин того же пространства по имени или псевдониму — ребро `links_to` с `dst_kind = entry`. `rebuild_derived` и `tree_changed` используют `resolve_target` (иначе пересчёт дерева разрывал бы ссылку на термин); `graph::terms_changed` вызывается при любой записи term и перепроверяет неразрешённые и указывающие на записи выведенные рёбра пространства: ожидающая ссылка находит термин, ссылка на выбывший термин становится неразрешённой. HTML-рендер заметок и `links` insight (`[[Имя]]` в `POST …/entries`) по-прежнему ищут только заметки (отложено, ниже).
- **REST.** `POST /spaces/{space}/entries kind: term` идёт через `insights::create` (пространство и права проверяются раньше вида: Human по токену — 404, из WebUI — 422, Rules — 403/422, `scope: global` — в Knowledge, как у insight); `kind_pending` теперь только `task` (4) и `question` (5), проверка стоит после `space_scope`; `GET /spaces/{space}/glossary` — список `{version, items}` и карточка `?term=` (имя или псевдоним). `PATCH` термина: `title` и `data` проверяются вместе (422), `certainty` разрешён у term.
- **MCP.** `memory_log kind=term` работает через REST без правок логики; описание инструмента и схема `data` дополнены (описание ≤ 300 символов). Число инструментов — 10.
- **CLI.** `zam glossary [<термин>] [--solution] [--json]` (список «имя — определение», карточка по имени или псевдониму, код 5 для неизвестного), `zam log term --title --definition [--alias]… [--code]… [--not-to-confuse]… [--area] [--solution] [--key] [--body-file]`; 409 `term-conflict` — пересечения построчно, код 4.
- **Мелкие замечания ревью задачи 1.** `apply_rebuild` перечитывает `foreign_keys` после `OFF` и при 1 возвращает `InvalidMigrations` «нельзя выключить foreign_keys: открыта транзакция» (юнит-тест `rebuild_rejected_inside_transaction`: через `apply` недостижимо — `VACUUM INTO` падает в транзакции раньше); комментарий `TargetFilter.statuses`; `kind_pending` без `_ =>`; длинные строки доки `entries/mod.rs`.
- **Правки прежних тестов.** `new_kinds_via_create_entry` создаёт term с `data.definition` (теперь обязательна).
- **Проверки.** Новые: `zam-server/tests/glossary.rs` (10 тестов брифа), `zam-cli/tests/glossary.rs` (`glossary_list_and_card`, `log_term_args`), `zam-store/tests/entries.rs` (`term_chunks_carry_aliases_and_definition`, `term_names_unique_in_transaction`), юниты `glossary.rs` в `zam-store`, `zam-cli` и `zam-server`.

## Решения

Решения контроллера и исполнителя, принятые без владельца; каждое можно пересмотреть.

- **Ошибка пересборки — существующий вариант `StoreError::InvalidMigrations` (исполнитель, задача 1).** Спецификация §1.1 называет её `InvalidMigration`; отдельный вариант не заведён: это та же «миграция неприменима», `is_permanent() = true`, повтор не поможет.
- **Создание term/task/question — только с начальным статусом (исполнитель, задача 1).** Задачи 2, 4, 5 могут расширить (например, задача сразу `in_progress`).
- **`filters.status` принимает все статусы видов (исполнитель, задача 1)** — см. запись задачи 1.
- **`matched` в `term-conflict` — имя нового термина (исполнитель, задача 2).** Спецификация §2.1 не уточняет, чьё имя; пара `id`/`title` называет существующий термин, `matched` — то, что клиент прислал и должен поменять.
- **«Не путать с» — строки до 200 символов, до 16 (исполнитель, задача 2).** Спецификация задаёт только число.
- **`data` термина строгая (исполнитель, задача 2).** Неизвестное поле — 422 `data.<поле>: неизвестное поле`; расширение схемы — правкой этого места.
- **Версия словаря при замещении растёт на 2 (исполнитель, задача 2).** Монотонность важна, шаг — нет.

## Отложенные замечания

- **Рендер HTML заметки и `links` insight не знают терминов (задача 2).** `[[Имя]]` на термин в `GET /render` остаётся нерешённой, в `links` insight `target: [[Имя]]` ищет только заметку. Граф (рёбра `links_to`) терминов уже достигает. Решить вместе с экраном «Словарь» (задача 14).
- **Предупреждения `term_alias` ищут термины только пространства записи (задача 2).** Заметка решения не видит терминов Knowledge (и наоборот); объединение пространств области — вместе с расширением запроса (задача 3).
