### Задача 1 — крейт `zam-code`: протокол и экстрактор tree-sitter (2026-11-03)

- **Крейт `zam-code`** (член workspace, `exclude += crates/zam-code/fuzz`). Без фич — `proto.rs`
  (`Lang`, `SymbolKind`, `RefKind`, `ParseState`, `SkipReason` со строками спецификации через
  `as_str`/`parse`/`ALL`/serde; `Symbol`, `RefAgg`, `FileUpload`, `ManifestItem`, `SymbolHash`;
  пределы `SIG_MAX_CHARS` 160, `NAME_MAX_CHARS` 256, `QUAL_MAX_CHARS` 512, `UPLOAD_FILES_MAX` 500,
  `MISSING_HASH` — 64 нуля, как `zam-cli` `refs::MISSING_HASH`; `lang_of`, `sig_line`,
  `body_hash`) и `names.rs` (`split_ident`, `fts_terms`, `split_ref`). Фича `parse` — `extract/`
  (`mod.rs` — порядок разбора, символы, ссылки; `lang.rs` — правила языков; `sniff.rs`). Зависимости
  без фич — только `blake3` и `serde`.
- **Запросы.** `TAGS_QUERY` грамматики + `queries/<язык>.scm`; TypeScript/TSX — ещё и
  `TAGS_QUERY` JavaScript (грамматика TS наследует JS, все шаблоны JS в ней компилируются); C# —
  только свой `csharp.scm`. Вид символа — по виду узла `@definition.*` (`lang::def_kind`), запасной
  путь — суффикс захвата. Дополнения сверх плана: Rust `associated_type` (`type`),
  `function_signature_item` (метод трейта без тела), `impl` трейта по пути и обобщённого
  (`impl fmt::Display`, `impl From<X>`) как `impl`; JS/TS — поля-стрелки класса (`handler = () =>`)
  как `method`, `extends`/`implements` как `impl`; Python — импорты, аннотации типов, базовые
  классы (`impl`), декораторы (`call`); Go — `type_alias`, методы интерфейсов (`method_elem`,
  контейнер — `type_spec`), константы верхнего уровня; Java — `enum`/`record`/`@interface`,
  конструкторы (в т. ч. компактные записей) и элементы аннотаций как методы, импорты, `type_list`
  обобщений; C# — запись `record struct` — `struct`, делегат — `type`.
- **Решения исполнителя.**
  1. **`line` — строка имени**, а не начала узла: декораторы Python/TS, аннотации Java,
     атрибуты C# не сдвигают строку; `sig` — с первой непробельной позиции строки имени (не
     раньше начала узла), поэтому `@Override` в сигнатуру не попадает. `end_line` — конец узла;
     `body_hash` — весь текст узла (декоратор — часть тела).
  2. **`split_ref`: «последний `#`, при котором префикс — путь кода, а суффикс — допустимый
     `qual`»** вместо буквального «последний `#`»: иначе ссылка на одноимённый `a.rs#foo#2`
     (Review Focus 2) стала бы путём. В суффиксе `#` допустим только как `#N` в конце
     (`src/c#/x.rs#Foo` → путь `src/c#/x.rs`).
  3. **Метод или функция** решает ближайший предок-контейнер или функция: функция в `impl`/`trait`
     Rust и в классе Python — `method`, вложенная в метод — `function` (её `qual` всё равно несёт
     контейнеры выше: `Cache::inner`). Модули (`mod`, `namespace`) — контейнеры `qual`, но не
     «классы». Контейнер `impl` — тип без обобщений (`impl<A> Pair<A>` → `Pair`, `impl net::Client`
     → `net::Client`); анонимный класс Java — не контейнер (метод — `Store::run`).
  4. **Конструкторы JS/TS не извлекаются** (встроенный `tags.scm` их исключает: `#not-eq?
     "constructor"`), у Java/C# — извлекаются (`Store::Store`, `#2`); Python `__init__` — метод.
     Приватные методы JS `#name` не извлекаются (символ `#` ломал бы `путь#qual`).
  5. **Ссылки:** один узел имени — один вид по приоритету `impl > call > import > type > other`
     (глобальный шаблон `type_identifier` иначе дублировал бы `impl`); `Store::open()` — `call
     open` и `type Store`; импорт строкой — последний сегмент пути (`"net/http"` → `http`); `Self` —
     не ссылка. Символы и ссылки с именем > 256, `qual` > 512 символов или с управляющими —
     отбрасываются (сервер ответил бы 422).
  6. **Запросы компилируются один раз на процесс** (`OnceLock` на язык) и отсечка времени
     начинается после компиляции. Из встроенных запросов JS и Go вырезаются захваты
     документирующих комментариев (`(comment)* @doc .`, `#strip!`, `#select-adjacent!`,
     `#set-adjacent!` — экстрактор их не берёт): компиляция TS 44 → 31 мс.
  7. **`symbol_hashes` (для хуков) — отдельный запрос только определений** (шаблоны с
     `@definition.`, разбор S-выражений верхнего уровня): итог равен `extract` на всех эталонах
     (тест), компиляция быстрее (таблица ниже).
  8. **Тесты без фичи** — отдельный `tests/proto.rs` (9 тестов: `lang_of`, `split_ref`,
     `split_ident`, `fts_terms`, `sig_line`, `body_hash`, serde перечислений), чтобы они шли и в
     `cargo test -p zam-code` без C-кода; `tests/extract.rs` — 19 тестов фичи `parse`.
- **BOM.** Срезается до эвристик и разбора, как требует план; мутационная проверка показала, что
  лексер tree-sitter 0.27 пропускает BOM и сам (тест `body_hash_same_for_crlf_lf_and_bom` зелёный и
  без среза) — срез оставлен явным ради `sniff` и смещений.

### Ревью задачи 1 — правки (2026-11-03)

Ревью — CHANGES REQUIRED (C1, C2, I1, I2, M1–M7). Затронуты только `crates/zam-code/src/extract/`,
`queries/`, `tests/extract.rs` и эталоны TS/TSX; `rank.rs`/`pack.rs` (задача 2) не тронуты.

- **C1 (квадратичный подъём к корню).** `Node::parent()` в tree-sitter 0.27.1 спускается от
  корня, поэтому подъём от каждого определения стоил O(глубины²): 80 КБ вложенных блоков
  разбирались 13,8 с при отсечке 200 мс. Теперь **один обход дерева `TreeCursor` в глубину** без
  рекурсии. Параллельно пути курсора идёт стек контекстов: звено цепочки контейнеров, ближайший
  класс, модуль или функция, `export` TS/JS, «внутри функции или тела класса», а также виды
  родителя и деда. `Node::parent()` больше не вызывается нигде. Звено цепочки хранит готовый
  `qual` контейнера, а длиннее 512 символов — `None`, поэтому глубина не умножает работу.
  Дедлайн проверяется раз в 1024 узла обхода и между символами. Замер на входах ревьюера
  (release, отсечка 200 мс): `jsnest`/`jsclass`/`rsmod`/`csns` (20 000 уровней) — `timeout` за
  214–255 мс; `jsblock` — `ok`, 44 мс. Регрессия `deep_blocks_definition_respects_timeout`:
  JS-блоки, Rust `mod`, C# `namespace`, классы JS (по 20 000 уровней), отсечка 50 мс → `ok` или
  `timeout` быстрее 150 мс, для `extract` и для `symbol_hashes`. До правки тест падал.
- **C2 (переполнение стека).** `rust_type_path` переписан циклом. Тест
  `rust_impl_deep_reference_type_no_stack_overflow` проверяет 10 000 и 100 000 уровней `&` и
  `V<…>`. Других рекурсивных обходов нет (`go_receiver` — явный стек).
- **Решение исполнителя: определения — обходом без `Query`, в обоих режимах.** Правила
  `@definition.*` встроенных `tags.scm` и `queries/*.scm` повторены явно таблицей видов узлов
  (`lang::defs_of`, `js_defs`): поле `name`, условия на родителя и деда (константа модуля Python,
  `const` верхнего уровня Go, `variable_declarator` под `lexical/variable_declaration`), значение
  стрелка или функция. Запрос (`refs_query`) теперь содержит **только ссылки**: из встроенных
  `TAGS_QUERY` берутся шаблоны с `@reference.` (`references_only`), из `queries/*.scm` шаблоны
  определений удалены. Отступление от плана («вид — по узлу `@definition.*` запроса»): одна
  реализация определений для `extract` и `symbol_hashes`, у хука нет компиляции запроса. Точность
  и полнота на эталонах по-прежнему 1,000.
- **Бюджет хука (для задачи 6 сделано здесь).** `symbol_hashes` работает без запроса
  (подготовка 0,0–0,2 мс против 14–24 мс у прежнего запроса определений). Дедлайн абсолютный, от
  вызова, включая подготовку. У `extract` отсечка начинается после компиляции запроса ссылок
  (один раз на процесс). Компиляция запроса ссылок, release, мс: Rust 13,7; TypeScript 11,7 (было
  31,3); TSX 12,2; JavaScript 5,2; Python 4,6; Go 1,3; Java 3,7; C# 44,1. Разбор `crates/` (412
  файлов, 8,1 МБ) — 1,97 с; `symbol_hashes` на `recall.rs` (106 КБ) — 14,3 мс. Задаче 6 остаётся
  отсечка 20 мс и предел 512 КиБ на разбор в хуке: разбор крупнейшего файла проекта близок к
  отсечке.
- **I1 (`exported` TS/JS).** `export` берётся из контекста обхода: узел под `export_statement`
  экспортирован. Его снимают границы: функции, `statement_block`, `internal_module`/`module`,
  `class_static_block`. Тело класса границей не является, поэтому методы и поля экспортированного
  класса — `true`. Случаи ревью добавлены в `exported_flags_per_lang`: inner, локальная стрелка,
  `hidden` неэкспортированного члена `export namespace` → `false`; `shown`, `G::K::m`, `k`
  экспортированного литерала, `E::g` → `true`.
- **I2 (литералы объектов).** `pair` и методы литерала (`method_definition` с родителем `object`)
  дают символы только вне функций и тел классов (верхний уровень модуля или пространства имён).
  Из эталонов убраны `Geometry::distance` (TS) и `Theme::shade` (TSX). Тест
  `object_literal_members_only_at_top_level` (JS и TS).
- **M1.** `impl_item` — всегда контейнер с видом `method`. Тип без обобщений и ссылок (`&mut S` →
  `S`, `Box<dyn Tr<T>>` → `Box`), иначе текст без пробелов: `[u8]`, `(A,B)` (до 128 символов,
  иначе `_`). Тест `rust_impl_for_any_type_is_container`.
- **M4.** `symbol_hashes` при `partial` возвращает `None`: усечённый список хук принял бы за
  удаление символов. Тест дополнен.
- **M5.** Вырезка захватов документирующих комментариев `strip_doc_captures` удалена вместе с
  шаблонами определений: в ссылочных шаблонах встроенных запросов `(comment)* @doc` нет, а
  `references_only` отбрасывает шаблоны с `@definition.` целиком.
- **M6.** `valid_name` запрещает `/` и `#` (в имени символа, в каждой части `qual` и в имени
  ссылки). Тест `names_with_slash_or_hash_rejected` проходил и до правки: ключ-строка `"a/b"` не
  совпадал ни с одним шаблоном, проверка оставлена защитной.
- **M7.** Регрессии C1 и C2 — выше.
- **M2 (известное ограничение, первая очередь).** C#: свойства, индексаторы, операторы, события и
  деструкторы не извлекаются (вида «свойство» в `SymbolKind` нет). Члены интерфейсов Java/C# без
  явного `public` — `exported = false`, хотя публичны неявно.
- **M3 (задача 9).** Формулировка `deploy/licenses/TREE-SITTER-QUERIES-MIT.txt` — «грамматики и
  запросы»: C-код грамматик тоже входит в `zam`. Проверить, как `cargo about` обходится без
  файлов `LICENSE` в пакетах `tree-sitter-typescript` и `tree-sitter-java`.
- **Проверки:** `cargo test -p zam-code --features parse -j 2` — extract 24, proto 9, rank 12,
  pack 8 зелёные; без фичи — proto 9, rank 12, pack 8; `cargo clippy -p zam-code --all-targets`
  с `--all-features` и без, `-D warnings` — чисто; `cargo fmt` по `zam-code` — чисто.
  Расхождения `fmt` есть только в чужом `crates/zam-store/tests/code_map.rs` (задача 3).

  `MapFile`, `Packed`, `map_line`, `render_map`) — интерфейсы плана без изменений; `proto.rs`
  не тронут. Атрибуция Aider (Apache-2.0) — в шапке `rank.rs`; код написан заново.
- **Решения исполнителя.**
  1. **Множители имени перемножаются** (как у Aider): `_длинное_имя` — ×10 × 0,1 = 1; «длинное» —
     ≥ 8 символов при `_`/`-` с буквой или смешанном регистре. ×10 упомянутым в фокусе именам
     (есть у Aider) не введено: фокус — только вектор перезапуска, как в плане.
  2. **`d` в весе ребра — все файлы с определением имени, включая сам A**, ребро A → A не
     строится (буквально по плану). Имя, определённое и в A, и в B, даёт A → B половину веса.
  3. **PageRank:** старт равномерный; висячие узлы — масса по вектору перезапуска; мусорные рёбра
     (индекс вне `n`, вес ≤ 0 или не конечный) и вектор перезапуска без положительной массы
     (→ равномерный) не дают NaN; `rank_on_edges` — тот же `pagerank` (сервер передаёт рёбра,
     переведённые из id в индексы). Сходимость за 50 итераций — тест против эталона на 2000
     итераций (L1 < 1e-4).
  4. **Доля символа — входящий поток ранга по имени** `r[src] × w / out(src)` (а не сырой вес
     ребра): ссылка из важного файла весит больше. Одноимённые определения делят поток поровну.
     «Остаток» символам без входящих ссылок — фиксированные **10 %** ранга файла (`UNREFERENCED_SHARE`),
     делятся по весу вида (типы/трейты/интерфейсы ×2, `exported = Some(true)` ×2); файл без
     входящих ссылок — 100 % по весу вида. Вариант «остаток = ранг − входящий поток» отвергнут:
     масса висячих узлов (телепорт) отдавала неиспользуемым символам больше половины ранга файла.
  5. **`focus_idents`** — слова `[буква|_][буква|цифра|_]*` длиной ≥ 3 символов (Unicode), без
     повторов, в порядке появления; совпадение с именами определений и `focus.paths` — точное
     (сервер нормализует пути до вызова). Масса перезапуска — 1 каждому совпавшему файлу.
  6. **`central`** — сортировка по рангу символа, при равенстве — по индексам (детерминизм).
  7. **`render_map`:** строки соединяются `\n`, файл — строка `path`, файл без символов — одна
     единица префикса (только путь). Хвост — с русскими формами числительных («1 файл, 3
     символа», «12 файлов»). Поиск префикса — **экспоненциальный, затем двоичный**: счётчик видит
     тексты не длиннее ≈ удвоенного ответа (точный bge-m3 на полной карте 50 000 файлов был бы
     дорог; тест `render_map_counts_only_texts_near_answer`, мутация «сначала весь текст» —
     2 721 633 символа при ответе 1 682). Каждый принятый префикс проверен счётчиком, поэтому
     немонотонный счётчик за бюджет не выводит. Заголовок длиннее бюджета обрезается по
     символам — с хвостом, если хвост влезает, иначе без него; `count("") > budget` — пустой
     текст (единственный случай, где `tokens ≤ budget` не гарантируется).
- **Тесты** (`tests/rank.rs` 12, `tests/pack.rs` 8, включая proptest
  `render_map_budget_property` 256 случаев, бюджеты 1..20000, два счётчика): сверх плана —
  `focus_idents_and_text_give_restart_mass`, `render_map_tail_plural_forms`,
  `render_map_long_header_truncated`, `render_map_counts_only_texts_near_answer`. В
  `focus_paths_and_their_targets_in_top5` фокусный файл ссылается на хаб и три цели (с ним —
  ровно пять файлов), без фокуса ни он, ни цели в пятёрку не входят.
- **Риск для задачи 4:** число рёбер по имени — `ссылки × определители`; у общих имён (`new`,
  `from`, `default` в тысячах файлов) на 50 000 файлах это 10^7–10^8 вкладов до суммирования.
  План это допускает (`rank_timeout_ms` 1000, старые ранги и `rank pending`); при замере в
  задаче 4 — кандидат: пропускать имена с числом определителей сверх порога (у них и так ×0,1).

### Ревью задачи 3 — исправления (2026-11-03)

Ревью: CHANGES REQUIRED, замеры ревьюера — `.tmp/m56/review-t3/` (50 000 файлов × 20 символов ×

- **I1. Ранги символов не хранятся строками.** `code_store_ranks` переписывал весь
  `code_symbols` (10^6 UPDATE, 6,4 с под замком писателя, +74 МиБ WAL). Теперь у файла —
  `code_files.rank` и `code_files.shares` (BLOB f32 little-endian в порядке `code_symbols.id`

  у `code_symbols` нет (0023 не выпущена — правка самой миграции). Ранг символа = ранг файла ×
  доля — при чтении (`MapSymRow`, `SymbolHit`; место символа в файле — подзапрос по индексу
  `code_symbols_file`). Пишутся только файлы, у которых ранг сдвинулся больше чем на 1e-4
  относительно или доля — больше чем на 1e-4 (исполнитель: пороги).

  символьные ссылки и только по загруженным символам (другое тело — `symbol_changed`, нет символа

  трогают; хэш файла ссылке не передаётся. Подтверждение тела снимает только `stale` по символу —
  `stale`/`source_changed`, поставленный хуком, остаётся (исполнитель: иначе ссылка мигала бы
  между хуком и загрузкой). Файловые ссылки и хэш файла меняют только хуки рабочей копии

### Повторное ревью задачи 4 — оговорки O1, O3 (2026-11-03)

Повторное ревью — APPROVED с оговорками; O1 и O3 — малой правкой, O2 и O4 — в задачу 9.

- **O1. Чтение входов для фокуса — отдельной задачей.** `CodeRuntime::loading` — идущие чтения
  `code_rank_inputs` по `(владелец, GUID, etag снимка)`: одно на всех ждущих (`Shared`-будущее
  над `tokio::spawn`), срок запроса его не отменяет — дочитанное ложится в кэш входов, и
  следующий запрос идёт с фокусом. Входы кладутся в кэш, только если `etag` снимка до и после
  чтения совпал. Фоновый пересчёт рангов (`store_rank`) кладёт свои входы в тот же кэш (ранги
  `etag` не меняют); рёбра `format=json` берут входы тем же путём. Запрос ждёт входов, слота и
  счёта не дольше `max(rank_timeout_ms, 200)`, иначе — карта без фокуса и `focus rank timeout`.
  Тест `focus_inputs_load_survives_timeout_single_read` (`CodeHooks::inputs_delay_ms`): два
  параллельных запроса откатываются без фокуса при одном чтении, следующий — с фокусом из кэша.
- **O3. Манифест `sync`** разбирается сразу в `Vec<ManifestIn {path, hash}>`
  (`deny_unknown_fields`; лишнее поле элемента — 400), без промежуточного `Value`. С заголовком
  `X-Zam-Solution` права проверяются **до чтения тела** (тело читается вручную,
  `axum::body::to_bytes` с пределом `sync_body_max`), `solution` тела обязан совпадать с
  заголовком (иначе 422). Тест `sync_header_checks_rights_before_body` (токен `ro` с заголовком —
  403 и на теле больше предела; без заголовка — сначала 413). **Для задачи 9:** клиент задачи 5
  заголовок `X-Zam-Solution` в `zam code sync` пока не шлёт — добавить, тогда чужой токен не
  заставит сервер читать десятки мегабайт.
- **O2 (задача 9, замер):** кэш входов — до 2 решений без срока жизни; входы 50 000 файлов —
  порядка сотен МБ. Замерить память на синтетике 50 000 файлов и решить: TTL, предел по
  размеру или один слот.
- **O4 (задача 9, замер):** `GET /code/files` читает все файлы карты и фильтрует в памяти —
  замерить на 50 000 файлов; при необходимости — фильтр и `LIMIT/OFFSET` в SQL хранилища.

## Решения

Решения контроллера, составителя плана и исполнителя, принятые без владельца; каждое можно

### Решения контроллера по вопросам §15 спецификации (2026-11-03)

Владелец разрешил работать автономно; ответы ниже приняты контроллером по рекомендациям
спецификации и действуют до ответа владельца. Каждое —
**[решение контроллера, на подтверждение владельцу]**.

1. **Сигнатуры на сервере** — отправляются (первая строка определения, ≤ 160 символов, секреты
   маскирует сервер `zam_markdown::mask_text`), выключатель клиента `code.send_signatures`
   (`true`; `false` — поле `sig` не отправляется, карта — только имена и виды).
2. **Языки первой очереди** — Rust, TypeScript/TSX, JavaScript/JSX, Python, Go, Java **и C#**
   (у владельца много .NET-проектов; +5,5 МБ к бинарнику `zam`, собственный запрос тегов
   `queries/csharp.scm`). C/C++ — позже (фича сборки), Svelte/Vue, Kotlin, PHP, Ruby, Swift — по
   запросу (§14).
3. **MCP** — новый, 11-й инструмент `memory_code` (`action: map | symbol | refs | impact`), символы
   не встраиваются в `memory_search`/`memory_read`; тест `mcp_tool_count_still_10` заменяется на
   `mcp_tool_count_11`.
4. **Дайджест** — только строка-указатель (≤ 80 токенов: размер карты, возраст снимка,
   центральные символы, как позвать карту); карта — по запросу; расширение — по агентному A/B в
   M6.
5. **Автосинхронизация** — фоновым отсоединённым процессом `zam code sync --background` из хуков
   `session-start` и `checkpoint` (после правок), не чаще `code.auto_interval_min` (30 мин) или
   при смене `HEAD`, под замком; выключатели — `code.auto` (клиент) и тип подсказок `code_map`.
6. **Одна карта на решение** — «последний снимок побеждает» пофайлово; коммит, ветка и машина
   загрузки хранятся у каждого файла и видны в заголовке карты; карты по веткам — позже.
7. **Разбор — в процессе `zam`** с журналом падений `cache/code-parsing.json`, пределами,
   эвристиками пропуска, отсечкой по времени и `catch_unwind`; отдельного рабочего процесса нет,
   песочница ОС — в M7 вместе с `doc-worker`.
8. **WebUI** — без интерактивного графа: состояние снимка, поиск символа, таблица файлов,
   карточка символа, обзор зависимостей Mermaid (40 файлов, до 120 рёбер, ELK); интерактивный граф
   — отдельной задачей позже.

### Решения составителя плана (2026-11-03)

Спецификация их не определяет или определяет неоднозначно (подробности — план, раздел «Решения
составителя плана»). Каждое — **[решение составителя плана]**, переносится в ТЗ в задаче 9.

1. **Порядок задач** уточнён против §16 спецификации: ранжирование и упаковка карты (чистые функции
   `zam-code`) — задача 2, миграция и хранилище — задача 3: хранилище сохраняет ранги в типах
   ранжирования (`zam_code::{RankFile, Ranked}`).
2. **Миграция** — `0023_code_map.sql` (последняя пользовательская на main — `0022_reports.sql`),
   `rebuild: false`: `ALTER TABLE file_refs ADD COLUMN symbol, symbol_hash` и пересоздание
   уникального индекса `file_refs_owner` по `(owner_kind, owner_id, path, COALESCE(symbol, ''))`;
   запасной путь, если SQLite не примет выражение в цели `ON CONFLICT`, — столбец `symbol_key`.
3. **Разбор ссылки `путь#qual`** (`zam_code::split_ref`) — по последнему `#`, только если префикс
   — путь кода (`lang_of`) и суффикс — допустимый `qual`; иначе вся строка — путь. Одно правило для
   frontmatter `refs:`, `data.refs.files`, `refs.files[i].path`, `--ref`.
4. **Устарелость:** символьная ссылка, подтверждённая по символам (`ok`), принимает новый хэш
   файла; удалённый файл (`MISSING_HASH`) — символьные ссылки `symbol_removed`.
5. **Хук `post-tool`** кладёт в очередь хэши **всех** символов правленого файла (≤ 5000), а не
   только из ссылок: кэш `file-refs.json` может отставать, и новый символьный референс получил бы
   ложный `symbol_removed` (отступление от §8 спецификации «только по символам из ссылок»).
6. **Хэш файла в манифесте** — всегда blake3 содержимого; git oid и размер+`mtime` — отпечатки,
   по которым клиент берёт хэш из `code-state.json` без чтения файла. Вторая машина со сброшенным
   состоянием читает файлы, но не разбирает и не загружает их.
7. **Малый `cache/code-sync.json`** (последняя успешная синхронизация, `HEAD`) отдельно от
   большого `code-state.json`: хук читает только его, `HEAD` — из файлов `.git` без процесса
   `git` (бюджет запуска ≤ 10 мс).
8. **Журнал падений** — перезапись малого файла без fsync перед каждым файлом (обрыв процесса
   запись сохраняет); пропуск `parser_crash` держится, пока хэш файла тот же. Разбор — в одном
   потоке.
9. **C#:** контейнеры `qual` — классы, структуры, интерфейсы, записи, без `namespace` (как
   пакеты Java); свойства в первой очереди не извлекаются.
10. **Ранги:** символу без входящих ссылок — доля по виду и `exported`; с `focus` — ранг файла
    персонализированным PageRank по сохранённым рёбрам × сохранённая доля символа; пересчёт
    single-flight на решение, сверх `rank_timeout_ms` — старые ранги и `rank pending`.
11. **Счётчик токенов карты** — `zam_store::count_tokens` (как у всех `tokens` сервера: точный
    bge-m3 при загруженной модели, иначе приближённый), а не всегда `ApproxCounter`.
12. **Маршруты `/code/*`** — в `service_routes` (не запись памяти, `memory_writes` не растёт);
    `code.enabled = false` — 404; сигнатура маскируется при записи и хранится маскированной.
13. **Строка знания о файле:** один символ — «о `Sym` в <путь> в памяти: …»; смесь символьных и
    файловых — «о файле <путь> в памяти: `Sym`: …; …», символьные первыми.
14. **WebUI:** «Код» — элемент `Journal` (`#/u/…/s/…/j/code[/<путь#qual>]`); карточка в адресе —
    по `путь#qual`, а не по id символа (id меняется при перезагрузке файла).
15. **Блок инструкции v5** (v4 — 494 из 500 токенов): строка «Код — с `refs.files`; новое
    понятие → `term`, пиши каноническими терминами.» заменяется строкой о `путь#Тип::метод`,
    `memory_code`/`zam code map` и `zam code sym`; в протокол `zam guide` переносятся
    «(исследование — `insight_kinds=[experiment,failure]`)», «(не про проект — scope=global)» и
    «пиши каноническими терминами»; запасной порядок сокращений — в плане (задача 7).
16. **Имитация обрыва процесса** в приёмке (§17 п. 7) — тестовый крючок `zam` только в
    debug-сборке.
17. **10 ключевых типов** для критерия §17 п. 3 (фиксируются до реализации): `Id`, `Db`,
    `StoreError`, `ApiError`, `AppState`, `Principal`, `Entry`, `Node`, `SpaceKind`,
    `ServerConfig`; порог — ≥ 6 из 10 в первых 15 центральных символах.
