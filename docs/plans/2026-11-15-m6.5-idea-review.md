# M6.5. Разбор идей агентом — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Агент сам разбирает новые идеи человека и выносит исход («в план», «на доработку»,
«отклонить», «уже сделано») с обязательным разбором, который человек видит в WebUI.

**Architecture:**
- Разбор — новая операция журнала «Идеи» поверх механизмов M5.7:
  - транзакция хранилища по образцу `apply_decision_tx`;
  - маршрут `POST /entries/{id}/review`;
  - ветка `review` в MCP `memory_update_entry`;
  - CLI `zam idea review`.
- Агент узнаёт об очереди из дайджеста (`### Идеи на разбор`) и пакета `memory_recall event=idea_review` с похожими записями. Пакет собирается внутренним поиском `inner_search`.
- Режим `ideas.mode` (`review` по умолчанию, `propose` — поведение M5.7) переключает дайджест, подсказки и допустимые операции.

**Tech Stack:** Rust (axum, rusqlite, serde), SQLite-миграции пользователя, Svelte + TypeScript
(WebUI), Playwright (e2e).

**Spec:** `docs/specs/2026-11-15-m6.5-idea-review.md` (согласован владельцем 2026-11-15). Основа —
`docs/specs/2026-11-04-m5.7-ideas.md`. Карта кода — отчёт исследования в журнале этапа
`docs/plans/2026-11-15-m6.5-dogfood-log.md` не нужен: пути ниже взяты с HEAD `d647d2c`.

## Global Constraints

- **Ветка и версия.** Ветка `m6.5-dogfood`, версия выпуска `0.0.12-m6.5`.
- **Миграция.** Пользовательская миграция `0026_idea_review.sql`, `rebuild: true`, копия `bak-v25`.
- **Статусы.** Значения идей в базе остаются прежними. Добавляется одно новое — `returned`.
  Подписи WebUI: Непросмотрено · На доработку · В плане · Отклонена · Сделано · Отложена ·
  Предложена.
- **Исходы разбора** — `plan | return | decline | done`.
  - `summary` — не короче `ideas.review_min_chars` (200) и не длиннее 8000 символов.
  - `missing` — обязателен у `return`, ≤ 2000.
  - Исход `done` требует в `basis` ссылку на сделанное (`c:`, `commit:`, `k:` задачи `done`,
    `r:`).
- **Кто разбирает.** Разбор — только токен. Из WebUI — 422 «разбор — действие агента».
  - Условия: идея живая, пространство решения (Knowledge — 422), `origin: human`, статус `new`.
  - Иначе 409: `transition-not-allowed`, `idea-agent-origin`, `idea-mode`.
- **Режим** `ideas.mode`: `review` (по умолчанию) или `propose`.
  - Умолчание сервера — `[ideas] default_mode`, настройка пользователя важнее.
  - В общем решении действует режим владельца базы.
  - `ideas.proactive = false` выключает и раздел, и подсказки.
- **Дайджест** `### Идеи на разбор` — только на первом `session_start` сессии.
  - До 3 строк идей: `high` первыми, затем самые старые.
  - Строка плана: «План из идей: N открытых, следующая — k:<id> «…» [<priority>]».
  - Напоминания на `Stop` нет.
- **MCP.** Новых инструментов нет, их 11. Описание каждого инструмента и каждого поля схемы — не
  длиннее 300 символов (тесты `mcp_descriptions_under_300`).
- **Блок инструкции** v8 — не больше 500 токенов bge-m3 в худшем случае
  (`agent_setup_block_v7_under_500_tokens_ru_en` переименовывается в `…_v8_…`).
- **Совместимость.** Флаг `idea_review` в `GET /api/v1/health` `features` и строка в
  `docs/api-compat.md` (тест `health_features_documented`).
- **Старый сервер.** Сообщение CLI: «сервер не поддерживает разбор идей: нужен zam-server
  0.0.12-m6.5 или новее».
- **Правила проекта:**
  - временные файлы — только внутри проекта под `.gitignore` (`.tmp/`, `target/`);
  - коммиты — только явными путями;
  - адреса LAN и секреты в коммиты не попадают;
  - сборка: `. scripts/dev-env.ps1`, свой `CARGO_TARGET_DIR` в `target/`, `-j 2`;
  - интеграционные тесты — `cargo test --workspace --test X`.
- **Решения составителя плана** (в спецификации — с пометкой при задаче 9):
  1. рёбер `mentions` из `basis` нет — ссылки только в `data.review`, с префиксами, чтобы импорт их переписывал;
  2. разбор в WebUI показывается текстом с переносами, как тело идеи;
  3. отдельной ошибки `idea-human-decided` нет — её покрывает условие «статус `new`»;
  4. проверку режима ведёт одна ошибка `idea-mode` (409).

## Review Focus

1. **Повтор разбора после обрыва связи.** Тот же `idempotency_key` возвращает прежний итог 200 и не
   заводит вторую задачу. Тест — задача 2, `review_retry_same_key_returns_same_task`.
2. **Человек правит возвращённую идею, пока агент разбирает другую ревизию.** Правка с устаревшим
   `If-Match` даёт 409. Разбор идеи, которая уже стала `new` после правки, проходит по новой
   ревизии. Тест — задача 1, `human_edit_returned_goes_new_and_stale_rev_conflicts`.
3. **Одна задача на несколько идей.** Задача `done` переводит в `done` все живые идеи с ребром
   `derived_from` на неё. Переоткрытие задачи возвращает их в `accepted`. Тест — задача 1,
   `task_done_closes_all_linked_ideas`.
4. **Мусор в ссылках `basis`/`similar`.** Неизвестный id, чужое пространство, ссылка без префикса,
   `file:` с `..` дают 422 с названием поля. Строки `file:`/`commit:` проверяются только по форме.
   Тест — задача 2, `review_rejects_bad_refs`.
5. **Участник общего решения с правом `ro`** получает 403. Агент участника с `rw` разбирает по
   режиму владельца. Тест — задача 3, `review_shared_solution_rights_and_owner_mode`.
