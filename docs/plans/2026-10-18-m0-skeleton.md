# M0. Каркас ZeroAIMemory — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal.** Получить работающий каркас:
- `zam-server` стартует, берёт администратора из конфига, ведёт `system.db` и базы пользователей с миграциями;
- выпускает и проверяет токены, отдаёт `/health`;
- показывает WebUI-заглушку со входом, пользователями и токенами;
- `zam status` проверяет связь с сервером;
- каждый тег `v*` собирает комплекты Windows x64 и Linux x64 (с Qdrant, ONNX Runtime и pdfium), прогоняет на них smoke-тест и публикует черновик релиза.

**Architecture.**
- Workspace Cargo из крейтов `zam-core`, `zam-store`, `zam-server`, `zam-cli` и `xtask`.
- SQLite через `rusqlite`. На каждый файл БД — один поток-писатель и пул читателей.
- HTTP на `axum` 0.8: REST `/api/v1` с аутентификацией по bearer-токену или cookie администратора.
- WebUI на Svelte 5 встроен в бинарник через `memory-serve`.
- Сборка и упаковка — `cargo xtask` по манифестам зависимостей в `deploy/`.

**Tech Stack.**
- Rust stable, edition 2024: axum 0.8, tokio, tower-http, rusqlite 0.40 (`bundled`), serde, toml, argon2, sha2, rand, uuid (v7), jiff 0.2, tracing, tracing-subscriber, tracing-appender, memory-serve, clap, ureq 3, thiserror, anyhow (только в бинарниках и xtask), fs4 (лок-файл).
- WebUI: Svelte 5, Vite, TypeScript, bits-ui, size-limit.
- CI: GitHub Actions (`windows-latest`, `ubuntu-22.04`).

**Spec:** `docs/specs/2026-10-17-zeroaimemory-tz.md` (v1.0). Нужны §4.3, §5, §6.1–6.3, §11.4–11.5, §12, §13.2–13.3, §15.1, §16, §16.3, §17, §19 (строка M0), §20.

## Global Constraints

- Временные файлы, логи прогонов и тестовые данные — только внутри проекта: `.tmp/` или `target/`. Запрещены `/tmp`, `%TEMP%`, `AppData\Local\Temp`, `std::env::temp_dir()`, `tempfile::tempdir()` без `tempdir_in(...)`. Субагентам передавать это правило явно.
- Ответы и документация — на русском. Идентификаторы кода — на английском.
- Платформы: **Windows x64** (`x86_64-pc-windows-msvc`) и **Linux x64**. `zam-server` для Linux собирается под `x86_64-unknown-linux-gnu` на `ubuntu-22.04`; `zam` — под `x86_64-unknown-linux-musl`. Другие платформы не поддерживаются.
- GPU — только CUDA. DirectML нигде не упоминается и не подключается.
- `server.bind` по умолчанию `0.0.0.0:7700`.
- Администратор: `[admin] login`, `password_hash = "argon2id…"`. Есть запасной вариант `ZAM_ADMIN_PASSWORD`, его значение хэшируется в памяти. В БД учётных данных администратора нет.
- Токены хранятся только как sha256. Режимы `rw` (по умолчанию) и `ro`. Префикс для отображения — 8 символов.
- Cookie WebUI: `HttpOnly`, `SameSite=Strict`, плюс `Secure`, если запрос пришёл по HTTPS через доверенный прокси. Изменяющие запросы WebUI требуют CSRF-токен.
- Ограничение частоты: вход администратора — 5 попыток в минуту на IP; неверные токены — тот же лимит на IP.
- Ошибки — RFC 9457 (`application/problem+json`).
- PRAGMA каждой БД: `journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=5000`, `foreign_keys=ON`. Версия схемы — `PRAGMA user_version`. Перед миграцией делается копия файла.
- Идентификаторы хранятся как UUIDv7, наружу отдаются строкой Crockford base32 из 26 символов.
- Логи не содержат текста заметок, секретов и токенов (токен маскируется до префикса).
- Начальный бандл WebUI ≤ 300 КБ gzip.
- Холодный старт `zam` ≤ 20 мс. В пути `zam status`/хуков нет tokio и нет инициализации `tracing`.
- Версии зависимостей поставки (§16.3): Qdrant **1.19.2**, ONNX Runtime **1.31.0** (CPU), pdfium из `bblanchon/pdfium-binaries` (закрепить тег при заполнении манифеста). Сравнение SHA-256 обязательно: при несовпадении сборка падает.
- Коммиты делаются только по согласию владельца. Перед выполнением договориться о ветке (`m0-skeleton`) и разрешении коммитить по задачам.

## Review Focus

1. **Первый запуск без пароля.** Нет ни `password_hash`, ни `ZAM_ADMIN_PASSWORD`: сервер не стартует и называет, что именно задать. Запуск с открытым или пустым админом недопустим. Тест — в задаче 3.
2. **Токен в логах.** Запрос с неверным или отозванным токеном не оставляет секрет ни в одной строке лога, только префикс. Тест — в задаче 7.
3. **Пробелы и кириллица в пути `data_dir`** (`H:\Мои данные\zam`): БД, логи и лок-файл работают. Тест — в задаче 4.
4. **Второй экземпляр на том же `data_dir`.** Он сразу завершается с понятной ошибкой и не трогает базы. Тест — в задаче 4.
5. **Отзыв токена и отключение пользователя.** Действуют на следующем же запросе: никакого кэширования результата проверки токена. Тест — в задаче 8.

### Task 3: База SQLite: открытие, писатель, читатели, миграции

**Files:**
- Create: `crates/zam-store/Cargo.toml`, `crates/zam-store/src/{lib.rs,db.rs,migrate.rs}`

**Interfaces:**
- Produces:
  - `pub struct Db` (Clone, Arc внутри). Методы:
    - `Db::open(path: &Path, migrations: &'static [Migration]) -> Result<Db, StoreError>`;
    - `async fn write<R: Send + 'static>(&self, f: impl FnOnce(&rusqlite::Transaction) -> Result<R, StoreError> + Send + 'static) -> Result<R, StoreError>` — выполняется в потоке-писателе внутри транзакции `IMMEDIATE`; при `Err` откатывается;
    - `async fn read<R: Send + 'static>(&self, f: impl FnOnce(&rusqlite::Connection) -> Result<R, StoreError> + Send + 'static) -> Result<R, StoreError>` — через `tokio::task::spawn_blocking` с соединением из пула (4 read-only соединения).
  - `pub struct Migration { pub version: u32, pub sql: &'static str }`.
  - `migrate::apply(conn, path, migrations) -> Result<u32 /*итоговая версия*/>`. Если `user_version` меньше последней версии и файл непустой, до миграции создаётся копия `<file>.bak-v<old>` через `VACUUM INTO`. Каждая миграция идёт в своей транзакции и выставляет `user_version`. Если версия в файле больше известной, возвращается `StoreError::SchemaTooNew { found, supported }`.
  - `pub enum StoreError` (thiserror): `Sqlite`, `SchemaTooNew`, `Io`, `NotFound`, `Conflict(String)`, `Closed`.
- При каждом открытии соединения применяются PRAGMA: `journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=5000`, `foreign_keys=ON`.
