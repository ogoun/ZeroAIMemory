# M1. Заметки — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal.** Пользователь и агент создают, правят, читают и ищут Markdown-заметки:
- через REST API;
- через CLI `zam`;
- через WebUI: дерево, просмотр с медиа, простой редактор, история, поиск.

Инвариант PATCH и набор XSS-векторов проходят.

**Architecture.**
- Новый крейт `zam-markdown` (comrak) — единственный парсер Markdown. Он отвечает за:
  - позиции и секции;
  - ссылки;
  - PATCH-splice;
  - HTML через ammonia и syntect.
- `zam-store` получает миграцию пользовательской БД 0002 (узлы, ревизии, чанки, FTS5, вложения) и репозитории:
  - `nodes` — узлы и ревизии;
  - `search` — поиск FTS;
  - `blobs` — блобы.

  Запись заметки — одна транзакция писателя: ревизия, узел, разбор, чанки, FTS.
- `zam-server` открывает REST-эндпоинты §12 (группы «Пространства», «Дерево», «Рендер», «Узлы», «Ревизии», «Поиск», «Вложения») с политикой доступа к пространствам.
- `zam` получает команды `tree`, `read`, `write`, `history`, `search`, `attach`.
- WebUI — дерево, документ, редактор, история, поиск.

**Tech Stack.** Всё из M0, плюс:
- Rust: `comrak` 0.x (≥ 0.56, без default-features кроме нужных), `syntect` 5 (`default-fancy`, без oniguruma), `ammonia` 4, `similar` 2, `mime_guess` 2, `lru` (кэш рендера); dev — `proptest` 1, `pulldown-cmark` 0.13.
- axum: feature `multipart`. tower-http: feature `fs` (`ServeFile` с Range).
- WebUI: `katex`, `mermaid` и `dompurify` грузятся лениво. Редактор — CodeMirror 6: `@codemirror/state`, `@codemirror/view`, `@codemirror/commands`, `@codemirror/lang-markdown`, лениво.

## Global Constraints

- **Временные файлы**, логи прогонов и тестовые данные — только внутри проекта: `.tmp/` или `target/` (в тестах — `env!("CARGO_TARGET_TMPDIR")`). Запрещены `/tmp`, `%TEMP%`, `AppData\Local\Temp`, `std::env::temp_dir()` и `tempfile::tempdir()` без `tempdir_in(...)`. Субагентам передавать это правило явно.
- **Окружение.** Перед `cargo` и `npm` выполняется `. scripts/dev-env.ps1` (PowerShell) или `. scripts/dev-env.sh`: тулчейн лежит в `.toolchain/`, диск C: заполнен.
- **Язык и стиль.** Ответы, документация и комментарии — на русском, идентификаторы — на английском. Стиль кода — как в M0: `thiserror` в библиотеках, `anyhow` только в бинарниках и xtask, ошибки HTTP — `ApiError` (RFC 9457).
- **Платформы:** Windows x64 и Linux x64. Пути в коде собираются только через `Path::join` по компонентам, без строк с `\` (урок CI M0).
- **Markdown:**
  - разбирает только `zam-markdown`;
  - обратная сериализация AST (`format_commonmark`) запрещена;
  - PATCH — только байтовый splice исходника;
  - инвариант: байты вне изменённого диапазона совпадают с исходными.
- **Секция** — от заголовка уровня N (H1–H3) до следующего заголовка уровня ≤ N на верхнем уровне документа. Заголовки в списках и цитатах секций не образуют. Setext учитывается, H4–H6 остаются внутри секции. Путь секции — заголовки через ` > ` (например `Установка > Linux`).
- **Безопасность рендера:**
  - comrak с `render.unsafe = false`;
  - после comrak HTML проходит `ammonia` с явным списком тегов и атрибутов;
  - на клиенте DOMPurify — только для SVG Mermaid.
  - CSP страницы не меняется: без `unsafe-inline` для скриптов.
- **Human:**
  - по токену недоступен ни в каком виде: ни дерево, ни узлы, ни поиск, ни вложения;
  - в FTS индексируется: в него ищет WebUI администратора.
- **Rules:** токен пишет туда только при настройке `rules.agent_write = true` (таблица `settings` в `system.db`, по умолчанию `false`), читать может всегда. Токен `ro` не пишет никуда.
- **Ревизии** только дописываются. Удаление мягкое (`deleted_at`). В аудит пишутся удаление, восстановление и откат.
- **Логи** не содержат текста заметок, секретов и токенов.
- **Пределы:**
  - тело `POST /render` — 1 МБ;
  - заметка — 5 МБ (`limits.note_max_bytes`);
  - вложение — 200 МБ (`limits.blob_max_bytes`).
- **Время** — UTC, через `zam_store::time::fmt_ts`. Идентификаторы — `zam_core::Id`.
- **Бандл WebUI:** начальный ≤ 300 КБ gzip, ленивые чанки не считаются (`size-limit` проверяет только entry-чанк).
- **Холодный старт** `zam status` ≤ 20 мс: новые команды не должны тянуть tokio или `tracing` в общий путь `main`.
- **Коммит** после каждой задачи. Ветка `m1-notes`. Сообщения — Conventional Commits на русском, с trailer `Co-Authored-By` по реальной модели.

## Review Focus

1. **CRLF и BOM в заметке.** Файл с `\r\n` и BOM: PATCH секции меняет только её байты, переводы строк вне секции остаются `\r\n`. Тест — в задаче 2.
2. **Кириллица и пробелы в пути и имени** (`knowledge:Инструменты/Bash скрипты`): создание, чтение по пути, поиск, CLI. Нормализация Unicode не применяется: путь хранится как прислан, но в NFC-проверке не нуждается. Тест — в задачах 4 и 10.
3. **Поисковый запрос с синтаксисом FTS5** (`"`, `*`, `AND`, `-`, `:`, `(`, `NEAR`): не 500, а обычный поиск по словам. Тест — в задаче 7.
4. **Загруженный HTML или SVG** открывается по прямой ссылке на блоб, но не исполняет скрипты в origin сервиса: `Content-Disposition: attachment` или CSP `sandbox`. Тест — в задаче 9.
5. **Две машины правят одну заметку.** `PUT` со старым `If-Match` → 409 с текущей ревизией и диффом. `PATCH` чужой секции с тем же `base_rev` проходит, своей уже изменённой — 409. Тест — в задаче 8.

### Task 2: `zam-markdown` — PATCH-операции

**Files:**
- Create: `crates/zam-markdown/src/patch.rs`, `crates/zam-markdown/tests/patch.rs`, цель fuzz `patch`.

**Interfaces:**
- Produces:
  ```rust
  #[derive(Deserialize, Serialize, Clone, Debug)] #[serde(tag = "op", rename_all = "snake_case")]
  pub enum PatchOp {
      ReplaceSection { section: String, content: String },       // заменяет тело (без строки заголовка)
      AppendToSection { section: String, content: String },      // в конец тела секции (перед подсекциями? — нет: в конец всего range)
      InsertAfterHeading { section: String, content: String },   // сразу после строк заголовка
      Append { content: String },                                // в конец документа
      Prepend { content: String },                               // после frontmatter
  }
  pub struct Applied { pub text: String, pub changed: Range<usize> /*в новом тексте*/, pub touched_section: Option<String> }
  #[derive(thiserror::Error, Debug)] pub enum PatchError { #[error("секция не найдена: {0}")] SectionNotFound(String),
      #[error("путь секции неоднозначен: {0}")] Ambiguous(String) }
  pub fn apply_patch(src: &str, op: &PatchOp) -> Result<Applied, PatchError>;
  /// Байты секции `path` в документе (для проверки «секция не менялась после base_rev»).
  pub fn section_bytes<'a>(src: &'a str, path: &str) -> Option<&'a str>;
  ```
- **Переводы строк:** вставляемый `content` приводится к переводам строк документа (CRLF, если в документе первым встречается `\r\n`). Если перед вставкой нет перевода строки, он добавляется. Конец `content` дополняется переводом строки, если его нет.
- **`AppendToSection`** дописывает в конец `range` секции, включая её подсекции: это конец всего диапазона `Section::range`. Следующий заголовок не затрагивается.

- [ ] **Step 1: Unit-тесты** каждой операции на одном документе с H1/H2/H3 и CRLF. Ожидаемый текст задаётся литералом.
- [ ] **Step 2: Property-инвариант** (proptest, 1000 случаев): для случайного документа, случайной существующей секции и случайного `content`:
  - `new[..changed.start] == old[..start]`;
  - `new[changed.end..] == old[end..]`, где `start..end` — заменённый диапазон в старом тексте;
  - повторный `parse(new)` находит секцию по тому же пути.
- [ ] **Step 3: Ошибки.** Несуществующий путь → `SectionNotFound`. Два одинаковых пути (`## A` дважды под одним H1) → `Ambiguous`.
- [ ] **Step 4: Реализация, проверки, коммит** `feat(markdown): PATCH секций байтовым splice`.

  pub async fn attach(db: &Db, node: Id, sha256: &str, size: u64, filename: &str, mime: &str) -> Result<String /*link*/, StoreError>;
      // blobs: INSERT или refcount+1 (только при новой паре node+sha+filename); attachments: строка; link = "_attachments/<sha[0..16]>/<filename>"
  pub async fn resolve_attachment(db: &Db, sha16: &str, filename: &str) -> Result<Option<(String, String /*mime*/)>, StoreError>;
  pub async fn blob_meta(db: &Db, sha256: &str, filename: &str) -> Result<Option<(String /*mime*/, u64)>, StoreError>;
  ```
  `DataDir` получает `blobs_dir()`. Имя файла проверяется по правилам сегмента `NodePath`.
- **`POST /blobs`** (multipart: поле `node` — id заметки, поле `file` с именем файла) → 201 `{sha256, link, mime, size}`:
  - MIME — `mime_guess` по имени, иначе тип из части, иначе `application/octet-stream`;
  - запись — по правилам записи в пространство узла;
  - лимит — `limits.blob_max_bytes`, поток не держится в памяти целиком;
  - превышение → 413.
- **`GET /blobs/{sha256}/{filename}`** (`?user=` — только для администратора):
  - отдаёт файл через `tower_http::services::ServeFile`, поэтому работают `Range` и `If-None-Match`;
  - `Content-Type` — из таблицы;
  - `X-Content-Type-Options: nosniff`;
  - `Content-Security-Policy: sandbox; default-src 'none'; img-src 'self'; media-src 'self'; style-src 'unsafe-inline'`;
  - `Content-Disposition: inline` для `image/*` (кроме `image/svg+xml`), `video/*`, `audio/*`, `application/pdf`, для остальных — `attachment; filename*=UTF-8''…`;
  - вложение узла в Human по токену → 404.
- **`POST /search`** — тело §9.1, в M1 учитываются:
  - `query`;
  - `scope`: `solution`, `include_knowledge` (по умолчанию true), `include_rules` (true), `all_solutions`, `path_prefix`, плюс `spaces: [SpaceRef]` и `include_human` (только администратор, по умолчанию false);
  - `mode`: `brief` | `chunks` | `notes`;
  - `top_k`;
  - `budget_tokens` — приблизительно: символы / 4 **[решение исполнителя до токенизатора M2]**;
  - `format`: `json` | `md`.
- **Ответ поиска** `{items:[{node_id, space, path, heading_path, rev, chunk_ids, score, updated_at, kind:"note", snippet, text?}], degraded:true, degraded_reason:"vector index not available (M1)", pending_count:0, timings:{fts_ms}}`:
  - `text` — только в `chunks`;
  - `notes` — по одному элементу на узел, с `l0` вместо `snippet`;
  - `md` — компактный список `- [space/path › heading] (id@rev) snippet`.
- **Область по умолчанию:**
  - задано `scope.solution` → это решение плюс Knowledge и Rules по флагам;
  - иначе — Knowledge, Rules и (при `all_solutions`) все решения;
  - заголовок `X-Zam-Solution` подставляется в `scope.solution`, если оно не задано.

  ```
