# M5.6. Карта кода — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal.** Встроенная карта кода решения: клиент `zam` разбирает рабочую копию tree-sitter'ом и
отправляет на сервер только метаданные символов; сервер хранит карту в базе владельца решения,
ранжирует её персонализированным PageRank и выдаёт в бюджете токенов (REST, MCP `memory_code`,
`zam code …`, страница WebUI «Код»); знание памяти привязывается к `путь#Тип::метод` и устаревает
только при изменении тела **этого** символа.

**Architecture.**
- **Новый крейт `zam-code`** — два слоя. Без фич (по умолчанию): типы протокола (`Lang`,
  `SymbolKind`, `Symbol`, `RefAgg`, `FileUpload`, …), нормализация имён для FTS, разбор ссылки
  `путь#qual`, ранжирование (граф файлов, PageRank) и упаковка карты в бюджет — чистые функции, их
  берут `zam-store`, `zam-server` и `zam-cli`. Фича `parse` — tree-sitter 0.27 и 7 грамматик
  (Rust, TS/TSX, JS/JSX, Python, Go, Java, C#), экстрактор с пределами, эвристиками пропуска и
  отсечкой по времени; её включает только `zam-cli`. Сервер C-код грамматик не тянет.
- **Клиент строит, сервер хранит.** `zam code sync`: отпечатки (git oid / размер+mtime → blake3) →
  `POST /code/sync` (манифест) → разбор только `need` → `PUT /code/files` пачками. Тела файлов не
  уходят никогда; сигнатуры — с выключателем `code.send_signatures`, сервер маскирует секреты.
- **Хранилище** — пользовательская миграция `0023_code_map.sql` (база владельца решения): снимок,
  файлы, символы, FTS символов, агрегированные ссылки, рёбра файлов; `file_refs.symbol` и
  `symbol_hash`. Ранги пересчитываются лениво при первом запросе карты после загрузки.
- **Связь с памятью — одна функция правила устарелости** (`zam_store::file_refs::files_changed`
  с символами) для трёх входов: `POST /files/changed` (хуки), `POST /files/verified`,
  `PUT /code/files`.
- **Карта не вытесняет память:** в дайджесте — одна строка-указатель, в пакете субагенту — раздел
  `### Код` ≤ 150 токенов, символы не входят в `POST /search` и подсказки; тип подсказок `code_map`
  гасит всё автоматическое.

**Tech Stack.** Новые зависимости (только `zam-code`, фича `parse`; версии закрепляются `=x.y.z`,
все MIT, аудит — исследование §3.1, повторить в задаче 1): `tree-sitter` =0.27.1,
`tree-sitter-rust` =0.24.2, `tree-sitter-typescript` =0.23.2, `tree-sitter-javascript` =0.25.0,
`tree-sitter-python` =0.25.0, `tree-sitter-go` =0.25.0, `tree-sitter-java` =0.23.5,
`tree-sitter-c-sharp` =0.23.5, `streaming-iterator` (версия из графа `tree-sitter` 0.27.1,
закрепить `=`). Уже в workspace: `blake3`, `globset`, `serde`, `serde_json`, `thiserror`,
`proptest`. WebUI — Mermaid + ELK (с M3), без новых пакетов.

**Spec:** `docs/specs/2026-11-03-m5.6-code-map.md` (далее — «спецификация»; главный документ),
исследование `docs/research/2026-11-03-m5.6-code-map.md`, основа — ТЗ
`docs/specs/2026-10-17-zeroaimemory-tz.md` v1.21 (§6.3, §7.10, §10.3, §10.7, §11.6, §12–§15).

## Review Focus

1. **Перевод строк и BOM между машинами.** Рабочая копия Windows (`autocrlf`, CRLF) и Linux (LF)
   одного коммита; файл с BOM. Ожидание: `body_hash`, `sig`, `line`/`end_line` совпадают, ссылки
   на символы не устаревают при синхронизации с другой машины; меняется только `hash` файла (он
   по сырому содержимому — файл перезагружается, символьные ссылки остаются `ok`). Тесты — задача
   1 `body_hash_same_for_crlf_lf_and_bom`, задача 3 `put_files_crlf_twin_keeps_symbol_refs_ok`.
2. **Сдвиг суффикса перегрузки.** Ссылка на `foo#2`; выше в файле вставлена ещё одна `foo`.
   Ожидание: ссылка не остаётся молча `ok` на чужом теле — `stale`/`symbol_changed` (новый `foo#2`
   с другим `body_hash`); вставка ниже — ссылка `ok`. Тест — задача 3
   `overload_insert_before_marks_changed_after_keeps_ok`.
3. **Удалённый и переименованный файл.** `git rm`, `git mv`, удаление правкой агента (очередь с
   `MISSING_HASH`). Ожидание: файл исчезает из карты при следующей синхронизации; символьные
   ссылки на него — `stale`/`symbol_removed`, файловые — `source_changed`; символы нового пути
   загружены. Тесты — задача 3 `missing_hash_marks_symbol_refs_removed`, задача 5
   `code_sync_rename_removes_old_adds_new`.
4. **Две синхронизации одновременно.** Фоновая из хука и ручная `zam code sync`; две машины на
   одном решении. Ожидание: второй процесс на той же машине не стартует (замок), брошенный замок
   старше 30 мин снимается; на сервере пофайлово «последний побеждает», без дублей строк и
   осиротевших символов. Тесты — задача 3 `put_files_same_path_twice_last_wins_no_orphans`,
   задача 5 `code_sync_lock_second_skips_stale_lock_taken`.
5. **Регистр и разделители путей.** Windows: `Src\Store.RS` против `src/store.rs` в git; повтор
   пути в манифесте; путь вне корня. Ожидание: клиент шлёт путь с регистром из ФС и `/`
   (`refs::real_case`, как `file_refs`); сервер нормализует по правилам `file_refs` и на повтор
   пути в манифесте отвечает 422 `manifest[i]: повтор пути`; путь вне корня — 422. Тесты — задача 4
   `code_sync_manifest_duplicate_and_outside_root_422`, задача 5
   `code_fingerprints_real_case_and_forward_slash`.

### Task 1: `zam-code` — протокол и экстрактор

**Files:** `crates/zam-code/**` (кроме `rank.rs`, `pack.rs` — задача 2), `Cargo.toml` (член workspace, `exclude += crates/zam-code/fuzz`,

**Interfaces — Produces:**
```rust
// proto.rs (без фич; serde: snake_case/lowercase как в спецификации)
pub enum Lang { Rust, TypeScript, Tsx, JavaScript, Python, Go, Java, CSharp }
//   as_str: "rust","typescript","tsx","javascript","python","go","java","csharp"; parse(&str)
pub fn lang_of(path: &str) -> Option<Lang>;   // расширения — таблица §3 спецификации, без учёта регистра
pub enum SymbolKind { Function, Method, Class, Struct, Enum, Interface, Trait, Type, Const, Module, Macro }
pub enum RefKind { Call, Type, Import, Impl, Other }
pub enum ParseState { Ok, Partial, Skipped }
pub enum SkipReason { TooLarge, Minified, Binary, Timeout, ParserCrash, Limit, Lang }
pub struct Symbol { pub name: String, pub qual: String, pub kind: SymbolKind, pub line: u32,
                    pub end_line: u32, pub sig: Option<String>, pub body_hash: String,
                    pub exported: Option<bool> }
pub struct RefAgg { pub name: String, pub kind: RefKind, pub count: u32, pub first_line: u32 }
pub struct FileUpload { pub path: String, pub lang: Lang, pub hash: String, pub git_oid: Option<String>,

pub struct ManifestItem { pub path: String, pub hash: String }
pub struct SymbolHash { pub qual: String, pub body_hash: String }
pub const SIG_MAX_CHARS: usize = 160; pub const NAME_MAX_CHARS: usize = 256;
pub const QUAL_MAX_CHARS: usize = 512; pub const UPLOAD_FILES_MAX: usize = 500;
pub const MISSING_HASH: &str = "0000…0000";   // 64 нуля — равен zam-cli refs::MISSING_HASH (тест)
pub fn sig_line(def_text: &str) -> Option<String>;  // первая непустая строка, trim_end, ≤160 с «…»
pub fn body_hash(def_text: &str) -> String;         // строки trim, пустые убраны, '\n' → blake3, 16 hex
// names.rs (без фич)
pub fn split_ident(name: &str) -> Vec<String>;      // getUserById → [get,user,by,id]; HTTPServer → [http,server]
pub fn fts_terms(name: &str, qual: &str) -> String; // слова name и частей qual через пробел, нижний регистр
pub fn split_ref(raw: &str) -> (&str, Option<&str>);
// последний '#': префикс с lang_of(..).is_some() и суффикс 1..=512 символов без '/' и управляющих
// → (путь, Some(qual)); иначе (raw, None) — путь с '#' в имени остаётся путём
// extract/ (фича `parse`)
pub struct Limits { pub max_file_bytes: u64, pub parse_timeout: Duration,
                    pub max_symbols: usize /*5000*/, pub max_refs: usize /*20000*/ }

                       pub symbols: Vec<Symbol>, pub refs: Vec<RefAgg> }
pub fn sniff(bytes: &[u8]) -> Option<SkipReason>;   // NUL в первых 8 КиБ → Binary; строка > 10 000
                                                    // символов или средняя длина > 300 → Minified
pub fn extract(lang: Lang, src: &[u8], lim: &Limits) -> Extracted;  // никогда не паникует наружу
pub fn symbol_hashes(lang: Lang, src: &[u8], lim: &Limits) -> Option<Vec<SymbolHash>>; // для хуков
```
- **Порядок в `extract`:** размер > `max_file_bytes` → `TooLarge`; `sniff`; невалидный UTF-8 —
  разбор по байтам (tree-sitter принимает), имена через `from_utf8_lossy`; BOM срезается до
  разбора (строки считаются без него); отсечка — `ParseOptions` с обратным вызовом прогресса
  (0.27; сверить по docs.rs 0.27.1) и тот же дедлайн у `QueryCursor` (`matches_with_options`) →
  `Timeout`; символов > `max_symbols` или ссылок > `max_refs` — первые по порядку,
  `Partial` + `Limit`; `catch_unwind(AssertUnwindSafe(..))` вокруг всего — паника →
  `Skipped`/`ParserCrash`.
- **Запросы:** встроенный `TAGS_QUERY` грамматики + `queries/<язык>.scm` (C# — только свой);
  вид — по виду узла `@definition.*` (`struct_item` → `struct`, `enum_item` → `enum`,
  `type_item` → `type`, `trait_item` → `trait`, …); дополнения: Rust — `const_item`/`static_item`
  (`const`), вызов `scoped_identifier` (`Store::open()`), `type_identifier` и
  `scoped_type_identifier` как `reference.type`, имена в `use_declaration` как `import`; TS/JS —
  `type_identifier` в аннотациях (`type`), `import_specifier` (`import`); C# —
  `class|struct|interface|enum|record_declaration`, `method_declaration`,
  `constructor_declaration`, `delegate_declaration` (`type`), `namespace_declaration` и
  file-scoped (`module`), вызовы `invocation_expression`, `object_creation_expression`, `base_list`
  (`impl`), `using_directive` (`import`), типы параметров и переменных (`type`). Ссылка, чей узел —
  имя определения, отбрасывается. Обход контейнеров для `qual` — `Node::parent()` (без рекурсии);
  контейнеры — таблица §3 спецификации; у C# — классы/структуры/интерфейсы/записи, без
  `namespace` **[решение составителя плана]** (как пакеты Java).
- **`exported`:** Rust — есть `visibility_modifier`; TS/JS — предок `export_statement`; Go —
  заглавная первая буква; Java/C# — модификатор `public`; Python — `null`.
- **Одноимённые** с равным `qual` — суффикс `#2`, `#3` по порядку в файле.
- **Ссылки** агрегируются `(name, kind)` → `count`, `first_line`; ссылки, попавшие внутрь
  определения символа, всё равно учитываются для файла (граф файлов), но к символу не

## Решения составителя плана

Спецификация их не определяет или определяет неоднозначно; каждое записать в журнал этапа и в ТЗ
при переносе.

1. Номер миграции — `0023` (последняя — `0022_reports.sql`), без пересборки таблиц: `ALTER TABLE`
   и пересоздание индекса `file_refs_owner` по выражению (запасной путь — `symbol_key`).
2. `split_ref`: символ отделяется по последнему `#`, только если префикс — путь кода
   (`lang_of`) и суффикс — допустимый `qual`; иначе строка — путь (имена с `#` не ломаются).
   Правило одно для frontmatter, `data.refs.files`, `refs.files[i].path`, `--ref`.
3. Ссылка с символом при `ok` по символам принимает новый `hash` файла.
4. `MISSING_HASH` (удалённый файл) — символьные ссылки `symbol_removed`.
5. Хук кладёт в очередь хэши **всех** символов файла (≤ 5000), а не только из ссылок: кэш
   ссылок может отставать — иначе ложный `symbol_removed`.
6. Хэш файла в манифесте — всегда blake3 содержимого; git oid и размер+mtime — только отпечаток,
   по которому клиент берёт хэш из `code-state.json` без чтения файла.
7. Малый `cache/code-sync.json` (время последней успешной синхронизации, `HEAD`) отдельно от
   большого `code-state.json`: хук читает только его (бюджет 10 мс); `HEAD` — из файлов `.git`
   без процесса `git`.
8. Журнал падений — перезапись малого файла без fsync перед каждым файлом (обрыв процесса её
   сохраняет); пропуск `parser_crash` держится, пока хэш файла тот же.
9. Разбор в одном потоке.
10. C#: контейнеры `qual` — типы, без `namespace`; свойства в первой очереди не извлекаются.
11. Ранг символа без входящих ссылок — по виду и `exported`; при `focus` — сохранённая доля ×
    ранг файла с персонализацией по сохранённым рёбрам.
12. Счётчик токенов карты — `zam_store::count_tokens` (как все `tokens` сервера), а не всегда
    `ApproxCounter`.
13. Маршруты карты — в `service_routes` (не `memory_routes`); `code.enabled = false` — 404.
14. Сигнатура маскируется при записи и хранится маскированной.
15. Строка знания о файле: один символ — «о `Sym` в <путь>», смесь — «о файле <путь>: `Sym`: …»,
    символьные первыми.
16. WebUI: «Код» — элемент `Journal` (`j/code`), карточка в адресе — по `путь#qual`.
17. Имитация обрыва процесса в приёмке — тестовый крючок только в debug-сборке.
18. Блок v5: перенос трёх фраз в протокол (см. задачу 7) с запасным порядком сокращений.
19. Порядок задач против §16 спецификации: ранжирование (чистые функции) — задача 2, хранилище —
    задача 3 (оно сохраняет ранги в типах `zam_code::{RankFile, Ranked}`).
