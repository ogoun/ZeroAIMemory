# M5.7. Идеи — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal.** Журнал «Идеи» (`idea`, ссылка `w:`) в решении и Knowledge. Человек записывает замыслы
в WebUI, агент — по диктовке или свои (с пометкой «от агента»). Агент предлагает начать идею:
раздел дайджеста `### Идеи` (до 3) и подсказка по смыслу `/recall prompt`, каждая идея — один раз
за сессию. Предложение — вопрос с вариантами «начать / отложить / отказаться». Ответ человека
переводит идею по статусам, а «начать» одной транзакцией создаёт `task` с ребром `derived_from`.

**Architecture.**
- **Новый вид записи, без новой подсистемы.** `EntryKind::Idea` в `entries`. Миграция
  `0024_ideas.sql` пересобирает `entries` по образцу 0015/0022 и пересоздаёт триггер неизменности
  отчёта. Модуль `zam_store::ideas` устроен как `tasks.rs`/`questions.rs`: `IdeaData`
  (клиентские и серверные поля), проверка переходов, транзакции `propose_idea`, `decide_idea`,
  `adopt_idea` и общий шаг `apply_decision_tx`. Его вызывают и `decide_idea`, и
  `answer_question` для вопроса-предложения (`QuestionData.idea`). Итог — одна транзакция писателя
  на любой путь решения.
- **Связь с задачей** — ребро `derived_from` задача → идея. Правка статуса задачи в `update_entry`
  вызывает `ideas::on_task_status_tx` в той же транзакции: `done` → идея `done`, переоткрытие →
  `accepted`.
- **Проактивность — в существующем `/recall`.** Отбор кандидатов —
  `zam_store::ideas::proactive_ideas`, общий для дайджеста и `prompt`: только `origin: human`;
  `new` или `deferred` с наступившим `horizon`; без `session_seen`. Раздел дайджеста стоит после
  `### Открытые вопросы`, подсказка — из того же внутреннего поиска `prompt` с `kinds += idea`.
  Выключатель — `[ideas] proactive` сервера и `ideas.proactive` пользователя (`user_settings`).
- **Пути клиента** — по шаблону вопросов: REST `POST /entries/{id}/{propose,decide,adopt}`,
  MCP `memory_update_entry action=propose|decide` (инструментов по-прежнему 11), CLI `zam idea …`,
  страница WebUI «Идеи». Блок инструкции v6 — одна строка, детали — протокол `zam guide`.

**Tech Stack.** Без новых зависимостей: Rust (rusqlite, axum, serde, jiff, thiserror, proptest —
уже в workspace), WebUI Svelte 5 (без новых пакетов).

**Spec:** `docs/specs/2026-11-04-m5.7-ideas.md` (далее — «спецификация»; главный документ), основа —
предложение и ответы владельца `docs/research/2026-11-02-ideas-journal-proposal.md` §6, ТЗ
`docs/specs/2026-10-17-zeroaimemory-tz.md` v1.22 (§7.5, §7.8, §7.9, §10, §11.6, §12–§15). Журнал
этапа — `docs/plans/2026-11-04-m5.7-ideas-log.md`.

## Review Focus

1. **Атомарность «начать» на всех трёх путях.** `decide accept` (WebUI, CLI, MCP), ответ `accept`
   на вопрос-предложение и `decide` по идее с открытым вопросом. Ожидание: при сбое вставки задачи
   или ребра (тестовый триггер `RAISE(ABORT)`) не меняется ничего — статус и ревизия идеи, вопрос,
   решение-`decision`, рёбра. Повтор после успеха — 409 `already-decided` с тем же `task_id`, вторая
   задача не создаётся. Тесты — задача 1 `accept_rolls_back_when_task_insert_fails`,
   `accept_twice_conflict_same_task`, `answer_accept_on_proposal_is_one_tx`.
2. **Пересборка `entries` не теряет защиту отчёта.** `DROP TABLE entries` в 0024 уносит триггер
   `entries_report_immutable`. Ожидание: после миграции правка отчёта — `report-immutable`, CHECK
   отчёта на месте, `foreign_key_check` пуст, все строки и `idempotency_key` сохранены. Тесты —
   задача 1 `migrate_0024_keeps_report_triggers_and_rows` в `tests/migrate_rebuild.rs`.
3. **Один показ за сессию между дайджестом и `prompt`.** `session_start` → `prompt` → повторный
   `session_start` (`source=compact`) одной сессии. Ожидание: идея показана ровно один раз; новая
   сессия — снова. При `record: false` и истёкшем сроке учёта (`recall timeout`) показ не
   отмечается, и идея придёт ещё раз — это допустимо и задокументировано. Тесты — задача 3
   `digest_ideas_once_per_session_across_compact`, `prompt_skips_idea_seen_in_digest`.
4. **Кто решает.** Токен `by: agent` на `accept`, `defer`, `reopen`, на `decline` идеи человека и на
   ответ вопроса-предложения; токен на `adopt`; токен на правку тела идеи человека. Ожидание: 403
   с нужной проблемой, без побочных записей (ни ревизии, ни аудита изменения). `decline` своей идеи
   `by: agent` — 200. Тесты — задача 2 `token_by_agent_cannot_decide_human_idea`,
   `token_cannot_adopt_or_rewrite_human_idea`, `agent_declines_own_idea`.
5. **Идея не вытесняет память и не протекает.** Идеи «от агента», `declined`, `proposed`,
   `deferred` до `horizon` и общие Knowledge ниже порога не появляются ни в дайджесте, ни в
   подсказке. При выключенном `ideas.proactive` дайджест побайтно равен дайджесту без идей; набор
   insight-подсказок `prompt` с идеями и без них один и тот же. Тесты — задача 3
   `proactive_off_digest_byte_equal`, `prompt_insight_hints_unchanged_with_ideas`,
   `never_proposed_kinds_matrix`.

## Решения составителя плана

Каждое записать в журнал этапа и перенести в ТЗ (задача 6). Те же решения помечены
«[решение составителя]» в спецификации.

1. Вид `idea` — запись `entries`, буква ссылки `w:` (`d:` занята документом вложения).
2. Миграция `0024_ideas.sql`, `rebuild: true`; триггер `entries_report_immutable`
   пересоздаётся.
3. `data.origin` у токена обязателен, по образцу обязательного `by` (§7.9, I-2).
4. Статус идеи — только операциями `propose|decide|adopt`; `PATCH status` — 422.
5. Варианты вопроса-предложения фиксирует сервер (`accept|defer|decline`), проверки дублей нет;
   повторный `propose` возвращает тот же открытый вопрос.
6. Один шаг перехода `apply_decision_tx` для `decide` и ответа на вопрос-предложение; прямое
   решение отвечает открытый вопрос вариантом. Решение-`decision` создаётся, как у любого ответа.
7. Идея «от агента»: ни `propose`, ни `accept` до «принять как свою»; `decline` своей — `by: agent`.
8. Токен не правит содержимое идеи человека (403 `idea-human-owned`), `append` — можно.
9. `accept` идеи Knowledge может создать задачу в решении той же базы (`space`); другая база —
   422.
10. Задача `dropped` идею не меняет; `done` → идея `done`, переоткрытие → `accepted`.
11. `deferred` после `horizon` статус не меняет (фоновых заданий нет), кандидатом становится сама.
12. Раздел `### Идеи` — после `### Открытые вопросы`, со строкой-указанием; отметка
    `session_seen` (как «Ответы человека»); нет в `recovery` и `brief`.
13. «Явная связь» общей идеи — балл подсказки ≥ `ideas.knowledge_min_score` (0,75).
14. Выключатель двухуровневый: `[ideas] proactive` && `ideas.proactive` пользователя.
15. Блок v6 в M5.7, M6 делает v7; в блоке одна строка идей, правило «без ответа не начинай» —
    в разделе дайджеста и строке подсказки; перенос «(409 — перечитай)», «перед работой», «в
    чате» в протокол.
16. CLI `propose` сверх списка владельца; `reopen` и «принять как свою» — только WebUI.
17. Фильтры ленты `origin` и `priority` — новые поля `EntryFilter` (по `json_extract`).
18. Статусы поиска по умолчанию для `idea` — `new, proposed, deferred, accepted`; у сессии WebUI
    `idea` входит в умолчания `kinds`, у токена — нет.
