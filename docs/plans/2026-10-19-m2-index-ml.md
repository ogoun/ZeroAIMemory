# M2. Индекс и ML — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal.** Поиск становится гибридным:
- Markdown режется на чанки по §8.2;
- bge-m3 (ONNX, CPU int8 или CUDA fp16) считает dense- и sparse-векторы;
- векторы хранятся в `embeddings` и в нативном Qdrant, которым управляет `zam-server`;
- `/search` объединяет Qdrant и FTS через RRF, при сбое деградирует и сообщает состояние в `/index/status`.

Каждый релиз собирает CPU- и GPU-комплекты для Windows x64 и Linux x64. Первый прогон eval и ADR по Qdrant Edge закрывают этап.

**Architecture.** Новые крейты:
- `zam-ml` — ORT через `load-dynamic`, токенизатор, эмбеддер, реранкер, выбор устройства;
- `zam-index` — супервизор Qdrant, `VectorIndex` с адаптером `QdrantIndex`, воркер индексации;
- `zam-search` — гибрид, поправки, упаковка ответа.

`zam-markdown` получает чанкер и L0/L1, `zam-store` — таблицы `embeddings` и `index_jobs` (outbox). Запись остаётся синхронной до FTS, векторизация идёт асинхронно через очередь.

## Global Constraints

- **Временные файлы**, логи прогонов, тестовые данные и модели — только внутри проекта: `.tmp/` или `target/` (в тестах `env!("CARGO_TARGET_TMPDIR")`, модели — `target/models/`, бинарники — `target/deps/<платформа>/`). Запрещены `/tmp`, `%TEMP%`, `AppData\Local\Temp`, `std::env::temp_dir()`, `os.tmpdir()`. Субагентам передавать явно.
- **Окружение.** Перед `cargo` и `npm` выполняется `. scripts/dev-env.ps1` (PowerShell) или `. scripts/dev-env.sh`: тулчейн лежит в `.toolchain/`, диск C: заполнен. Данные проекта на HDD, задержки fsync учитываются.
- **Стиль M0–M1:** русские комментарии, документы и тексты UI; английские идентификаторы; `thiserror` в библиотеках, `anyhow` в бинарниках; RFC 9457; пути через `Path::join` по компонентам.
- **Платформы:** Windows x64 и Linux x64. GPU — только CUDA (DirectML нигде не упоминается). Без Docker.
- **Самодостаточность.** Модели исполняются в процессе. Без моделей или без библиотеки ORT сервер стартует в режиме FTS-only и явно это сообщает (`degraded`, `/index/status`, лог).
- **Неизменные ограничения:**
  - Human никогда не попадает в Qdrant;
  - узлы с `index: false` (`index_state = 'excluded'`) не векторизуются;
  - vault — этап M3.
- **Qdrant.** Только `127.0.0.1`. API-ключ случайный при каждом старте и передаётся только через `QDRANT__SERVICE__API_KEY`. Запись идёт с `wait=true`. Задание закрывается только после подтверждённого upsert. id точки детерминирован.
- **Источник истины — SQLite.** Qdrant пересобирается из `embeddings` без инференса.
- **Версии с нестабильным API** закрепляются через `=`: `ort`, `tokenizers`, `qdrant-client`, `process-wrap`, `qdrant-edge`.
- **Модели** закрепляются ревизией (commit HF) и sha256 в `deploy/models.toml`. При несовпадении загрузка падает.
- **Реранкер:**
  - CPU — `jinaai/jina-reranker-v2-base-multilingual` (CC-BY-NC-4.0, решение владельца): в комплект `zam-models` не входит, скачивается только с флагом `--accept-nc-license`;
  - GPU — `onnx-community/bge-reranker-v2-m3-ONNX` (Apache-2.0);
  - по умолчанию `rerank=off`.
- **GPU-комплект** содержит ORT с CUDA EP, но не содержит библиотек NVIDIA. Их ставит `zam-server cuda fetch` по `deploy/cuda.toml` (sha256) или отдельный архив `zam-cuda-<ver>-<os>-x64` (решение владельца). Без GPU и без CUDA GPU-комплект работает на CPU.
- **Логи** не содержат текста заметок и чанков, секретов, токенов и ключа Qdrant.
- **Коммиты** после каждой задачи, ветка `m2-index`, Conventional Commits на русском, trailer `Co-Authored-By` по реальной модели.

## Review Focus

1. **Qdrant недоступен или упал во время работы.** Запись и FTS продолжают работать, поиск отвечает `degraded: true` с причиной, задания копятся. После возврата Qdrant очередь догоняет сама. Тест — в задаче 9.
2. **Нет моделей или ORT** (свежая установка без `models fetch`). Сервер стартует, поиск — FTS-only с `degraded_reason`, `/index/status` пишет «модели не загружены» и подсказывает команду. Тест — в задаче 3.
3. **Смена модели или устройства** (CPU int8 ↔ GPU fp16). Если `model_id` в коллекции не совпадает с текущим, векторный канал выключается и сообщает об этом до `reindex`. Векторы разных моделей не смешиваются. Тест — в задаче 7.
4. **Убит `zam-server`.** Процесс Qdrant завершается вместе с ним на Windows (Job Object) и на Linux (PDEATHSIG). При следующем старте осиротевший процесс находится по pid-файлу и завершается. Тест — в задаче 6 (CI, обе ОС).
5. **Длинные и неудобные чанки:** заметка из одного блока кода на 5000 строк, таблица на 2000 строк, текст без заголовков и без точек, смесь кириллицы и кода. Чанкер не рвёт блоки посередине строки, каждый чанк ≤ 800 токенов, заголовок блока повторяется. Тест — в задаче 2.

  pub struct BgeTokenCounter(Arc<Tokenizer>); impl zam_markdown::TokenCounter for BgeTokenCounter { … }

- **Решения:**
  - ORT загружается только через `init_from` с путём рядом с бинарником (`ml.ort_dylib`, по умолчанию `<exe_dir>/onnxruntime.{dll,so}`). `ORT_DYLIB_PATH` не используется.
  - CUDA: `preload_dylibs` из `<exe_dir>/cuda/` (туда кладёт `cuda fetch`), затем CUDA EP с `error_on_failure()`. При ошибке сессия пересобирается на CPU, причина пишется в `DeviceReport.reason`.
  - Веса двух сессий общие (`PrepackedWeights`). В отчёте задачи — замер RSS после загрузки bge-m3 int8.
  - Батч `embed_passages`: сортировка по длине, ≤ 8192 токенов на батч, padding до кратного 8.
  - Sparse: `relu(h·w + b)`, max по id, веса < 1e-4 отбрасываются. `sparse_linear.pt` читается как zip (fp16 `data/0`, `data/1`) без pickle.
  - `Pooling::Mean` — для MiniLM.
  - `token_type_ids` подаётся, если он есть в `session.inputs()`.
