- **§3.1 реплики.** `zam_search::recall::subject_terms` = `error_terms` → `prepared_terms`
  (`Stems`: без служебных слов, `norm_word`, без повторов) → без `PROMPT_REPLY_WORDS` (65 слов
  спецификации дословно). Реплика сравнивается с нормализованным словом целиком (множество
  нормализованных слов строится один раз: `вперёд` и `вперед` — одно слово). Пустой
  `subject_terms` — только строки словаря (`term_cands`), без поиска, задач и идей; сессия
  касается, учёт — как у пустого ответа (`record` без показанного).
- **§3.2 короткий запрос.** При `subject_terms.len() <= 2` карточка поиска проходит, только если
  в её `sources` есть `fts`, `alias` или `trigram`; порог балла — прежний. Без модели
  (`degraded`) все карточки и так лексические — проверка та же, поведение FTS-only не меняется.
- **§3.3 пересланные сообщения.** `zam_core::text::RELAYED_PREFIXES` и `is_relayed_message`
  (`trim_start`, начало строки, с учётом регистра). Сервер — тишина без строк словаря; клиент
  (`zam hook prompt`) — без `/recall`, очереди `files/changed` и токенов уходят как прежде.
  **Эквивалент у Codex неизвестен — проверить на машине владельца** (как пересылает Codex
  отчёты субагентов и уведомления во вход хука промпта; маркеры Claude Code на ответ Codex не
  влияют: человек так не пишет).
- **§3.4 задача по заголовку.** `task_prompt_cands`: `search_fts_channels` по задачам `open |
  in_progress | blocked` пространств решения и Knowledge каждой живой цели, `top_k` 10 (и не
  больше 10 находок канала с базы), слияние баз — по сырому bm25, как у `post_tool`; строгий
  запрос проходит, ослабленный — при `title_covered` (`covered >= max(min(k, 2), ⌈2k/3⌉)`,

  предметными словами промпта). Строка — `hint_line("задача ", «<заголовок>», [<статус>],

  предел `TASK_HINTS_MAX` в `section_limit` (по `reason`); повтор гасит `session_seen`.
  `reason` задач дайджеста — та же константа `REASON_TASK` (была строка `"task"`).
- **[решение исполнителя, задача 2]** префикс строки — общий `HINT_PREFIX` (`ZeroAIMemory:`)

## Задача 6 — Vault

Замечания 6, 7, 25; спецификация §7, решения координатора 11 (агенту можно удалять и переносить

- **Хранилище.** `zam_store::vault_move(db, id, expected_rev, to, secret_blob, a)` — одна
  транзакция: ревизия `expected_rev` иначе `Conflict`; та же область — запись как есть, без
  ревизии; иначе `UPDATE vault_items SET scope, agent_solution_id, secret, current_rev,
  updated_at` и ревизия `rev + 1` с прежними `title` и `data`. Занятое в цели имя (уникальный
  индекс `vault_live_title`) — `Conflict` «имя занято: в Vault <область> уже есть запись «…»»,
