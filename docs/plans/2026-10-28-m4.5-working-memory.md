# M4.5. Рабочая память — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal.** Агент держит в памяти не только знания, но и состояние работы:
- словарь домена с расширением запроса;
- задачи с передачей между сессиями;
- вопросы к человеку с ответом из WebUI или чата;
- решения с обоснованием и связью `contradicts`;
- знания, привязанные к файлам, с устарелостью;
- окружение в Vault.

После сжатия контекста и у субагента агент получает пакет восстановления и пакет под задачу. Хуки ведут локальный журнал событий сессии и замечают пары «ошибка → исправление».

**Architecture.**
- **Ядро — REST** с тонкими MCP и CLI, как в M4 (принцип 0.1 спецификации). Новые виды записей `term`, `task`, `question` живут в таблице `entries` и получают всё, что уже есть у записей: ревизии, атрибуцию, FTS, Qdrant, связи, `usage`. Новых инструментов MCP нет (принцип 0.2).
- **Привязка к файлам** — отдельная таблица `file_refs` в базе цели. Сервер файлов не видит: хэши (blake3) считает и присылает клиент `zam`.
- **Хуки** — те же `zam hook …` (без tokio и SQLite). Новые пути:
  - `post-tool` для успешных инструментов — только локально, 50 мс;
  - `subagent-start` — сеть, 300 мс.
- **Журнал сессии** — локальный `jsonl` в `.zeroaimemory/cache/`, только метаданные.

**Tech Stack.** Без новых зависимостей. `blake3`, `globset`, `regex` в `zam-cli` уже есть (M4). `similar` для диффа уже есть в `zam-store`. Если исполнитель всё же сочтёт зависимость нужной — аудит и запись в журнал задачи до добавления.

**Spec:** `docs/specs/2026-10-28-m4.5-working-memory.md` (далее — «спецификация», § — её разделы). Основа — ТЗ `docs/specs/2026-10-17-zeroaimemory-tz.md` v1.16 (§6, §7.5–7.6, §9, §10, §12–§15). События агентов — `docs/research/2026-10-28-agent-hook-events.md`. Журнал этапа — `docs/plans/2026-10-28-m4.5-working-memory-log.md`.

## Global Constraints

- **Временные файлы**, логи прогонов, тестовые данные — только внутри проекта: `.tmp/` (под `.gitignore`) или `target/` (в тестах — `env!("CARGO_TARGET_TMPDIR")`). Запрещены:
  - `/tmp` (на Windows это корень диска);
  - `%TEMP%`, `AppData\Local\Temp`;
  - scratchpad Claude Code;
  - `std::env::temp_dir()`, `tempfile` без `dir=`.

  Субагентам это правило передаётся явно.
- **Окружение.**
  - Перед `cargo`/`npm` — `. scripts/dev-env.ps1` (PowerShell) или `. scripts/dev-env.sh`. Без этого rustup ставит toolchain в профиль пользователя.
  - Данные проекта на HDD: пределы ожидания в тестах — с запасом на fsync.
  - Полный прогон — около 2 ч. Известный флейк — `index_api::managed_status_rss_and_cli_reindex_on_stopped_server`.
- **Тесты с процессами** `zam-server`/`zam` запускают дочерние процессы без переменных `ZAM_*` и `AGENT_ENV_VARS` (CI задаёт `ZAM_REQUIRE_ML=1`, сервер читает любые `ZAM_*` как ключи конфига).
- **Правка литералов Rust** с `\` — через Edit, не через shell-heredoc: heredoc ломает продолжения строк.
- **Платформы:** Windows x64 и Linux x64; GPU — только CUDA; без Docker.
- **Проверки каждой задачи:**
  - `cargo fmt --all -- --check`;
  - `cargo clippy --workspace --all-targets -- -D warnings`;
  - `cargo test -p <затронутые> --no-fail-fast`, полный `cargo test --workspace` — в задачах 1, 8, 16;
  - для WebUI — `npm run check`, `npm run build`, `npm run size`, `npm run e2e`.
- **Единообразие с M0–M4:**
  - русские комментарии, документы и тексты UI; английские идентификаторы;
  - `thiserror` в библиотеках, `anyhow` в бинарниках;
  - ошибки API — RFC 9457 через `ApiError` (`type` вида `/problems/<код>`);
  - логи — `tracing` без текста записей, промптов и секретов;
  - запись в память — только маршрутами `memory_routes` (R12: счётчик `memory_writes`);
  - правки записей — `If-Match`.
- **Миграции** — пользовательские:
  - `0015` (задача 1, `rebuild`);
  - `0016` (задача 7);
  - `0017` (задача 10);
  - `0018` (задача 11).

  Системных миграций в этапе нет. Перед миграцией — копия `bak-v<N>`. Тесты на срезы `USER_MIGRATIONS[..N]` не ломаются.
- **MCP:** число инструментов остаётся 10 (`ToolName::ALL`). Новое идёт через `memory_log`, `memory_update_entry`, `memory_search`, `memory_recall`.
- **Блок инструкции v3** — не больше 500 токенов bge-m3 (тест ru/en, ТЗ §14.2).
- **Бюджеты хуков:**
  - `post-tool` успеха — 50 мс весь процесс, без сети;
  - `subagent-start` — 300 мс;
  - прежние (ТЗ §10.3) не меняются.
- **Инварианты** (M4, не нарушаются):
  - Human не попадает в Qdrant, выдачу по токену, MCP, подсказки и журнал сессии;
  - участник общего решения видит только пространство решения;
  - значения Vault не попадают в FTS, Qdrant, `/recall`, журнал сессии и логи (`vault_fts` — только открытые поля);
  - история только дописывается;
  - хук всегда выходит с кодом 0;
  - SQLite — источник истины.
- **Коммиты** — после каждой задачи, в ветке `m4.5-working-memory`. Conventional Commits на русском, trailer `Co-Authored-By` — по реальной модели исполнителя. Коммит только своими путями (`git commit -m … -- <пути>`).

5. **Частые хуки и параллельные инструменты:**
   - сотни `post-tool` за сессию;
   - несколько процессов `zam hook` одновременно дописывают `events-*.jsonl`;
   - файл дорастает до 1 МБ.

   Ожидание:
   - каждая строка пишется одним `write` с флагом append (≤ 4 КиБ);
   - битая строка пропускается при чтении;
   - усечение головы идёт через временный файл и rename;
   - хук укладывается в 50 мс.

   Тест — задача 8, `journal_concurrent_appends_parse_and_trim`.
