# M4. Агенты: MCP, хуки, кэш выжимок, вход пользователей, режим службы — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Редакция 1 (2026-10-26).** План учитывает ответы владельца на 26 вопросов M3 (журнал M3, раздел «Итог ответов владельца (2026-10-26)»). Из M7 в M4 перенесены по решению владельца вход пользователей в WebUI (п. 6) и режим службы (п. 21–22).

**Goal.** Агент начинает пользоваться памятью сам и экономно:
- подключается к серверу по MCP или через CLI одной командой `zam init` (блок в CLAUDE.md/AGENTS.md, хуки, `.mcp.json`) или со страницы WebUI «Подключение агента»;
- получает подсказки хуками в четыре момента (старт сессии, запрос пользователя, перед действием, после ошибки) — триггеры сопоставляются локально, без сети;
- ищет по протоколу «кэш → карточки → точечное чтение → `cache_put`», не получает повторно уже прочитанное (`session_seen`, `if_rev`), а выжимки в кэше инвалидируются при изменении источников;
- обычные пользователи входят в WebUI; сервер работает и службой (Windows SCM, systemd), и обычным процессом;
- правила `certainty`, ревизии записей, поиск и Qdrant приведены к ответам владельца.

Этап закрывают e2e «CRLF» (§1.1), бюджеты хуков, тест «изменение источника → `stale`», замер расхода токенов на eval-сценариях и версия `0.0.5-m4`.

**Architecture.**
- **Ядро — REST** (принцип 5): `/recall`, `/read`, `/cache`, `/sessions`, `/agent-setup` — обычные маршруты axum. **MCP** (`/mcp`, streamable HTTP, `rmcp`) — тонкий адаптер: каждый инструмент вызывает те же функции сервиса, что REST, с тем же `Principal` и проверкой доступа. `zam mcp` — stdio-прокси к `/mcp` для агентов без HTTP-транспорта.
- **Хуки** — команды `zam hook …` (CLI без tokio и SQLite, холодный старт ≤ 20 мс). `pre-tool` работает **только по локальному кэшу триггеров** (`.zeroaimemory/cache/triggers.json`, ETag); остальные события ходят на `/recall` с жёстким тайм-аутом. Любая ошибка → пустой вывод и код 0 (fail-open), запись в `.zeroaimemory/logs/`. Контракт stdin/stdout — `docs/research/2026-10-26-agent-hooks-contract.md`.
- **Сессии и показы** — в базе пользователя запроса (`sessions`, `session_seen`); статистика показов и оценок (`usage`) — в базе, где лежит цель (владелец решения видит «шумные» записи своего решения).
- **Кэш выжимок** — `answer_cache` + обратный индекс `cache_deps` в базе, где лежит пространство кэша: выжимка по решению — в базе владельца решения (общая на решение, §9.4), по личным пространствам — в базе пользователя. Проверка актуальности — одним SQL по `cache_deps` при чтении; инвалидация — в транзакции записи источника (тот же писатель) и по векторной близости новых чанков в воркере индексации.
- **Вход пользователей** — пароль пользователя (argon2id) в `system.db`, cookie-сессия обобщается: `web_sessions.user_id`; `Principal::User` даёт тот же доступ, что `rw`-токен этого пользователя, плюс `author_kind = human`. Администратор по-прежнему из конфига.
- **Режим службы** — тот же бинарник `zam-server`: подкоманда `service run` — точка входа SCM (Windows, `windows-service`), `service install|uninstall|start|stop|status`; на Linux `service install` пишет юнит systemd. Остановка службы идёт тем же путём, что Ctrl+C (`shutdown` сигнал → ожидание WAL Qdrant).

**Tech Stack.** К стеку M3 добавляется (аудит лицензии и активности каждой — в журнал задачи; Rust — `about.toml`):
- `rmcp` `=3.5.1` (Apache-2.0; официальный Rust SDK MCP, github.com/modelcontextprotocol/rust-sdk) — фичи `server`, `transport-streamable-http-server`, `macros`; не новее версии, вышедшей хотя бы за 2 недели до начала задачи (3.6/3.7 — октябрь 2026, свежие);

## Global Constraints

- **Временные файлы**, логи прогонов, тестовые данные — только внутри проекта: `.tmp/` (под `.gitignore`) или `target/` (в тестах `env!("CARGO_TARGET_TMPDIR")`). Запрещены `/tmp` (на Windows это корень диска), `%TEMP%`, `AppData\Local\Temp`, scratchpad Claude Code, `std::env::temp_dir()`, `tempfile` без явного `dir=`/`tempdir_in`, `os.tmpdir()`. **Правило передаётся каждому субагенту в тексте задания.**
- **Окружение.** Rust portable — `.toolchain/`: перед `cargo`/`npm` выполнять `. scripts/dev-env.ps1` (PowerShell) или `. scripts/dev-env.sh`. Данные проекта на HDD — пределы ожидания в тестах с запасом на fsync. Если на `H:` свободно < 100 ГБ — удалить `target/debug/incremental` и `target/tmp`.
- **Платформы:** Windows x64 и Linux x64; GPU — только CUDA; без Docker.
- **Зависимости** — только из Tech Stack или с аудитом лицензии (проект MIT). Новая зависимость и лицензия — в журнал задачи.
- **Проверки каждой задачи:** `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test … --no-fail-fast`; для WebUI — `npm run check`, `npm run build`, `npm run size`, `npm run e2e`.
- **Единообразие с M0–M3:** русские комментарии, документы и тексты UI; английские идентификаторы; `thiserror` в библиотеках, `anyhow` в бинарниках; ошибки API — RFC 9457 через `ApiError`; логи — `tracing` без текста заметок, записей, выжимок, секретов, токенов, паролей и промптов пользователя; конфигурация — слой «файл → `ZAM_*` → флаги»; один писатель на файл SQLite (`Db::write`, BEGIN IMMEDIATE).
- **Миграции** — номера по факту: системная `0006` (пароли пользователей, `web_sessions.user_id`); пользовательские `0013` (сессии, показы, `usage`), `0014` (кэш выжимок). Перед миграцией — копия `bak-v<N>` (`migrate::apply`), обработка данных идемпотентна.
- **Инварианты (не нарушаются ни одной задачей):**
  - Human никогда не попадает в Qdrant, в выдачу по токену и MCP, в выжимки кэша, подсказки хуков и логи; выжимка с источником из Human отклоняется (422);
  - участник общего решения видит в базе владельца только пространство решения — это касается и `/read`, `/recall`, кэша выжимок, MCP;
  - значения Vault не попадают в FTS, Qdrant, ответы поиска и `/recall`, кэш выжимок, логи;
  - история только дописывается; удаление мягкое;
  - хук никогда не блокирует агента: код выхода 0 при любой ошибке, тайм-аутах и выключенном сервере;
  - `axiom` агент ставит и меняет **только по указанию пользователя** — это правило инструкции агента (§14.2), сервер его не проверяет (решение владельца 2026-10-26);
  - SQLite — источник истины, Qdrant пересобирается из `embeddings`.
- **Коммиты** — после каждой задачи, ветка `m4-agents` от `main`, Conventional Commits на русском, trailer `Co-Authored-By` по реальной модели исполнителя. Коммит — только своими путями (`git commit -m … -- <пути>`).

## Review Focus

1. **Хук при недоступном или медленном сервере, битом кэше триггеров, чужом формате stdin** (Codex без `PostToolUseFailure`, пустой stdin, не-JSON, неизвестное событие, огромный `tool_input.content`). Ожидание: пустой вывод или корректный JSON, код 0, укладывание в бюджет; кэш триггеров атомарно перезаписывается (временный файл в `.zeroaimemory/cache/` + rename). Тест — в задаче 10.
2. **Выжимка из кэша после изменения, удаления, отзыва доступа к источнику или его переноса в корзину.** Ожидание: `stale` со списком изменившихся источников; выжимка по решению, к которому у участника отозван доступ, ему не выдаётся. Тест — в задаче 7.
3. **Два агента одновременно правят одну запись журнала** (PATCH без ревизии, с устаревшей ревизией, параллельно). Ожидание: без `If-Match` — 428, с устаревшей — 409 с текущей ревизией; ничья правка не потеряна. Тест — в задаче 2.
4. **Пользователь WebUI выходит за свою память** — открывает чужого пользователя через `X-Zam-User`, админ-маршруты, чужой Knowledge, Human другого пользователя, решение без доступа. Ожидание: 403/404, как у его `rw`-токена; администраторские разделы скрыты и закрыты на сервере. Тест — в задаче 12.
5. **Остановка службы во время массовой индексации и сразу после записи** (SCM `STOP`, `SHUTDOWN` машины, `systemctl stop`). Ожидание: ожидание WAL до `shutdown_flush_wait_ms`, Qdrant не остаётся процессом, данные целы, следующий старт штатный. Тест — в задаче 14 (автотест на Linux-юнит и ручная проверка Windows-службы в журнале).
