# M5.5. Отчёты — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal.** Журнал решения «Отчёты»: агент пишет неизменяемый отчёт (Markdown + картинки и прочие
файлы) через `zam report` или MCP `memory_log kind=report`, пользователь читает его в WebUI с
формулами, диаграммами, таблицами, кодом и картинками, ищет по заголовку, тексту и тегам и выгружает
в PDF печатью браузера. Агенту отчёты не выдаются нигде.

**Architecture.**
- **Отчёт — запись `entries` вида `report`** (буква ссылки `p`), без статуса и `certainty`;
  атрибуция, теги, область, корзина — общие механизмы журналов. Неизменность держат три слоя:
  хранилище (`StoreError::ReportImmutable`), триггеры SQLite миграции (контент `entries`, ревизии
  после первой, `entry_attachments`) и сервер (409 `/problems/report-immutable` на всех изменяющих
  маршрутах записи).
- **Файлы отчёта** — блобы (дедупликация по sha256, `blobs.refcount`) и таблица
  `entry_attachments(entry_id, blob_sha256, filename, mime, size, created_at)`. Ссылки тела
  переписываются сервером в `_attachments/<sha16>/<имя>` при создании; при рендере их разрешает
  резолвер записи → `api/v1/entries/{id}/attachments/{sha}/{имя}`.
- **Создание — одна функция сервера** для двух входов: `multipart` (CLI: часть `meta`, затем
  `file`) и JSON с `images: [{name, data}]` (MCP, base64). Блобы пишутся потоком в `BlobStore`,
  запись, ревизия, чанки FTS и `entry_attachments` — одной транзакцией писателя.
- **Невидимость для агента — одна точка отсечения на каждый вход:** `entry_scope` (любой маршрут
  записи по id), фильтр видов поиска (`report` вне умолчаний токена и вне `KINDS` токена), фильтр
  ленты (`EntryFilter.with_reports`), `index_state = excluded` (нет векторов, нет заданий), запрет
  рёбер и `file_refs`. Тест-матрица задачи 4 проходит все пути агента.
- **PDF — печать браузера** из того же отрисованного HTML: печатный контейнер гидратируется заново
  в светлой теме, `window.print()` — только после KaTeX, Mermaid, картинок и шрифтов.

**Tech Stack.** Новых зависимостей нет. Сервер — `axum` multipart (уже), `zam-markdown`
(`parse`, `render_html`, `attachment_ref`), `mime_guess` (уже), `base64` 0.22 (уже в workspace и
`zam-server`). CLI — `ureq` с потоковым телом (как `zam attach`),
`zam-markdown` только как dev-зависимость (тест согласия разбора ссылок). WebUI — KaTeX, Mermaid,
DOMPurify уже в бандле; e2e PDF — Playwright `page.pdf()` и `pdfjs-dist` (добавлен в M5).

**Spec:** `docs/specs/2026-11-01-m5.5-reports.md` (далее — «спецификация»; решения владельца §2 и
помеченные решения контроллера не пересматриваются), основа — ТЗ (§7.2–7.5, §9, §11.6, §13,
§14.2, §15, §15.5). Журнал этапа — `docs/plans/2026-11-01-m5.5-reports-log.md`. Этап начинается
после выпуска M5: задачи 7–9 M5 меняют `/read`, превью и просмотрщики WebUI, поэтому ссылки ниже —
на функции и файлы, а не на строки.

1. **Агент находит отчёт обходным путём.** Пути: поиск без `kinds` и с `kinds ∋ report`, токен с

2. **Отчёт меняется после записи.** Пути: `PATCH` любого поля (title, body, `append_body`, tags,
   area, data, `refs`, certainty, status, triggers), supersede, retract, answer, claim, release,
   feedback, ребро с отчётом-источником, повтор `Idempotency-Key` с другим телом, прямой `UPDATE`

   (токен), повтор `Idempotency-Key` с другим телом или файлами — 422
   `/problems/idempotency-mismatch` (как у всех записей), `rev` и `body` прежние, триггер SQLite
   отбивает прямую правку. Тесты — задача 1 `sql_update_report_content_aborts`, задача 2
   `report_idempotency_repeat_200_mismatch_422`, задача 3 `report_patch_any_field_409`,
   `report_other_mutations_409`.
3. **Враждебные файлы и пути.** SVG со `<script>` и `onload`, HTML под именем `.png`, имя файла с
   кавычками и управляющими символами, ссылка `..`, абсолютный путь, `\`, символическая ссылка
   наружу каталога, ссылка `_attachments/…` чужой заметки, внешняя и `data:` картинка, картинка с
   не-image MIME, лишняя часть multipart. Ожидание: CLI отказывает до отправки (код ввода), сервер —
   422/413, SVG — только `<img>` и CSP `sandbox` при прямом открытии, скрипты не исполняются. Тесты —
   задача 2 `report_hostile_names_and_links_422`, задача 3
   `report_attachment_download_image_inline_svg_sandbox`, задача 5
   `cli_report_rejects_dotdot_absolute_backslash_symlink_outside`, задача 6 `report_svg_as_img_no_script`.
4. **PDF печатается до догрузки или не таким, как на экране.** Медленный чанк KaTeX или Mermaid,
   медленная картинка, шрифты KaTeX, тёмная тема ОС, ошибка модуля. Ожидание: `window.print()`
   вызывается только после всех модулей, картинок и `document.fonts.ready`; печать в светлой теме;
   при ошибке модуля печать не вызывается, показано сообщение. Тест — задача 7

5. **Удаляет не владелец.** Участник `rw` и `ro` (cookie), токен владельца, токен участника,
   администратор от имени пользователя (`?user=`). Ожидание: 403 у всех, кроме владельца решения в
   своей сессии WebUI; корзина отчётов видна только владельцу; кнопки «Удалить» у прочих нет. Тесты —
   задача 3 `report_delete_restore_owner_only`, задача 6 `report_delete_restore_owner_only_ui`.

- **Маршрут.** `POST /spaces/{space}/entries`: `Content-Type: multipart/form-data` → отчёт;
  JSON с `kind: report` → отчёт с `images`; остальное — прежний путь. Предел слоя маршрута —
  `max(note_body_max, max_total_bytes + MULTIPART_OVERHEAD)`; JSON читается
  `axum::body::to_bytes` с пределом `note_body_max + ceil(mcp_max_bytes · 4/3) + 64 КиБ`, и
  не-отчёт больше `note_body_max` — 413 как раньше **[решение составителя плана]**.
- **Порядок проверок:** доступ к пространству (`space_scope`, `Mode::Write`: токен `ro` и участник
  `ro` → 403, Human по токену → 404) → вид пространства: не решение → 422 → принципал: сессия
  WebUI → 403 «отчёты пишет агент» (ответ владельца 12) → заголовок, `data`, размер тела → файлы.
- **Multipart:** первая часть `meta` (JSON `ReportMeta`, ≤ `note_body_max` + 64 КиБ; иначе 400 «первой
  должна идти часть meta»), затем части `file` с `filename` = путь из тела. На заголовке части:
  имя не из `report_refs` → 422 сразу, до записи байт; повтор имени → 400. Поток — в
  `BlobStore::put` с пределом `min(limits.blob_max_bytes, остаток max_total_bytes)`; число частей
  > `max_files` → 422; превышение размера → 413.
- **JSON (MCP):** `images: [{name, data /*base64*/}]` — любой MIME, тот же механизм; сумма
  декодированных байт и тела > `mcp_max_bytes` → 413 с подсказкой «большой отчёт — `zam report`».
- **Правила ссылок тела** (`report_refs`; ссылки в коде не считаются — их не видит `parse`):

## Решения составителя плана

Спецификация их не определяет или определяет неоднозначно; каждое записать в журнал этапа и в ТЗ
при переносе.

1. Предел файла — `limits.blob_max_bytes` (в спецификации — `blobs.max_bytes`, такого ключа нет).
2. Сессия WebUI не создаёт отчёт: `POST kind=report` по cookie — 403 (ответ владельца 12).
3. Токен: `DELETE`/`restore` отчёта — 403 (спецификация §4, §12 п. 5), прочие обращения — 404
   (§7); администратор от имени другого пользователя — 403, в своей базе-владельце — разрешено.
4. Human по токену — 404, как у всех маршрутов (доступ проверяется раньше вида); Knowledge и Rules — 422.
5. `report` в фильтрах токена (поиск, лента) — 400 тем же текстом, что неизвестный вид.
6. Ответ создания — `{id, url}`, `url` из `server.public_url` или адреса запроса (`agent_setup::public_url`).
7. Внешние и `data:` картинки, ссылки `_attachments/…`, относительные ссылки без файла — 422;
   обычные внешние ссылки — как есть; картинка с не-image MIME — 422.
8. MCP `images` принимает любые файлы (тот же механизм, что у CLI); предел — сумма
   декодированных байт и тела.
9. Multipart: первая часть `meta`, затем `file` с именем = путь из тела; лишняя часть — 422 до
   записи байт; число файлов сверх предела — 422, размер — 413.
10. Неизменность продублирована триггерами SQLite; `entry_attachments` только дописываются (M7
    снимает запрет вместе с GC).
11. Изменяющие маршруты записи (не только `PATCH`) у отчёта — 409; ребро к отчёту — 422.
12. Поле запроса `refs` (ссылки на файлы M4.5) у отчёта — 422; ссылки — только `data.refs`.
13. `format=html` у `GET /entries/{id}` — только у отчёта.
14. CLI разбирает ссылки своим сканером (без `comrak` в бинарнике хуков), согласие — тест против
    `zam-markdown`.
15. Поиск ленты — `POST /search kinds=[report]`; миниатюра — исходная картинка лениво.
16. Корзина отчётов — `deleted=only` в ленте, только владельцу.
17. Печать — печатный контейнер в той же странице с повторной гидратацией в светлой теме; при
    ошибке модуля печати нет.
18. Повторяющийся первый `#` тела не дублируется в шапке страницы.
