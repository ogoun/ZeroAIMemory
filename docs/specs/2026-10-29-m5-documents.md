## 1. Крейт `zam-docs`

Новый крейт workspace (ТЗ §20 «следующий этап: zam-docs»): извлечение структуры документа без
сети, без записи на диск, с лимитами. Интерфейс:

```rust
pub enum DocKind { Pdf, Docx, Pptx, Xlsx, Xls, Ods, Csv, Text }
pub struct Extracted { pub kind: DocKind, pub units: Vec<Unit>, pub warnings: Vec<String>, pub ocr_needed: bool }
pub struct Unit { pub locator: Locator, pub heading_path: Vec<String>, pub text: String }
pub enum Locator { Page(u32), Slide(u32), Sheet { name: String, range: String /*A1:F40*/ }, Para(u32) }
pub fn sniff(bytes: &[u8], name: &str) -> Option<DocKind>;           // по сигнатуре, затем расширению
pub fn extract(kind: DocKind, bytes: &[u8], limits: &Limits, deadline: Instant) -> Result<Extracted, DocError>;
```

- **DOCX, PPTX** — свой разбор `zip` + `quick-xml` (≥ 0.41): абзацы со стилями заголовков
  (`Heading1..6`, `Title`) → `heading_path`; таблицы → строки `| a | b |`; сноски и колонтитулы —
  отдельными единицами в конце; PPTX — текст фигур слайда по порядку, заметки докладчика — отдельной
  единицей слайда. `Locator::Para(n)` у DOCX — номер абзаца (для перехода в просмотрщике — §4).
- **XLSX/XLS/ODS** — `calamine` 0.36.x (точная версия — не новее выпущенной за 2 недели до начала
  задачи); **CSV** — свой разбор (RFC 4180, разделитель угадывается из `,;\t`). Единица — блок строк с
  шапкой (первая непустая строка листа), до `chunk_target_max` токенов; `Locator::Sheet`.
- **PDF** — `pdfium-render` 0.9 с pdfium из комплекта (ТЗ §16.3) **в рабочем процессе** (§2):
  текстовый слой постранично, порядок колонок — по координатам символов (XY-cut), повторяющиеся на
  ≥ 60 % страниц строки в верхних/нижних 8 % страницы — колонтитулы, выбрасываются; страница без
  текста при наличии изображения — `ocr_needed = true` (OCR — вне этапа, §10).
- **Лимиты** (`[docs]` конфигурации, проверяются во всех форматах): размер файла `max_bytes`
  (100 МиБ), распакованный объём zip `max_unpacked` (500 МиБ) и степень сжатия записи ≤ 100,
  записей zip ≤ 10 000, глубина XML ≤ 256, ячеек листа `max_cells` (2 млн), символов текста документа
  `max_chars` (20 млн), страниц PDF `max_pages` (5000), срок разбора `timeout_ms` (60 000). Превышение —
  частичный результат с `warnings` (`truncated: <лимит>`), а не ошибка, кроме размера файла (отказ).
- **XML:** `DocType` — ошибка разбора; внешних сущностей и своего резолвера нет.
- Распаковка только чтением записей в память через `take(лимит)`, без `extract()` на диск.

## 2. Изоляция разбора PDF

Pdfium (C++) нельзя прервать и он регулярно получает CVE переполнения кучи, поэтому PDF разбирается
в **рабочем процессе того же бинарника** — `zam-server doc-worker` (не внешний сервис: тот же файл,
что и сервер, «вещь в себе» сохраняется; механизм — как супервизор Qdrant, ТЗ §4.3):
- запуск по требованию, пул из `docs.workers` (2) процессов, повторное использование до
  `docs.worker_jobs` (200) заданий, затем перезапуск;
- обмен — stdin/stdout, кадры длины + bincode/JSON (решение исполнителя), файл передаётся байтами;
- лимит памяти — Job Object (`JOB_OBJECT_LIMIT_PROCESS_MEMORY`) на Windows, `RLIMIT_AS` на Linux,
  `docs.worker_memory_mb` (2048); срок — `docs.timeout_ms`, по истечении процесс убивается;
- падение или убийство процесса — вложение получает `index_state = failed` с причиной
  (`parse_crash | parse_timeout | parse_oom`), сервер работает дальше; повтор — `reindex`;
- процессы завершаются вместе с сервером (Job Object `KILL_ON_JOB_CLOSE` / `PDEATHSIG`, как Qdrant).
OOXML и таблицы разбираются в процессе сервера с дедлайном и `catch_unwind` (чистый Rust).

## 3. Индексация вложений

- Вложение (`blob` с узлом-владельцем, ТЗ §6) поддерживаемого вида при записи ставит задание
  индексации; воркер вызывает `zam-docs` (PDF — через рабочий процесс), режет `units` по правилам §8.1
  (единица длиннее `chunk_hard_max` — по предложениям; `locator` наследуется), пишет чанки
  `level=attachment` с `locator`, `blob_sha256`, `heading_path`; `context_prefix` —
  `[<space>/<путь заметки>] <имя файла> > <heading_path>`.
- Кэш извлечения по `blob_sha256` (`blob_extract(sha256, extractor_version, units JSON zstd, ocr_needed,
  warnings)`) — одинаковый файл в разных заметках не разбирается повторно; смена версии извлечения —
  перенарезка вложений (отпечаток, как у заметок, ТЗ §8.1).
- Сканер секретов (ТЗ §7.6) применяется к тексту вложений, как к заметкам.
- Human-вложения — только FTS, не Qdrant (инвариант).
- `filters.kinds` по умолчанию += `attachment`; карточка выдачи — `a:<chunk>` с именем файла и
  `locator` (`стр. 12`, `лист «Итоги» A1:F40`, `слайд 3`).

## 4. `/read` и `locator`

- `POST /read` элемент `{id: "n:<node>"|"a:<chunk>"|"b:<sha256>", locator?: "page:12"|"slide:3"|
  "sheet:Итоги!A1:F40"|"para:40"}` — текст единиц документа по `locator` (или весь документ в бюджете
  `max_tokens`); без `locator` у вложения — оглавление (страницы/листы/слайды с L0) и подсказка
  `locator`. 422 `locator-unsupported` снимается; неверный `locator` — 422 `locator-invalid`.
- MCP `memory_read` принимает `locator`; описание инструмента ≤ 300 символов (число инструментов — 10).

## 5. Превью и просмотрщики WebUI

- `GET /blobs/{sha256}/preview?kind=sheet&sheet=&from=&rows=` — JSON листа (страница строк, шапка,
  размеры) для XLSX/XLS/ODS/CSV, кэш в `previews/`; первый экран XLSX 10 тыс. строк ≤ 1 с (ТЗ §17).
- `kind=thumb&page=` — PNG-миниатюра страницы PDF (рабочий процесс, pdfium) или изображения
  (`image` + `fast_image_resize`), кэш `previews/`.
- `kind=text` — PPTX: текст слайдов; TXT/JSON/YAML/код — HTML syntect (ТЗ §15.3).
- **PDF** — `pdf.js` 6.x (Apache-2.0), лениво; `isEvalSupported: false`, скрипты PDF выключены; CSP
  получает `'wasm-unsafe-eval'` только для маршрута просмотрщика PDF (решение контроллера — §11);
  переход к странице из выдачи по `locator`; поиск по тексту — средствами pdf.js.
- **DOCX** — `docx-preview` 0.4 + DOMPurify, вывод в sandbox-iframe (без `allow-scripts`);
  `jszip` — под лицензией MIT (двойная MIT/GPL).
- **XLSX/ODS/CSV** — своя таблица с виртуальной прокруткой, закреплённой шапкой, переключением
  листов, переходом к диапазону `locator`.
- **PPTX** — v1: текст слайдов с навигацией по слайдам (визуальный просмотр — v2, ТЗ §19).
- Бюджет `size-limit`: основной чанк не растёт больше чем на 10 КБ; просмотрщики — отдельные
  ленивые чанки со своими пределами.

## 6. Тестовый набор `eval/docs/`

Свои синтетические документы (генерируются скриптом `xtask docs-corpus` — без чужих файлов с неясной
лицензией): DOCX с заголовками/таблицами/сносками, XLSX на 10 тыс. строк и 3 листа, PPTX на 20
слайдов, PDF — одноколоночный, двухколоночный, с кириллицей и CJK, 500 страниц, «скан» без текста,
враждебные — zip-бомба, XML с DTD/XXE, глубокая вложенность, битый PDF, PDF с JS. Запросы с разметкой
(`eval/docs-queries.toml`, ≥ 30) — recall@5 по вложениям, точность `locator`.
A/B `pdfium-render` против `pdf_oxide` на корпусе — по качеству (доля верного порядка, recall@5) и
скорости; выбор фиксируется в журнале; `pdf_oxide` подключается только при явном выигрыше.

## 7. Критерии готовности (приёмка M5)

e2e (`crates/zam-server/tests/m5_acceptance.rs`): заметка с вложениями DOCX/XLSX/PDF/PPTX →
индексация → поиск находит фрагмент каждого формата с верным `locator` → `/read` по `locator`
возвращает текст страницы/листа/слайда; враждебные файлы из корпуса не роняют сервер и не превышают
лимиты (вложение `failed` с причиной); убийство рабочего процесса посреди разбора — вложение `failed`,
сервер работает; превью листа XLSX 10 тыс. строк ≤ 1 с; Human-вложение не попадает в Qdrant.
WebUI e2e: просмотр PDF с переходом к странице из поиска, DOCX, XLSX с переключением листов, PPTX.
Smoke комплектов: вложение PDF ищется в собранном пакете (pdfium из комплекта).

## 8. Миграции

Пользовательская `0019_blob_extract.sql` (кэш извлечения, состояние индексации вложений);
системных — нет. Номер фиксируется планом.

## 9. Безопасность

Недоверенные файлы — от агентов и людей: лимиты §1 обязательны, разбор PDF — только в рабочем
процессе, превью DOCX — в sandbox-iframe, PDF без исполнения скриптов. Регламент обновления pdfium —
вопрос владельцу (§11). Fuzz-цели `cargo fuzz` для `zam-docs` (DOCX/PPTX/CSV) — короткий прогон в
задаче, по образцу `fuzz-check` проекта.

## 10. Вне этапа

OCR сканов (кандидат — PaddleOCR на `ort`), визуальный PPTX, DOC/PPT старых форматов, правка
документов, карта кода (предложение — отдельный этап M5.5, §11).

## 11. Уточнить у владельца

1. Рабочий процесс `zam-server doc-worker` (тот же бинарник) при правиле «без внешних процессов» —
   принято контроллером как допустимое (тот же механизм, что Qdrant).
2. Регламент обновления pdfium: раз в 2–4 недели и внеочередно при критическом CVE.
3. `'wasm-unsafe-eval'` в CSP только для просмотрщика PDF.
4. Временный дубль `zip 8` и `zip 9` до обновления `calamine`.
5. Карта кода (встроенная, решение владельца 2026-10-28) — отдельным этапом M5.5 после M5
   (предложение контроллера), чтобы M5 не разрастался.
6. OCR — отдельным этапом или в M6.
