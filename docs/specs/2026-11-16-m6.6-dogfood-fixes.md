## 1. Зачем

За первые сутки работы через собственную память (M6.5) записано 33 замечания: агент не видит
открытых задач и ловушек проекта, получает посторонние подсказки на «согласен» и на отчёты

крупному M7.

## 3. Подсказки к запросу (замечания 17, 22, 28б)

**3.1. Нет предметных слов — нет подсказки** (17). Новая функция
`zam_search::recall::subject_terms(prompt) -> Vec<String>`: слова от 3 символов (как
`error_terms`) → без стоп-слов ru/en (`prepared_terms`, основы) → без слов-реплик
`PROMPT_REPLY_WORDS`. Слова-реплики сравниваются **точным совпадением** после нормализации, без
основ («продолжительность» — предметное слово). Список: согласен, согласна, согласны, хорошо,
отлично, супер, давай, давайте, продолжай, продолжайте, продолжи, дальше, далее, делай, делайте,
вперед, вперёд, поехали, погнали, понял, поняла, понятно, ясно, принято, верно, точно, конечно,
угу, ага, окей, спасибо, годится, подходит, одобряю, начинай, запускай, готово, норм, нормально,
правильно, именно, нет, yes, yep, yeah, sure, agreed, agree, okay, fine, great, good, thanks,
thank, continue, proceed, next, lgtm, done, right, correct, exactly, please, ahead, approved.
Пустой `subject_terms` — `prompt_hints` и `prompt_ideas` не вызываются (ответ пустой, сессия
касается, учёт — как у пустого ответа); подсказки терминов (`term_cands`) остаются.

**3.2. Короткий запрос — только с лексическим совпадением** (17). При `subject_terms.len() <=
PROMPT_SHORT_WORDS` (= 2) карточка подсказки `prompt` проходит, только если среди её `sources`
есть `fts`, `alias` или `trigram`. Проверка — общая `fn lexical(item) -> bool`, вынесенная из
`idea_lexically_matched`. Причина: балл гибрида нормируется по непустым каналам, у слова без
FTS-совпадения ближайшая по вектору запись получает 1,0 при пороге 0,6. Поиск без модели
(`degraded`) правило не меняет. Константы, не конфиг **[решение координатора]**.

**3.3. Пересланные сообщения** (22). `zam_core::text::is_relayed_message(s) -> bool`: начало
`s.trim_start()` — один из `RELAYED_PREFIXES = ["[Subagent hand-back]", "<agent-message",
"<task-notification>"]`, с учётом регистра. Сервер (`recall`, событие `prompt`) — тишина без
подсказок терминов; клиент (`zam hook prompt`) — не зовёт `/recall` и не пишет событие `Prompt` в
журнал сессии, очереди `files/changed` и токенов отправляет как прежде. Обе стороны **[решение
координатора]**: сервер — для уже установленных клиентов. Эквивалент у Codex — проверить на машине
владельца (журнал этапа).

**3.4. Задача по заголовку** (28б). Отдельный проход FTS без эмбеддинга
(`task_prompt_cands`): `kinds ["task"]`, статусы `open|in_progress|blocked`, пространства —
решение и Knowledge, `top_k` 10. Строгий запрос (все слова) — проходит; ослабленный — только
если слова заголовка покрыты промптом: `covered >= max(min(k, 2), ceil(2k/3))`, где `k` —
значимые слова заголовка. Строка `<решение>: задача «…» [<статус>] k:<id>`, `reason: "task"`,
не больше `TASK_HINTS_MAX = 1` на ответ, повтор в сессии гасит `session_seen`. Основной поиск
подсказок (`kinds: insight, note`) не меняется.

Код подсказок к запросу (3.1–3.4) — в `crates/zam-server/src/api/recall/prompt.rs` (§11.1).

## 4. Дайджест (замечания 27, 28а, 16а, 30)

**4.1. Ловушки проекта первыми** (27). `trap_cands`: ловушки решения (новые первыми), затем

У решения меньше `n-1` ловушек — остальные места занимает Knowledge, как прежде. Раздел

**4.2. Открытые задачи** (28а). В разделе `### Задачи` (он появляется и без захваченных задач)
строка `Открыто задач: N — «…», «…», «…»`: `N` — все живые `open` решения и Knowledge; до
`OPEN_TASKS_TITLES = 3` заголовков (`clip` 80 символов, `mask_text`) без задач с живым захватом
(те уже в разделе), порядок — `priority` (high → normal → low → нет), затем новые первыми. Нет

восстановления; в мини-дайджесте `brief` строки нет. Хранилище: `zam_store::open_tasks(db,
spaces, titles) -> (usize, Vec<…>)` по образцу `open_questions`. Число и заголовки не зависят от
сессии (детерминизм дайджеста сохраняется).

**4.3. Мелочи.** «Окружение» (16а): у частей `purpose`, `address`, `limits` срезаются хвостовые
`.`, `;`, `,` и пробелы до склейки «; » (многоточие `…` не трогается). Склонение (30): общая
`zam_core::text::plural_ru(n, one, few, many) -> &str` заменяет обе приватные копии
(`zam-code/src/pack.rs`, `api/code.rs`); строка словаря — «74 термина», «1 термин», «5 терминов».

## 5. Явные пакеты и настройки (замечание 20; разбор идей; кэш настроек)

**5.1. Срок явного вызова** (20). Срок по умолчанию: хук — `recall.timeout_ms`; явный вызов —
`max(recall.max_timeout_ms, recall.timeout_ms)`. Хук — запрос без происхождения MCP с событием
`session_start|prompt|post_tool` или с полем `code_map` (его шлёт хук `subagent-start`). Явные —
MCP (все события), REST и `zam` для `brief`, `recovery`, `idea_review` без `code_map`. Поле
`timeout_ms` по-прежнему важнее. Описание `timeout_ms` в MCP — «по умолчанию: хук —
recall.timeout_ms, явный вызов — recall.max_timeout_ms». Конфиг и API не меняются.

**5.2. Разбор идей без решения на сервере.** Пакет `idea_review`, когда решения нет в области
поиска: решения не передано — как сейчас («решение не задано…»); в `warnings` есть `solution
access …` или решение есть в реестре без доступа — `IDEA_REVIEW_NO_ACCESS` «Идей на разбор нет:
нет доступа к решению (см. warnings).»; решения нет в реестре — `IDEA_REVIEW_UNREGISTERED` «Идей
на разбор нет: решение <GUID> не зарегистрировано на сервере — подключите его `zam init`.».

**5.3. Кэш настроек пользователя.** `UserFlagsCache` в `AppState` по образцу `GlossaryCache`:
`Mutex<HashMap<Id, UserFlags>>` и счётчик поколения; запись в кэш — только если поколение не
изменилось за чтение; `PATCH` настроек увеличивает поколение и удаляет запись пользователя.
`/recall` читает `user_flags` и режим идей владельца общего решения через кэш **[решение
координатора: кэш процесса, а не сессии — точен без TTL]**.

## 6. Словарь (замечание 12)

Одна функция поиска псевдонимов для предупреждений `term_alias` и подсказок терминов:
1. **Код не текст:** `zam_markdown::prose_mask(text) -> String` заменяет блоки в ограждениях
   (```` ``` ````, `~~~`) и `` `…` `` пробелами той же длины в байтах (логика ограждений —
   общая с `sentences.rs`).
2. **Идентификатор не слово:** граница не засчитывается, если рядом с псевдонимом соединитель
   `_ - . / \ : @ # $`, а за ним (или перед ним) буква или цифра; `_` считается буквой. Точка в
   конце предложения остаётся границей.
3. **Аббревиатуры с учётом регистра:** псевдоним из двух и более букв, все заглавные (`ZAM`,
   `MCP`), сравнивается с учётом регистра; остальные — без учёта, как прежде.
4. Подсказка термина к запросу (`GlossaryIndex::find_in_head`) — шаги 1–3 до разбора на слова.
   Расширение запроса поиска (канал `alias`) **не меняется** (влияет на ранжирование и ТС-1).
5. **Слишком общий псевдоним:** при записи и правке `term` — предупреждение
   `term_alias_broad: «…» — …` (запись не отклоняется), если в псевдониме меньше 3 букв или цифр
   или он стоп-слово (`zam_core::text::is_stop_word`). Новый вид предупреждения — в
   `docs/api-compat.md` и в протоколе.

`Authorization: Digest` прозой без кавычек остаётся срабатыванием — предел правила (руководство,
«Известные ограничения»).

администратора) — в `home`/`local` отказ, код 1. Повторный `zam init` без флага сохраняет режим
(нет строки адреса в прежнем блоке — не `block`). В `block`, если `CLAUDE.md` не исключён из git,
— предупреждение «адрес сервера окажется в репозитории: zam init --url-to home». Умолчание
`block` **[решение координатора: совместимость с WebUI и чужими установками]**.

**10.2. Документы.** «Первый токен администратора» (3): админ-API — только по входу
администратора (`POST /api/v1/auth/login` → cookie и `csrf`; изменяющие запросы — `x-csrf-token`),
любой токен агентский — 403; пример `curl`. Текст 403 `AdminOnly`: токену — «администраторский
маршрут: нужен вход администратора (POST /api/v1/auth/login, cookie и x-csrf-token); токен —
агентский», сессии пользователя — «только администратору». Права не меняются. `zam status` (16в):
«токен целиком не печатается — префикс `zam_XXXXXXXX…`, как в списке токенов WebUI». Обновление
(32): копия каталога данных — лучше `zam-server backup`; проверка ручной копии — не `du -sh` (на
ZFS и Btrfs со сжатием это место на диске), а `du -sh --apparent-size` или сверка списка и
размеров баз.

## 12. Приёмка

1. Каждое решение §3–§11 закреплено тестом, названным в плане; тесты, падающие на `main`, —
   зелёные на ветке.
2. `cargo xtask eval --hints` (CPU) на прежних случаях `eval/hints.toml` — доля нужных подсказок
   не ниже, лишних не больше, чем на `main` (число записать в журнал этапа); новые случаи «тишина»
   на «согласен», «продолжай», отчёт субагента — пусты.
3. `recall_frozen`, `recall_heavy*` (детерминизм и предел канала) — зелёные; блок v8 — ≤ 500
   токенов ru и en, как прежде; MCP — 11 инструментов; все описания схем ≤ 300 символов.
4. `features` содержит `vault_move`, `docs/api-compat.md` его описывает (`health_features_documented`).
5. fmt, clippy `--workspace --all-targets -D warnings`; полный прогон `ZAM_REQUIRE_ML=1`; e2e
   WebUI, если WebUI менялся; smoke комплекта; CI, CUDA, Edge зелёные.
6. Выпуск `0.0.13-m6.6` развёрнут на сервере памяти и тестовом стенде; хосты владельца перенесены в
   личный Vault; статусы замечаний в журнале обкатки обновлены.
