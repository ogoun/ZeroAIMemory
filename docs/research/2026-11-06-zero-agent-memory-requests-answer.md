# Ответ ZeroAIMemory на предложения zero-agent (2026-11-06)

Исходный документ: [`2026-11-06-zero-agent-memory-requests.md`](2026-11-06-zero-agent-memory-requests.md).
Решение владельца 2026-11-06 (ответ «А»): небольшие исправления — в M6 (`0.0.11-m6`), крупные
функции — в M7 или отдельный этап «Память для своего агента», остальное — по необходимости.

## 2. Перенесено в M7 / отдельный этап

CR-4 (лента изменений), CR-6 (атомарная выдача задачи), CR-10 (дедупликация под гонкой), CR-12
(пакетная запись), CR-19 (происхождение записи), CR-2 (токены с областью), CR-3 (идентичность

## 3. По необходимости

CR-11, CR-13, CR-14, CR-15, CR-16 — у каждого есть обходной путь; потребности сейчас нет.

## 4. Что в описании неверно

Сверка задачи 19 (2026-11-11, ветка `m6-portability`): каждое утверждение CR-7, CR-8, CR-20 и
строк приложения проверено по коду и тестом. Номера строк в запросе даны на срез `13b0bac` и
с тех пор уехали — это не считается расхождением. Вердикт: **верно**, **неточно** (суть верна,
деталь нет) или **неверно**.

### CR-7

| Утверждение | Вердикт | Проверка |
|---|---|---|
| `recall.timeout_ms` = 200 мс и рассчитан на хуки | верно | `config.rs` (умолчание 200), `recall_timeout_ms_param_full_digest`: без поля при задержке 600 мс — `recall timeout` |
| `source` принимается `memory_recall`, но не объявлен в схеме; то же `agent_block_version` | верно | `mcp/tools.rs`: оба поля были в `pick`, в схеме — нет; `mcp_recall_schema_has_source_block_timeout` |
| С `timeout_ms: 1000` на медленном диске будет полный дайджест | верно после правки | тот же тест: шаг сбора задержан на 600 мс, ответ полный, без предупреждения |

### CR-8

| Утверждение | Вердикт | Проверка |
|---|---|---|
| `account()` смотрит только заголовок | верно | `mcp/mod.rs`: `explicit = rest.header(SESSION_HEADER).is_some()`, `session_touch(…, None)` |
| `/recall` считает сессию явной и по полю тела | верно | `api/sessions.rs::request_session`: `body || !implicit` |
| `memory_recall` с `session_id` без заголовка уходит в `tokens_unattributed` | верно, и хуже | по коду: `account()` без заголовка пишет в `unattributed`, а REST `/recall` отмечал «выдано» в сессии аргумента — учёт и отметки расходились; тест `mcp_session_id_arg_accounts_session` до правки падал (у `memory_read` с `session_id` отметок не было вовсе), после — учёт трёх вызовов в сессии аргумента, `unattributed` пуст |
| У `memory_search` и `memory_read` поля `session_id` нет | неточно | в схеме MCP не было, но REST `/search` и `/read` поле `session_id` тела принимают давно; MCP его просто не пересылал (`pick` без поля) |
| (не упомянуто) заголовок и аргумент вместе | дополнение (по коду) | раньше у `memory_recall` побеждал аргумент (тело сильнее заголовка), учёт же шёл по заголовку; теперь разные значения — ошибка 400 (`mcp_session_header_and_arg_conflict_400`) |

### CR-20

| Утверждение | Вердикт | Проверка |
|---|---|---|
| `Idempotency-Key` есть только у `POST /spaces/{space}/entries` и `/supersede` | верно | тем же маршрутом идут отчёт, идея, вопрос, задача; у `PATCH /entries/{id}` (действие `append` записи журнала) ключа тоже нет — см. «Остаётся» ниже |
| У `POST /nodes` и `PATCH /nodes` защиты нет | верно, и у `PUT` | заголовок не читался ни одним из трёх |
| Повтор `op: append` задвоит текст | верно | `patch_append_idempotent` до правки: два `PATCH append` с одним ключом — две вставки; `memory_write_idempotency_key`: без ключа так и осталось (`append` и `prepend` применяются к текущему тексту при любом `base_rev ≤ current`) |
| Семантика записей журнала: «повтор возвращает 200 и исходный результат» | неточно | записи журнала с M3 отдают на повтор 200 и **текущее** состояние записи, а не сохранённый первый ответ; узлы сделаны так же (`patch_append_idempotent`: повтор после чужой правки покажет последнюю ревизию) |

### Строки приложения

| Наблюдение | Вердикт | Проверка |
|---|---|---|
| `memory_read` с `focus` даёт 400 до задачи 7b | было верно; закрыто 7b | `mcp_read_focus` |
| `brief` без `session_id` отмечает показ в сессии заголовка (родителя) и гасит его подсказки | неточно по механизму, верно по последствию | хук `subagent-start` всегда шлёт `session_id` в теле; без `agent_id` он **явно** подставлял id родителя (комментарий «показ учитывается в сессии родителя»). Последствие подтверждено: `subagent_brief_does_not_mute_parent_hints` до правки — подсказка `prompt` родителя к ловушке из пакета погашена. Теперь пакет без `agent_id` идёт в своей сессии субагента с `parent_id` родителя |
| `memory_writes` растёт от `claim`, `release`, `POST /cache`, смены статуса | верно | все они в `memory_routes` (`api/mod.rs`); `mcp_read_and_cache_put_roundtrip` (запись выжимки — `memory_writes = 1`) |
| Дайджест показывает только `in_progress` и `blocked`, захваченная `open` не видна | было верно; закрыто 8a | `api/recall.rs` (раздел «Задачи»: `open` с живым захватом) |
| `.zeroaimemory/area.toml` описан в ТЗ, но не читается | верно | ни клиент, ни сервер файл не читают (поиск по коду) → 13c (ТЗ) |
| README отстаёт | верно | → 13c |
| Устаревшие комментарии: «срок» токена | верно | у токена нет столбца срока (`migrations/system/0001_init.sql`); комментарий `mcp/mod.rs` исправлен в задаче 19, остальные → 13c |
| Описание `memory_update_entry` неполно: `propose`, `decide` тоже без `rev` | верно | описание называло четыре действия, схема поля `rev` — шесть; исправлено, `mcp_ref_prefixes_include_w` |
| Префикс `w:` работает, но не указан в списках | верно | `memory_read w:<id>` читает идею; списки в описаниях MCP и в документации кода дополнены (`mcp_ref_prefixes_include_w`) |
| Снимок сессии: маршрута нет | было верно; закрыто 17c | `PUT|GET /sessions/{id}/snapshot` |

### Что сделано в M6 (задача 19)

Описание для разработчика клиента — [`docs/api-compat.md`](../api-compat.md): правило
совместимости `/api/v1`, флаги `features` (в том числе новые `recall_timeout`,
`idempotent_nodes`, `mcp_session_arg`, а также `epochs`, `unattributed`, `holdout`, `backup`,
`export`, `import`), явная сессия MCP, срок `/recall`, таблица идемпотентности.

### Остаётся (M7)

- `Idempotency-Key` у правки записи журнала (`PATCH /entries/{id}`, в том числе `append`) и у
  `POST /entries/{id}/answer|claim|propose|decide` — тот же класс повтора, что CR-20, но
  вне запроса; вместе с CR-12 (пакетная запись, идемпотентность по элементам).
- OpenAPI для `/api/v1` (CR-9).

## 5. Связанное решение владельца (2026-11-06)

Маскировка секретов при полном чтении агентом (L2, `range`, MCP): в M7. Агент получает
`‹secret›`, исходный текст остаётся в базе и виден в WebUI; ключи агент берёт из Vault.
