# Разбор sukamenev/baton: что взять в ZeroAIMemory

**Статус:** исследование, 2026-11-04. Запрос владельца: «посмотри… может найдёшь что-то полезное нам из идей». **Решение владельца 2026-11-04 (вопрос baton-1): А** — снимок сессии делать в M6, по умолчанию включён, с маскировкой секретов и пределом размера; правило «отвергнутые подходы» — в протокол агента.

## 1. Что это

[baton](https://github.com/sukamenev/baton) — CLI на Go (MIT, v0.3.11, 34 коммита, 7 звёзд, последний коммит 2026-11-03) для передачи сессии между CLI-агентами: Claude Code, Codex, Antigravity, Pi, OpenCode, Cursor. Есть ещё перенос сессии на другую машину, зашифрованный и через публичные paste-сервисы.

Главная мысль автора: пересказ, сделанный LLM, теряет данные — точные флаги, номера строк, отвергнутые гипотезы. Кроме того, когда кончается лимит подписки, агент уже не успевает написать HANDOFF.md. Поэтому baton **не делает пересказ сам**. Он читает с диска сырые журналы сессий агентов (`~/.claude/projects/<slug>/<uuid>.jsonl`, `~/.codex/sessions/…/rollout-*.jsonl` и т. п.) и берёт оттуда:
- последний конспект после сжатия контекста, который агент уже написал сам. У Claude это запись `type: "summary"` или `isCompactSummary`, у Codex — `type: "compaction"`;
- диалог после этого конспекта;
- изменённые файлы и выполненные команды, восстановленные по вызовам инструментов;
- правила проекта (CLAUDE.md, AGENTS.md…).

Принимающий агент получает сводку со статусом COMPLETE или PARTIAL и части по 28–40 КБ, которые дочитывает по одной. Интеграция — через skill и `/baton`, без MCP и без фонового процесса.

## 2. Сравнение с ZeroAIMemory

| Тема | baton | ZeroAIMemory сейчас |
|---|---|---|
| Состояние работы | восстанавливается из журнала сессии агента после факта | ведётся по ходу работы: задачи с `next_step`, захват, журнал сессии, вопросы, решения (§7.8, M4.5) |
| Передача другому агенту | `baton load` | дайджест `session_start`, `recovery`, `brief`; ядро не зависит от агента |
| Пересказ LLM | не делается | выжимку делает агент (G9) |
| Журнал сессии агента | читается | **не читается**: хуки получают `transcript_path`, но не используют его |
| Секреты | не маскируются (пакуются изменённые файлы и глобальные правила) | сканер секретов с маскировкой (M5.6, `secrets.rs`) |
| Перенос между машинами | AES-GCM и публичный paste, ключ в `#` | сервер и совместный доступ (§11.6) |

Почти всё, что делает baton, у нас уже есть в более строгом виде: состояние ведётся по ходу работы, а не восстанавливается задним числом. Новое — только одно: **журнал сессии агента как бесплатный источник фактов**.

## 3. Что можно взять

1. **Страховка на случай внезапной смерти сессии** (главное). Если агент упёрся в лимит или окно закрыли, `next_step` задачи может быть устаревшим.
   - Хук `Stop`, `SessionEnd` или `PreCompact`, а при `SessionStart compact` — следующий запуск, читает хвост `transcript_path` без LLM и без токенов.
   - Из журнала берутся конспект сжатия, последние запросы пользователя, изменённые файлы и команды.
   - Всё проходит маскировку секретов и сохраняется в журнал сессии как запись «снимок сессии» с пометкой «извлечено автоматически».
   - `recovery` и дайджест следующей сессии подают его как «последнее известное состояние», если задача давно не обновлялась.
2. **Изменённые файлы по вызовам инструментов.** Список `Edit`/`Write`/`Bash` из журнала даёт точное «что трогали» для `checkpoint` и карты кода. Хук `PostToolUse` это уже частично видит. Журнал позволяет восполнить пропуски, например когда хук был выключен.
3. **«Отвергнутые гипотезы»** — это то, что сжатие теряет. Полезно добавить в протокол агента короткое правило: отвергнутый подход записывать как `insight` или `decision` с пометкой «отвергнуто, потому что…». Дёшево, без кода.
4. **Не брать:**
   - перенос через публичные paste-сервисы. Он противоречит самодостаточности и безопасности: секреты не маскируются, а ссылка — единственный ключ;
   - перезапись файлов проекта без подтверждения;
   - фоновую проверку обновлений.

## 4. Риски и вопросы

- **Формат журналов агентов не документирован** и меняется от версии к версии. В baton за месяц было несколько правок парсеров. Нужны разбор с допуском ошибок (неизвестное пропускается), тесты на фикстурах и выключатель.
- **Объём.** Журналы сессий бывают по десяткам МБ. Читать только хвост, с пределом по байтам и сроком, как у хуков (§10).
- **Приватность.** Журнал содержит весь диалог. Сохранять только извлечённые поля, после маскировки и с пределом размера; по умолчанию функция включена или выключена — решает владелец.
- **Место в плане.** Кандидат для M6 (связь с `checkpoint` и восстановлением после сжатия) или для M7. Решение — за владельцем.
