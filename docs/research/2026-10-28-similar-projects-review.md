# Обзор похожих проектов: что упущено в ZeroAIMemory

Дата: 2026-10-28. Состояние ZeroAIMemory на дату обзора — `0.0.5-m4` (ветка `m4-agents`), согласован
этап M4.5 «Рабочая память» (`docs/research/2026-10-27-memory-gaps-agent-view.md`, §4–§5).

## 1. Цель и метод

**Цель.** Изучить семь проектов из той же ниши (память агента, экономия контекста, карта кодовой
базы), найти идеи, которых нет в ТЗ (`docs/specs/2026-10-17-zeroaimemory-tz.md`) и в плане M4.5, и
разложить их по плану: взять в M4.5, позже (M5–M7, v2) или не брать.

**Метод.**
- Источники: README, документация и исходный код в GitHub (через веб и GitHub API, без клонирования),
  справочник хуков Claude Code (сверка возможностей, на которые опираются проекты).
- Утверждения проверялись по коду там, где это решало вопрос: обработчики хуков claude-mem
  (`src/cli/handlers/*.ts`, `src/utils/redaction.ts`, `src/utils/tag-stripping.ts`), снимок сессии и
  извлечение событий context-mode (`src/session/snapshot.ts`, `src/session/extract.ts`,
  `hooks/pretooluse.mjs`), техническая документация rtk (`docs/contributing/TECHNICAL.md`,
  `src/learn/README.md`), CCR и `learn` в headroom (`headroom/ccr/marker_resolution.py`,
  `headroom/learn/analyzer.py`), навыки Understand-Anything (`skills/understand-chat`,
  `skills/understand-diff`), хуки ponytail (`hooks/ponytail-map.js`, `hooks/ponytail-subagent.js`),
  `ARCHITECTURE.md` и `BENCHMARKS.md` graphify.
- В тексте помечено: **[код]** — проверено по исходникам; **[README]** — только по описанию проекта,
  код не сверялся. Цифры экономии из README — заявления авторов, независимо не воспроизводились.
- Все семь репозиториев доступны и не пусты.

**Базовая линия для сравнения** (§18.2, итоги M4): протокол brief→read с чтением L2 на первом
обращении — 120,6 % токенов «наивного» `mode=chunks` (4000), повтор через кэш — 33,0 %; цель M6 —
снижение расхода на типовой сценарий ≥ 30 % при той же полноте.

## 2. Проекты

### 2.1. claude-mem (thedotmack/claude-mem)

**Назначение.** Плагин постоянной памяти для Claude Code (и ещё ~10 агентов): сам записывает, что
агент делал в сессии, сжимает это LLM-наблюдателем и подаёт индекс прошлого в новые сессии.
TypeScript/Bun, Apache-2.0, ~104 тыс. звёзд, версия 15.3.0.

**Механизмы.**
- **Хуки** [код, `plugin/hooks/hooks.json`]: `SessionStart` (запуск воркера; контекст — на
  `startup|clear|compact`, на `resume` **не выдаётся**, чтобы не ломать кэш промпта),
  `UserPromptSubmit` (регистрация сессии, сырой промпт сохраняется для FTS), `PostToolUse` и
  `PostToolUseFailure` с matcher `*` (асинхронная постановка в очередь: имя инструмента, вход, выход),
  `PreToolUse` на `Read|Bash|Grep|Glob` (контекст по файлу, см. ниже), `Stop` (сводка сессии),
  `SubagentStart` (таймлайн субагенту), `SubagentStop`, `SessionEnd`.
- **Наблюдатель.** Воркер по очереди отдаёт события LLM (по умолчанию Sonnet через Claude Agent SDK;
  есть Gemini, OpenRouter, OpenAI-совместимые) — 5–30 с на наблюдение, последовательно. Результат —
  типизированные наблюдения (bugfix, feature, refactor, discovery, decision, change) и сводки
  `<summary>` с полями `request, investigated, learned, completed, next_steps, files_read,
  files_modified, notes`; сводок может быть несколько за сессию («контрольные точки»).
- **Хранение.** SQLite (`~/.claude-mem/claude-mem.db`, FTS5) + Chroma для векторов (ставит `uv`).
- **Подача в контекст.** На старте — таблица-индекс `ID | Time | T | Title | Tokens` по дням
  (по умолчанию 50 наблюдений из 10 последних сессий), без полного текста, со ссылкой на поиск.
  Поиск — три слоя: `search` (индекс, ~50–100 токенов на запись) → `timeline` (соседи по времени) →
  `get_observations` (полный текст, ~500–1000), заявлено «~10× экономии».
- **Контекст по файлу на `Read`** [код, `file-context.ts`]: перед чтением файла ≥ 1500 байт хук
  запрашивает наблюдения по этому пути (`/api/observations/by-file`, до 40), отбрасывает их, если
  файл изменён после последнего наблюдения (`mtime ≥ newest observation`), оставляет по одному на
  сессию, ранжирует (+2 — файл менялся в наблюдении, +2 — наблюдение касалось ≤ 3 файлов) и
  выдаёт до 15 строк таймлайна; повтор — только при появлении нового наблюдения. Есть «шлюз
  чтения»: полное чтение файла ≥ 32 КиБ (кроме md/yaml/toml) **запрещается** (`permissionDecision:
  deny`) с переадресацией на `smart_outline`/`smart_unfold` (tree-sitter).
- **Субагенты** [код, `subagent-context.ts`]: на `SubagentStart` — тот же таймлайн, но не в
  ответвлённые потоки (они уже несут историю родителя). Известная проблема (issue): N параллельных
  субагентов умножают расход на инъекцию.
- **Приватность** [код]: `<private>…</private>`, `<system-reminder>`, `<persisted-output>` и
  собственные теги вырезаются в «единой точке» захвата; маскировка секретов по шаблонам (AWS, GitHub
  PAT, OpenAI/Anthropic, Slack, JWT, PEM, Stripe, Google) **выключена по умолчанию**
  (`CLAUDE_MEM_REDACT_ENABLED`); в обработчике `observation.ts` сырые `tool_input/tool_response`
  уходят в очередь без маскировки. Сжатие идёт во внешний LLM — содержимое файлов и вывод команд
  покидают машину.

**Отличие от нас.** У claude-mem запись неявная и делает её LLM, у нас — явная запись агентом
(§2.2 не-цели, принцип 2 «на сервере нет LLM»). У нас есть то, чего у них нет: ревизии,
`certainty`, `supersedes/retract`, триггеры без сети, инвалидация кэша выжимок, общий доступ.
У них есть то, чего нет у нас: подсказки по файлу при **чтении**, инъекция субагентам, индекс с
ценой в токенах на старте, сводка-контрольная точка на `Stop`.

### 2.2. graphify (Graphify-Labs/graphify)

**Назначение.** Навык `/graphify` и Python-библиотека: превращает кодовую базу, документы, схемы,
PDF в граф знаний (`graph.json`, `graph.html`, `GRAPH_REPORT.md`), который агент запрашивает вместо
grep. Python, Apache-2.0/MIT, ~137 тыс. звёзд.

**Механизмы.**
- Код — tree-sitter (~40 языков), детерминированно, без LLM: вызовы, импорты, наследование между
  файлами; документы, PDF, изображения — семантический проход LLM (можно `GRAPHIFY_BACKEND=none`
  или Ollama). Кластеры — Leiden/Louvain; «узлы-боги» (самые связанные); комментарии `# NOTE:`,
  `# WHY:` и ссылки на ADR/RFC — отдельные узлы, связанные с кодом [README].
- Рёбра с уверенностью `EXTRACTED | INFERRED | AMBIGUOUS` [код, `ARCHITECTURE.md`, `validate.py`].
- Потребление: `graphify query|path|explain` (подграф по вопросу; коды выхода «неоднозначно»/«нет»),
  MCP stdio, хук Claude Code перед поисковыми вызовами и `Read/Glob` «подталкивает» к графу,
  инструкции в AGENTS.md. Инкрементально: кэш извлечения по изменённым файлам, `watch` с задержкой
  3 с, git-хуки на commit/checkout.
- Измерение: собственный стенд (LOCOMO, LongMemEval-S, ERPNext) с одним LLM-судьёй (каппа 0,81 со
  вторым). На коде — покрытие ключевых фактов 82,0 % против 70,8 % у grep/read, но выборка — 6
  вопросов, ~140 тыс. токенов на вопрос; «−80 % токенов» относится к платному Graphify Cloud и не
  обоснован методикой.

**Отличие от нас.** Граф graphify — граф **кода**, построенный парсером; наш граф (§8.5) — граф
**заметок и записей** из ссылок и явных связей. Знаний «почему» (решений, ловушек, их устаревания)
у graphify нет, кроме комментариев `WHY`.

### 2.3. Understand-Anything (Egonex-AI/Understand-Anything)

**Назначение.** Плагин Claude Code и др.: строит интерактивный граф знаний кодовой базы с
пояснениями «простым языком», слоями архитектуры, доменом и обучающими турами; цель — ввод в
проект. TypeScript, MIT, ~89 тыс. звёзд.

**Механизмы.**
- Гибрид: tree-sitter (WASM) — импорты, определения, вызовы, отпечатки файлов для инкрементального
  обновления; LLM-агенты `project-scanner`, `file-analyzer` (параллельно, до 5 воркеров),
  `architecture-analyzer`, `tour-builder`, `graph-reviewer` — сводки, теги, слои. Промежуточные
  результаты агенты пишут в файлы (`.ua/intermediate/`), а не в контекст [README, CLAUDE.md].
- Результат — `.ua/knowledge-graph.json` (коммитится для команды), дашборд React Flow, просмотрщик
  без LLM.
- **Запрос к графу** [код, `skills/understand-chat/SKILL.md`]: навык не читает JSON целиком —
  grep по `name/summary/tags`, затем рёбра на 1 шаг, затем слои; ответ — только по подграфу.
- **Свежесть** [код]: `project.gitCommitHash` графа сверяется с `git rev-parse HEAD` и `git diff`
  по файлам проекта; при расхождении — предупреждение.
- **Влияние изменений** [код, `understand-diff`]: изменённые файлы из git → узлы по `filePath` →
  соседи на 1 шаг → затронутые слои → оценка риска (сложность, межслойные рёбра).

**Отличие от нас.** Тот же класс, что graphify: карта кода, а не память о решениях. Полезные для
нас приёмы — дешёвая проверка свежести по git-коммиту и «влияние диффа» по привязке к файлам.

### 2.4. ponytail (DietrichGebert/ponytail)

**Назначение.** Навык-промпт «пиши меньше кода»: лестница решений перед написанием кода (нужно ли
вообще → есть ли в кодовой базе → стандартная библиотека → установленная зависимость → одна строка
→ минимальная версия), пометки `shortcut:` и реестр долга. MIT, ~178 тыс. звёзд. Не система памяти
и не компрессор контекста.

**Механизмы.**
- Один промпт `skills/ponytail/SKILL.md`, адаптеры под ~20 агентов.
- `hooks/ponytail-map.js` [код]: regex-извлечение верхнеуровневых определений из `git ls-files`,
  строка на папку `dir/: name1, name2, …`, общие каталоги (util, lib, service) — первыми, бюджет
  2000 символов; цель — повторное использование существующего кода.
- `hooks/ponytail-subagent.js` [код]: хук `SubagentStart` вкалывает правила в субагентов, фильтр по
  `agent_type` regex с тайм-аутом 100 мс, fail-open.
- «Band» в статусной строке Claude Code: стоимость, токены, время, тесты по сессиям, локально.
- Измерение [код, `benchmarks/README.md`]: агентный бенчмарк — 39 задач, безголовые сессии Claude
  Code на реальных репозиториях, 5 прогонов, скрытые проверки; плечи — «без навыка», прошлая и
  текущая версия вперемешку. Авторы честно отмечают: на части задач навык повышает число вызовов и
  стоимость.

**Отличие от нас.** Пересечение только в методике: инъекция в субагентов и **агентный A/B-бенчмарк**
как способ доказать пользу, которого у нас нет (наш eval меряет поиск и токены ответов сервера, а
не исход задачи агента).

### 2.5. rtk (rtk-ai/rtk)

**Назначение.** Rust-прокси команд: хук переписывает Bash-команду агента (`git status` →
`rtk git status`), rtk выполняет её и сжимает вывод до того, как агент его прочтёт. Один бинарник,
100+ команд. CLI — Apache-2.0, движок `rtk-engine` и `rtk-proxy` — BUSL-1.1. ~85 тыс. звёзд.

**Механизмы** [код/техдок].
- `PreToolUse` → `rtk rewrite "<cmd>"` → `updatedInput`; составные команды режутся по операторам,
  в конвейере переписывается только безопасный последний этап; ошибка — команда идёт как есть.
  Встроенные `Read/Grep/Glob` хук не ловит.
- Фильтры: Rust-модули по командам (тесты — только падения, git — компактно, grep — группировка по
  файлам, логи — схлопывание повторов со счётчиком) и декларативный TOML (8 стадий: ANSI, regex,
  отбор строк, усечение, head/tail…), уровни встроенный/глобальный/проектный (с доверием).
- **Восстановление сырого вывода**: при ненулевом коде или усечении полный вывод в `recall.db`
  (gzip, адресация по хэшу), в выводе — `[full output: rtk recall <hash>]`.
- Учёт: `tracking.db` (сырой и сжатый размер, время, проект; 90 дней), `rtk gain` с историей;
  токены — `байты/4`, авторы прямо пишут, что проценты надёжны, абсолютные числа — нет, и что
  экономия на выводе Bash «размывается» в полном счёте сессии. Issue #1160: в `tracking.db` полный
  текст команд — риск для секретов.
- **`rtk learn`** [код, `src/learn/README.md`]: разбирает JSONL сессий Claude Code, ищет пары
  «команда упала → та же базовая команда прошла», классифицирует ошибку regex-ами, сливает в
  правила, пишет `.claude/rules/cli-corrections.md`; пороги `--min-confidence`,
  `--min-occurrences`. Без LLM.

**Отличие от нас.** rtk экономит токены **вывода инструментов**, мы — токены **памяти**. Он не
хранит знания. Совместим с нами: наш `pre-tool` только читает `tool_input.command` и ничего не
переписывает; при параллельных хуках `command_regex` видит исходную команду.

### 2.6. headroom (headroomlabs-ai/headroom)

**Назначение.** Слой сжатия контекста на границе с API модели: библиотека `compress(messages)`,
прокси, обёртка агента (`headroom wrap claude`), MCP. Python + Rust + TS SDK, Apache-2.0,
~78 тыс. звёзд; телеметрия-маячок включена по умолчанию.

**Механизмы.**
- Конвейер CacheAligner → ContentRouter → компрессоры: SmartCrusher для JSON (сохраняет ошибки,
  выбросы и границы по статистике разброса полей), AST-компрессор кода, модель Kompress-v2 для
  текста [README].
- **Учёт кэша промпта**: сжимается только «живая зона» (свежий вывод инструмента и последний ход),
  ранний префикс остаётся побайтно тем же; метрика `headroom_cache_bust_total` (сколько раз сжатие
  сломало кэш) [`docs/metrics-technical-guide.md`].
- **Обратимость (CCR)** [код]: вместо вырезанного — маркер `<<ccr:HASH,KIND,SIZE>>`, оригинал в
  локальном хранилище с вытеснением, модель достаёт его инструментом `headroom_retrieve`.
- Измерение: сэкономленные токены и доллары с разбивкой по источникам, «сигналы потерь» отдельно от
  экономии; экономия выходных токенов — контрфактическая, с доверительным интервалом и опциональной
  **контрольной группой 10 %** (holdout) для измеренного значения [README].
- **`headroom learn`** [код, `analyzer.py`]: сканер сессий → дайджест (до 80 тыс. токенов) → LLM →
  правила для CLAUDE.md/AGENTS.md (уверенность 0,9) и MEMORY.md (0,7) по категориям: петли повторов,
  правила окружения, факты о файлах, предпочтения пользователя, повторяющиеся сбои; требование
  «≥ 2 случая или прямое указание пользователя»; запись — управляемым блоком между маркерами.

**Отличие от нас.** Работает на другой границе (запрос к модели) и с потерями. Для нас ценны не
компрессоры, а методика учёта (holdout, cache-bust, разбивка экономии) и идея «учиться на
неудачных сессиях» — но без LLM на сервере.

### 2.7. context-mode (mksglu/context-mode)

**Назначение.** MCP-сервер и набор хуков, решающий две задачи: большой вывод инструментов не
попадает в контекст (исполнение в песочнице, в контекст — только stdout или найденные фрагменты),
и рабочее состояние переживает сжатие контекста. TypeScript, **Elastic License 2.0**, ~33 тыс.
звёзд.

**Механизмы.**
- Инструменты `ctx_execute`, `ctx_batch_execute`, `ctx_execute_file`, `ctx_index`, `ctx_search`,
  `ctx_fetch_and_index`; вывод > 5 КБ с `intent` индексируется, в ответ — только совпавшие секции.
  FTS5 (BM25, Porter, триграммы) + RRF, исправление опечаток по Левенштейну [README].
- `PreToolUse` [код]: маршрутизация `curl/wget`, `WebFetch`, крупного `Read` в песочницу (отказ или
  переадресация с причиной); MCP-инструменты субагентам не предлагаются.
- **Журнал событий сессии** [код, `extract.ts`]: детерминированно, по именам инструментов и regex,
  извлекаются ~20 категорий с приоритетом 1–5: файлы (чтение/правка), правила (чтение CLAUDE.md),
  `cd`, ошибки, git и коммиты, задачи (`TodoWrite/TaskCreate/TaskUpdate`), план, окружение,
  обнаруженные ограничения («not supported», «permission denied»), субагенты и их находки, решения
  пользователя (`AskUserQuestion`), цель, блокеры и их снятие, **«ошибка → исправление»** (успешный
  повтор того же инструмента), **«петля»** (≥ 3 одинаковых вызова подряд), стоимость.
- **Восстановление после compact** [код, `snapshot.ts`]: на `PreCompact` — XML `<session_resume>` с
  секциями `how_to_search, session_goal, files, errors, decisions, rules, git, task_state,
  environment, subagents, …, recent_user_messages` (последние 3 сообщения до 400 символов),
  в каждой секции — готовый вызов `ctx_search(queries: […])` за подробностями; на `SessionStart`
  после сжатия — «Session Guide». Заявленный «приоритетный бюджет ~2 КБ» в коде не действует:
  `priority` не читается, `maxBytes` игнорируется; сопоставление задач по позиции хрупкое.
- **Приватность** [код]: маскировка только по имени ключа во входе MCP и `export NAME=***`; вывод
  ошибок, задачи и ответы MCP хранятся как есть — секреты могут оседать в SQLite. «Ничего не
  покидает машину» соседствует с облачным Insight-дашбордом, о котором не сказано, что он получает.
- Экономия «98 %» (315 КБ → 5,4 КБ) — по сценариям, методика в README не раскрыта.

**Отличие от нас.** Память context-mode — эфемерная и сессионная (без `--continue` удаляется), без

## 5. Что сознательно не брать

- **LLM-наблюдатель и автоматическая запись в память** (claude-mem, headroom learn). Противоречит
  §2.2 и принципу 2; отправляет содержимое файлов и вывод команд во внешний LLM; у claude-mem
  маскировка секретов по умолчанию выключена, сырые входы/выходы инструментов попадают в очередь;
  записи без проверки и без `certainty` создают шум, который потом выдаётся как знание. Наш путь —
  детерминированные детекторы (п. 2, 9 таблицы) и явная запись агентом с напоминанием.
- **Сжатие вывода инструментов и прокси к API модели** (rtk, headroom, песочница context-mode).
  Другая граница и другой продукт; конфликтует с простотой и самодостаточностью; движок rtk —
  BUSL-1.1, context-mode — ELv2 (код не заимствовать). Совместимость с rtk — проверить в M6.
- **Подмена вывода инструмента (`updatedToolOutput`) и «шлюз чтения»** (запрет полного `Read`):
  вмешательство в работу агента, риск ложных выводов, нарушение fail-open.
- **Подталкивание перед каждым `Grep/Glob`**: шум, раздувание контекста (анти-цель §2.3).
- **Собственный построитель графа кода** (graphify, Understand-Anything): высокая стоимость при
  средней ценности; позже — импорт их результата, а не повторение.
- **Облачная синхронизация, телеметрия по умолчанию, хостинговые дашборды** (claude-mem cmem.ai,
  headroom-маячок, context-mode Insight): противоречат локальности и самодостаточности.
- **Хранение сырого текста команд и промптов в журналах** (rtk `tracking.db`, issue #1160;
  claude-mem сохраняет сырой промпт для FTS): наш журнал сессии — только метаданные и
  нормализованные ошибки, как уже принято для `hooks.log` (§10.3).

**Риски взятого.** Инъекция в субагентов умножает расход на их число (п. 1 — малый бюджет и
выключатель); журнал событий может накопить чувствительные пути и фрагменты ошибок (только
локально, права 0600 как у кэша хуков, срок 7 дней как у `shown-*`); подсказки на `Read` повышают
частоту показов — мерить `silence_rate` и «шумные записи» (§10.5); всё, что опирается на
`SubagentStart`, `PreCompact` и поля stdin, привязано к контракту конкретных агентов — для Codex
проверять отдельно, держать адаптер (`--agent codex`), как в §10.3.

## 5а. Решение владельца (2026-10-28)

- Пункты 1, 2, 3, 5 топ-5 — в M4.5; пункт 4 — в M6 (`2026-10-27-memory-gaps-agent-view.md` §4,
  дополнение).
- **Построитель карты кода — свой, встроенный** (вместо «не брать / импортировать результат»):
  продукт самодостаточен, сторонние проекты как зависимость или внешний процесс не используются;
  можно заимствовать код с совместимой лицензией и полностью интегрировать (перенос в Rust);
  минимум зависимостей. Этап — при планировании (предложение: M5).
- **Агентонезависимость:** `SubagentStart`/`PreCompact` — адаптеры Claude Code к общему ядру;
  для Codex и других агентов — свои события, где они есть, иначе MCP и блок инструкции.
