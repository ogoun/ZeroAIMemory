# ZeroAIMemory: протокол работы агента с памятью

Краткие правила — в блоке ZeroAIMemory в CLAUDE.md / AGENTS.md. Здесь — подробности.

## Подключение

- Адрес сервера — строка `ZeroAIMemoryUrl=` в блоке; без неё (`zam init --url-to home|local`) — `url` в `~/.zeroaimemory/config.toml` или строка `ZeroAIMemoryUrl=` в `CLAUDE.local.md`; либо `ZAM_URL`. Откуда взят — `zam status`. Токен — переменная `ZAM_TOKEN` или `~/.zeroaimemory/config.toml`; в CLAUDE.md, AGENTS.md и `.mcp.json` его нет.
- Решение — `.zeroaimemory/solution.toml` (`agent_solution_id`, `name`); его создаёт `zam init`. Все клоны с этим GUID делят одну память.
- MCP — у Claude Code `.mcp.json` со stdio-прокси `zam mcp` (его пишет `zam init`): прокси сам привязывает вызовы к сессии агента. Прочим клиентам — `zam mcp` или `<url>/mcp` (streamable HTTP, `Authorization: Bearer`, заголовок `X-Zam-Solution`); сессию передай заголовком `X-Zam-Session` или аргументом `session_id` у `memory_search`, `memory_read`, `memory_recall` — один постоянный id на сессию, до 128 символов; заданы оба и различаются — 400. Без сессии всё работает, но без пометок «уже выдавалось». Без MCP — CLI `zam`, без CLI — REST `/api/v1`.
- Хуки (`zam hook …`) `zam init` ставит для Claude Code и Codex. Прочим агентам (Cursor, Gemini CLI, Copilot, Windsurf, Cline и др.) — MCP и этот протокол: всё, что делают хуки, доступно вызовами MCP (раздел «После сжатия и для субагентов»).

## Поиск: четыре шага с экономией токенов

Каждый следующий шаг — только если на предыдущем не хватило данных. Перед задачей — `memory_search`; перед исследованием — по прошлым опытам и провалам (`insight_kinds=[experiment,failure]`), чтобы не повторить их.

0. **Кэш.** `memory_search` сначала ищет готовую выжимку. Строка `[cache] «…» — выжимка …, все актуальны` — используй её и дальше не иди. `[cache, stale: …]` — перечитай только изменившиеся источники и обнови выжимку.
1. **Карточки** (`mode=brief`): по строке на кандидата — id, путь › секция и хвост `[.82] r7 · th · 2026-10-10 14:03:22 · 340t`: оценка, ревизия, надёжность (`ax`/`th`/`hyp`), статус записи (если не `active`), дата обновления (UTC), размер источника в токенах; под строкой — фрагмент. Префиксы id: `n:` заметка, `i:` insight, `c:` changelog, `r:` релиз, `t:` термин, `k:` задача, `q:` вопрос, `v:` запись Vault. `(выдавалось)` (MCP) — уже было в сессии, перечитывать не нужно, если текст у тебя есть; `(выдавалось, в выжимке)` — карточка — источник выжимки `[cache]` этого же ответа: её текст уже в выжимке, фрагмента нет; `(seen)` — то же без фрагмента (REST, CLI, MCP с `skip_seen: true`). «возможно устарело: изменился <путь>» — файл, о котором знание, изменился после записи: сверь с кодом. Ранжируй карточки сам по смыслу задачи. Строка хвоста `> не поместилось по бюджету: N (budget_tokens B)` (перед `~N tok` в MCP) — ещё N карточек не вошли в бюджет: нужны — повтори поиск с большим `budget_tokens`.
2. **Точечное чтение** — `memory_read` одним вызовом нескольких id (до 20). Для каждого: `tier=L0|L1|L2`, `section` (путь заголовков `A > B`), `max_tokens`, `if_rev` (ревизия не изменилась — `unchanged` без текста), `since_rev` (знаешь ревизию N — получи только дифф изменений с неё). Сначала L1 или секция, полный текст — только при необходимости; длинное при дорогой модели — `focus` (раздел «Фокусное чтение»). Бюджет ответа по умолчанию — 1500 токенов. Пометка `· уже выдавалось в этой сессии` в заголовке — эту цель в этой ревизии ты уже получал целиком; текст выдан снова (повтор может быть обрезан бюджетом): пока контекст не сжимался, не перечитывай её.
3. **Выжимка** — `memory_cache_put {query, summary, sources}`: Markdown до 600 токенов со ссылками; `sources` — id (и секции) того, на чём выжимка реально основана. Сервер фиксирует ревизии источников и сам инвалидирует выжимку при их изменении. Ценное надолго — `promote` в заметку или insight.

Каждый ответ оканчивается строкой `~N tok` — это твой расход. Перед новым поиском по той же теме сначала проверь кэш. Фильтры поиска: `kinds` (задачи — только явным `kinds: [task]`), `status`, `certainty`, `insight_kinds`, `decided_by`, `file`.

## Фокусное чтение

По умолчанию `memory_read` отдаёт L2 целиком. Фокус — только по явному запросу: `memory_read {items: [{id, focus: "<что ищешь>"}]}` (то же — `tier: "focus"` с `focus`), CLI `zam read --focus "<запрос>"`.

- **Когда** — длинная запись (размер в хвосте карточки, `· 340t`, больше ≈ 600) и дорогая модель, или из большого текста нужен один факт. В остальных случаях — без фокуса.
- **Один `focus` на пачку.** Несколько целей об одном — дай им один и тот же текст `focus`: каждый отдельный текст — свой эмбеддинг, и общий срок вызова растёт.
- **Что придёт** — строка оглавления (выбранные заголовки отмечены `*`), лучшие по запросу листы в порядке документа, между ними — `[пропущено: range:r<rev>:S-E (<секции>) · ~N t]`; в заголовке — `· фокус`.
- **Дочитать пропуск** — элемент `{id, range: "r<rev>:S-E"}` с адресом из пометки (CLI `--range r<rev>:S-E`): ровно пропущенный текст той ревизии; заметка с тех пор изменилась — текст прежней ревизии с предупреждением `range: rev7, текущая rev8`. У документа пометка называет первую и последнюю часть пропуска (`page:3 — page:7`): дочитывай элементами `{id, locator: "page:N"}`; `оглавление` — часть без адреса, его даёт чтение без `locator`.
- **Целиком без фокуса**: короткая цель и запись журнала — `focus skipped: short`; цель ещё не нарезана индексом — `focus skipped: not indexed`. Модель не успела или выгружена — фокус по словам, `focus lexical`.
- `focus` вместе с `section`, `locator`, `since_rev` или `range` — 400.

## Запись

- **Заметки** — `memory_write {path, content | ops, base_rev?, message?, l0?}`; путь `[<пространство>:/]<путь>`. Без `base_rev` — создание, с ним — замена или правка. Каждой заметке — `l0`: однострочная сводка. **Проверенные команды** (сборка, тесты, деплой, которые реально сработали) — заметки с `verified_at: ГГГГ-ММ-ДД` (и `verified_at_commit: <sha>`) во frontmatter: дайджест старта показывает их строкой «Проверенные команды», а возраст считается от даты проверки. Перепроверил — обнови `verified_at`. `idempotency_key` — повтор того же вызова после сбоя связи не пишет второй раз (тот же ключ с другим телом — 422).
- **Журналы** — `memory_log {kind, …}`:
  - `changelog` — изменение проекта (что и зачем);
  - `insight` — открытие: `gotcha` (ловушка), `failure` (провал), `experiment` (с результатом), `discovery`, `decision` (решение, см. ниже); `scope=global`, если знание не про этот проект. `triggers` — когда показать подсказку: массив объектов `{type, pattern, tools?}`, `type` — `file_glob` (маска пути), `command_regex`, `error_regex` (regex без обратных ссылок и lookaround) или `keyword`; `tools` — инструменты агента (`Bash`, `Edit`…; нет — любые); до 32 на запись: `triggers: [{type: "file_glob", pattern: "**/*.sh"}, {type: "error_regex", pattern: "bad interpreter", tools: ["Bash"]}]` (строка вместо объекта — 422). В CLI — `zam log insight --trigger ВИД:ШАБЛОН` (`--trigger file_glob:**/*.sh`, повторяемый); широкий или неверный триггер — `action=triggers` (набор целиком), замещать запись не нужно: `memory_update_entry {id, rev, action: "triggers", triggers: […]}`, `[]` — снять все; CLI — `zam insight triggers <id> --trigger ВИД:ШАБЛОН` (повторяемый) или `--clear`. Опыт `experiment` — `data.experiment: {hypothesis?, method?, result: confirmed|refuted|inconclusive}` (строка вместо объекта или иной `result` — 422). После исправления ошибки запиши `gotcha`/`failure` с `error_regex` — хук напомнит об этом, если заметит пару «ошибка → исправление». **`theorem` от агента** — только с доказательством `data.evidence: {checked, method, result}`: объект из трёх непустых строк — что проверено, каким методом, с каким итогом (строка — 422 «ожидается объект», без доказательства — 422 `evidence-required`); у `certify` в `theorem` — в `data` вместе с прежними полями (`data` insight заменяется целиком); в CLI — `--evidence-file` (JSON-файл с этим объектом) у `zam log insight` и `zam insight certify`. **Отверг подход после проверки** — запиши `insight` с `kind: decision`, поля решения — внутри `data.decision`: `data: {kind: "decision", decision: {options: [<отвергнутое>], chosen, rationale: "отвергнуто, потому что…"}}` (`options`, `chosen`, `rationale` на верхнем уровне `data` — 422, даже рядом с `data.decision`). Или `failure` с результатом. Сжатие контекста эти подробности теряет первыми;
  - `release` — релиз: `data: {version (обязательна, 1–64), date?: YYYY-MM-DD, git_tag?, commits?: [{sha, subject?}]}`; CLI — `zam release add`;
  - `term`, `task`, `question`, `idea` — словарь, задачи, вопросы человеку, идеи (разделы ниже).
- **Правка записи** — `memory_update_entry {id, rev, action}` (409 — перечитай): `supersede` (замена новой), `retract` (отзыв с причиной), `revisit`, `certify`, `append`, `triggers`, `feedback`; у задач — `status`, `claim`, `release`, у вопросов — `answer`, у идей — `propose`, `decide`, `review` (раздел «Идеи»). `rev` обязателен (кроме `feedback`, `claim`, `release`, `answer`, `propose`, `decide`, `review`): без него — 428, при чужой правке — 409 с текущей ревизией. На 409/428 перечитай запись и повтори.
- **Связи** — `memory_link {src, type, dst}`: `links_to`, `relates_to`, `depends_on`, `part_of`, `caused_by`, `fixes`, `derived_from`, `mentions`, `contradicts`.
- **Секреты** — только `memory_vault` (`get | set | list | rename | move | delete`). Значения не попадают в поиск, выжимки и журналы; не копируй их в заметки.
- Ответ записи может нести `warnings` (`term_alias`, `decision_near_axiom` и др.) — прочитай и при необходимости поправь запись.
- **Отчёт для пользователя** — `zam report` (раздел «Отчёты»).

## Отчёты

Отчёт — итог работы **для пользователя**: исследования, эксперимента, обучения модели, сравнения вариантов (или по его просьбе). Пользователь читает его в WebUI (журнал «Отчёты» решения) с формулами, диаграммами Mermaid, таблицами, кодом и картинками и выгружает в PDF.

- **Записать** — `zam report <файл.md> [--title T] [--tag X]… [--area A] [--ref commit:<sha>|file:<путь>|note:<id>|task:k:<id>]… [--key K]`. Без `--title` — первый заголовок `#` файла. Ответ — `Отчёт: <url>`: передай ссылку пользователю.
- **Картинки и файлы** — относительные ссылки от каталога файла: `![кривая](figs/loss.png)`, `[данные](data/run.csv)`; путь с пробелом — `<figs/my plot.png>` или `%20`. CLI загружает их одним запросом с телом. Картинки — PNG, JPEG, WebP, GIF, SVG; прочие файлы — для скачивания. Нельзя: `..`, абсолютный путь, `\`, внешняя или `data:` картинка, `![[…]]`, ссылка на каталог (`[код](src/)`); файл без ссылки из тела не принимается.
- **Ссылки** — схемы `http`, `https`, `mailto`, `vscode`, `file` (прочие `zam report` отклоняет до отправки); у картинки схемы `vscode:` и `file:` нельзя (422). Переход в WebUI — только по `http`, `https`, `mailto` и `vscode://file/…`; `file:` и прочие `vscode:` — текстом; кнопка «копировать путь» — у `file:` и `vscode://file/…`.
- **Ссылка на код** — `vscode://file/<абсолютный путь>:<строка>`, путь нормализованный, через `/`: `vscode://file/home/u/proj/src/a.rs:10`, `vscode://file/C:/proj/src/a.rs:10`. Без второй косой после `file/` (`vscode://file//home/…` — сетевой путь), без сегментов `.` и `..` и без кодированных разделителей и точек (`%2F`, `%5C`, `%2E`, `%252F`) — иначе ссылка не кликается. В пути без пробелов и знаков оболочки — иначе нет и «копировать путь».
- **Лимиты** — до 64 файлов, всего до 200 МиБ; один файл — до предела блоба сервера.
- **MCP** — `memory_log {kind: "report", title, body, images: [{name, data}]}`: `name` — путь из ссылки тела, `data` — base64; тело с файлами — до 16 МиБ, больше — `zam report`.
- **Неизменяем** — исправить или дописать нельзя: повтор — новый отчёт. `--key K` (`idempotency_key`) защищает от дубля при повторе той же команды.
- **Агент отчёты не читает** — их нет в поиске, `memory_read`, дайджесте и подсказках. Выводы, нужные тебе в следующих сессиях, пиши отдельно в `insight` (`experiment`, `failure`, `decision`).

## Задачи и передача работы

Задача (`task`) — состояние работы, которое переживает сжатие контекста, смену сессии и агента.

- **Создать** — `memory_log {kind: "task", title, body: план, data: {next_step?, owner?: agent|human, estimate_min?, links?}}` → `k:<id>`; статус при создании не задаётся: `data.status` — 422, новая задача — `open`, дальше — `action: "status"` (CLI `zam task status`). CLI: `zam task new`.
- **Взять в работу** — claim перед работой: `memory_update_entry {id: "k:<id>", action: "claim", ttl_min?}` (по умолчанию 120 мин, до 1440). Чужой живой захват — 409 `task-claimed` с `claimed_by`: не дублируй работу, выбери другую задачу или спроси человека. Захват рекомендательный, он не запрещает правку. Закончил или бросил — `release`.
- **Ход работы** — `memory_update_entry {id, rev, action: "status", status: in_progress|blocked|done|dropped, next_step?, blocked_by?}`. Обновляй `next_step` после каждого заметного шага: это первое, что увидит следующая сессия. `blocked` — с `blocked_by`. `done`/`dropped` сами снимают `next_step` и `blocked_by` (прежние — в истории; явный `next_step` в том же вызове остаётся) — «—» вместо шага не нужен. Из `done`/`dropped` — только переоткрытие в `open` с `reason`.
- **Дайджест старта** показывает раздел «Задачи»: `in_progress` и `blocked`, захваченные этой сессией — первыми. Продолжай с `next_step`.
- **Оценка сроков** — по фактическим длительностям похожих задач: у закрытых задач есть `duration_min` (`zam task list --status done`, REST `GET /spaces/{space}/entries?kind=task&status=done`); найти похожие — `memory_search {filters: {kinds: [task], status: [done]}}`.
- Перед завершением с правками хук напомнит обновить `next_step` захваченной задачи.

## Вопросы человеку

Вопрос (`question`) — то, что решает только человек. Ответ становится решением в памяти.

- **Задать** — `memory_log {kind: "question", title: вопрос, body: контекст, data: {options: [{key, text}] до 8, recommendation?: key}}` → `q:<id>`. Тот же вопрос уже открыт или отвечен — 409 `possible-duplicate` с кандидатами: прочитай ответ, не задавай заново. Открытые вопросы видны в дайджесте.
- **Ответ из WebUI** (страница «Вопросы») человек даёт сам; ответы за 14 дней приходят в дайджест разделом «Ответы человека».
- **Ответ в чате.** Человек ответил тебе в диалоге — запиши: `memory_update_entry {id: "q:<id>", action: "answer", option? | text?, by: "human", channel: "chat"}` (вопроса ещё нет — сначала задай его). `by` обязателен: без него — 400 `by-required`. `by: human` — решение получает `certainty: axiom`. CLI: `zam question answer q:<id> --option … --by human|agent --channel chat`.
- **`by: human` — только если человек действительно ответил.** Решил сам (человек не ответил, поручил выбрать тебе, ответ — твой вывод) — `by: agent`: решение получит `hypothesis`. Не приписывай человеку свой выбор.
- Сервер в одной операции: вопрос → `answered`, новый insight `decision` («вопрос → ответ») со связью `derived_from`; `decision_id` — в ответе.
- **Неактуален** — `memory_update_entry {id, rev, action: "status", status: "obsolete", reason}`.

## Идеи

Идея (`idea`, ссылка `w:`) — то, что человек хочет сделать, но ещё не запустил. В отличие от задачи у идеи нет плана, `next_step` и захвата: работа по идее идёт в задаче `k:`, которую заводит разбор с исходом «в план» (режим `review`) или ответ человека «начать» (режим `propose`).

- **Записать** — `memory_log {kind: "idea", title, body: замысел, data: {origin, priority?, horizon?, links?}}` → `w:<id>`; CLI `zam idea new`. `origin` обязателен: диктовка «запиши идею …» → `origin: human`; своя мысль на будущее (например, отложенное замечание ревью) → `origin: agent` — такую идею не разбирают и не предлагают, человек принимает её как свою в WebUI. `priority` — `low|normal|high`, `horizon` — дата «не раньше» (`ГГГГ-ММ-ДД`, UTC). Идею человека не переписывай (только `append`) и не удаляй.
- **Режим** — `ideas.mode` (WebUI «Подключение агента → Подсказки хуков»: «Идеи: разбирать сам / предлагать мне»): `review` (по умолчанию) — новые идеи человека разбираешь сам (подраздел «Разбор идей»); `propose` — предлагаешь их человеку, решает он (пункты ниже). В общем решении действует режим его владельца. Разбор в режиме `propose` и `propose` новой идеи человека (`new`) решения в режиме `review` — 409 `/problems/idea-mode` (общую идею Knowledge по просьбе человека предлагать можно).
- **Предложить** (режим `propose`; в режиме `review` — только отложенную идею с наступившим `horizon` и принятую со снятой задачей: есть очередь разбора — они приходят строкой с `action=propose` в разделе `### Идеи на разбор` после её идей, очереди нет — разделом `### Идеи`, как ниже). Идеи приходят разделом дайджеста `### Идеи` (до 3, только на первом старте сессии) и строкой подсказки «к задаче подходит идея» к запросу. Предложи человеку одну: `memory_update_entry {id: "w:<id>", action: "propose", text?: почему сейчас}` (action=propose) — сервер задаёт вопрос `q:` с вариантами «начать / отложить / отказаться». Одна идея — один показ за сессию; отказанные и отложенные до `horizon` не приходят.
- **Ответ в чате** — `memory_update_entry {id: "q:<id>", action: "answer", option, by: "human"}`: `option` — `accept` (начать), `defer` (отложить), `decline` (отказаться); «отложить до …» — ещё `horizon`. Решение без вопроса — `action: "decide", decision: accept|defer|decline|reopen`. Решает человек: `by: human` — только его слова; `by: agent` — только `decline` своей идеи. CLI: `zam idea accept|defer|decline w:<id> --by human --channel chat` (решение человека из чата — всегда с `--channel chat`).
- **Без ответа «начать» не начинай** (режим `propose` и любая идея, которую ты предложил вопросом). «Начать» одной операцией создаёт задачу `k:` со связью `derived_from` на идею — дальше работай по протоколу задач; задача `done` — идея тоже `done`.
- **Вернуть.** Идею с пометкой «задача снята» можно предложить вернуть: propose с объяснением, почему сейчас (`text` обязателен; у удалённой задачи пометка «задача удалена»); решает человек. Сервер задаёт вопрос «вернуть / отказаться» — `option`: `reopen` или `decline`.
- **Общие идеи Knowledge** не разбирай и сам не предлагай: только по просьбе человека (`memory_search {filters: {kinds: [idea]}}`, CLI `zam idea list --global`) или при явной связи с текущей работой — тогда подсказку пришлёт сервер.
- **Выключатель** — `ideas.proactive` (WebUI «Подключение агента → Подсказки хуков»): выключен — ни раздела, ни подсказок идей, ни строки плана; явный пакет `idea_review` работает.

### Разбор идей

Режим `review` (по умолчанию): решение по новой идее человека («Непросмотрено», `new`) принимаешь ты; человек видит в WebUI исход и разбор и может с ними не согласиться.

- **Когда.** Дайджест старта (первый `session_start` сессии) приносит раздел `### Идеи на разбор` — строку «Непросмотренных идей: N. Разбери, когда закончишь текущий шаг: memory_recall event=idea_review → memory_update_entry action=review.» и до 3 идей (`high` первыми, затем самые старые); к запросу — подсказка «к задаче подходит идея на разбор w:<id>», а идея очереди, ещё не показанная в этом контексте (записанная человеком посреди сессии; после сжатия контекста — снова), — строкой «новая идея на разбор «…» w:<id>» к любому запросу человека, и к короткой реплике («продолжай»); « (ещё N)» — столько ещё таких идей в очереди. Разбирай, когда закончишь текущий шаг: не посреди ответа человеку и не бросая начатое.
- **Шаги:**
  1. **Пакет** — `memory_recall event=idea_review` (`{event: "idea_review", limit?}`, `limit` 1–20, по умолчанию 5), CLI `zam idea queue [--limit N]`: текст идеи, прежние разборы и доводы человека, до 5 похожих записей решения (идеи любого статуса — у отклонённых строка причины, задачи, changelog, решения, заметки) и строка шагов; в конце — «Показано идей на разбор: k из N».
  2. **Сверка** — с планом (открытые задачи), ТЗ и спецификациями репозитория (их читаешь сам), сделанным (changelog, задачи `done`, код), похожими и отклонёнными идеями; пакета не хватает — `memory_search`.
  3. **Решение и разбор** — `summary` для человека (Markdown, от `ideas.review_min_chars` сервера — по умолчанию 200 — до 8000 символов): что просит идея; что уже есть в плане, ТЗ и сделанном (со ссылками); решение и почему. Исход `outcome`:
     - `plan` — в план: план шагов — в теле задачи (`task: {title?, body, priority?}`, `priority` — `low|normal|high`, по умолчанию приоритет идеи); идею уже покрывает незакрытая задача плана — `task: {id: "k:<id>"}`, новой задачи нет;
     - `return` — на доработку: в `missing` — конкретные вопросы человеку (обязательно, до 2000 символов);
     - `decline` — отклонить: `summary` и есть причина, прежнее решение — ссылкой в `basis`;
     - `done` — уже сделано: в `basis` — хотя бы одна ссылка на сделанное (`c:`, `r:`, `commit:<sha>`, `k:` задачи `done`).
  4. **Повтор отклонённой** без новых доводов — `decline` со ссылкой на прежнюю идею в `similar`.
- **Вызов** — `memory_update_entry {id: "w:<id>", action: "review", outcome, summary, missing?, basis?, similar?, task?, idempotency_key?}` (без `rev`); CLI `zam idea review w:<id> --plan|--return|--decline|--done --summary-file F [--missing T] [--basis ID]… [--similar w:ID]… [--task k:ID | --task-title T --task-body-file F --task-priority P] [--key K]`. `basis` — на что опирался: `k:`, `n:`, `i:`, `c:`, `r:`, `t:`, `q:`, `w:` (живые записи и заметки пространства идеи), `file:<путь от корня решения>`, `commit:<sha>` (от 7 знаков); `similar` — только идеи `w:`; неверная или несуществующая ссылка — 422. `missing` — только у `return`, `task` — только у `plan`, иначе 422. `idempotency_key` — на один разбор: повтор того же вызова после сбоя связи не заводит вторую задачу; другому разбору — новый ключ.
- **Что делает сервер** — одной операцией: `plan` — задача `open` (заголовок — `task.title` или заголовок идеи, в теле — строка «Идея: w:<id>») со связью `derived_from` на идею, идея `accepted` («В плане»); `return` — `returned` («На доработку»); `decline` — `declined` («Отклонена»); `done` — `done` («Сделано»). Разбор со ссылками `basis` и `similar` — в `data.review` идеи, история разборов — в `data.reviews` (вместе с текущим, новый первым, до 10); человек видит их в карточке идеи.
- **Что не разбирать.** Только идеи человека (`origin: human`) в статусе `new` в пространстве решения: идея «от агента» — 409 `/problems/idea-agent-origin`, не `new` (уже разобрана, в том числе другой сессией, или решена человеком) — 409 с `code: transition-not-allowed`, Knowledge — 422. Решение человека («Начать», «Отложить», «Отказаться») не пересматривай.
- **Дальше решает человек.** Возвращённую он дописывает — она снова `new`: разбери заново (история разборов — в пакете). Его слова из чата к возвращённой идее дописывай с `by: human` — `memory_update_entry {id: "w:<id>", action: "append", rev, body, by: "human"}` (CLI `zam insight append w:<id> --by human`): она снова `new`; своя дописка (без `by`) статус не меняет. Отклонённую удаляет, оставляет или возвращает на разбор с доводом — она снова `new`, довод — в пакете. Идею человека не удаляй.
- **Пункты плана из идей** — обычные задачи. Дайджест показывает строку «План из идей: N открытых, следующая — k:<id> «…» [<priority>]» (следующая — только среди `open`: по `priority`, затем самая старая; все пункты в работе или заблокированы — без «следующая»). Возьми следующий пункт сам, когда закончишь текущую работу (задача `done` или сессия без захваченной задачи, и человек не дал другой работы — данная им работа и есть текущая), — по протоколу задач: `claim`, `status`, `next_step`. Посреди другой задачи план не начинай. Человек может снять или отложить пункт в «Задачах», пока ты до него не дошёл.

## Словарь

Термин (`term`) — каноническое имя понятия проекта или домена.

- **Новое понятие** — `memory_log {kind: "term", title: имя, data: {definition (до 300 символов, обязательно), aliases?, not_to_confuse?, code?: [идентификаторы]}}` → `t:<id>`. Имя или псевдоним занят другим действующим термином — 409 `term-conflict`: уточни или замени прежний (`supersede`).
- **Пиши каноническими терминами.** Псевдоним вместо имени в записи — предупреждение `term_alias: «псевдоним» → «имя»`.
- Псевдоним короче 3 букв или цифр или служебное слово — предупреждение `term_alias_broad: «псевдоним» — …` (термин записан): такой псевдоним срабатывает на посторонних словах — замени его точнее.
- Аббревиатура (`MCP`, `ZAM`) сравнивается с учётом регистра, прочие имена — без: чтобы термин находился и по «mcp», добавь псевдоним строчными.
- Поиск сам расширяет запрос псевдонимами (`expanded` в ответе); `[[Имя]]` в заметке без заметки с таким именем ссылается на термин. Словарь — `memory_search {filters: {kinds: [term]}}`, CLI `zam glossary [<термин>]`; встреченный в промпте термин приходит подсказкой с определением.

## Решения и противоречия

- **Решение (ADR)** — `memory_log {kind: "insight", data: {kind: "decision", decision: {context?, options?, chosen?, rationale?, consequences?, decided_by?: human|agent, revisit_if?}}}`. Решения человека — `filters.decided_by: human`.
- **Достоверность** `certainty`: `axiom` — принятая истина, `theorem` — доказано или проверено, `hypothesis` — предположение. Меняется с `reason`.
- `axiom` ставь, правь и снимай **только по прямому указанию пользователя**. Если по своему выводу считаешь иначе — запиши `hypothesis` или `theorem` с возражением и доказательствами, свяжи её с аксиомой связью `contradicts` (`links` записи или `memory_link {src: <твоя запись>, type: "contradicts", dst: <аксиома>}`) и сообщи пользователю. Так же возражай `theorem`: `hypothesis` с `contradicts` к ней. Выдача не ставит запись выше действующей более надёжной записи (`theorem`/`axiom`), которой она противоречит.
- `warnings: ["decision_near_axiom: i:<id> …"]` при записи решения — рядом уже есть аксиома на ту же тему: проверь, не противоречишь ли ей.

## Ссылки на файлы

- Знание о коде привязывай к файлам: `refs: {files: [{path}]}` в `memory_log` и `memory_update_entry` (`supersede`, `append`); у заметок — `refs:` (список путей) во frontmatter. Путь — относительно корня решения, через `/`. CLI `zam log … --ref <путь>` и `zam write --ref <путь>` сами добавляют хэш содержимого и коммит.
- Файл изменился после записи — ссылка становится `stale`, карточка — «возможно устарело: изменился <путь>». Сверил, знание верно — `zam refs verify <путь>` (или перезапиши запись с теми же путями); неверно — `supersede`.
- «Что память знает о файле» — `memory_search {filters: {file: "<путь>"}}`, CLI `zam links file:<путь>`. С хуками подсказка о файле приходит сама при чтении и перед правкой. `zam refs check [--since <commit>]` сверяет все ссылки решения с рабочей копией.
- Знание об одной функции — ссылка на символ `путь#Тип::метод` (раздел «Карта кода»): она не устаревает от правки соседнего кода.

## Карта кода

Карта кода решения — файлы и символы (функции, методы, типы) с сигнатурами, упорядоченные по связям (PageRank по ссылкам между файлами). Строит её клиент `zam` (tree-sitter: Rust, TypeScript/TSX, JavaScript/JSX, Python, Go, Java, C#), хранит сервер. Знания памяти по-прежнему ищет `memory_search`: символов нет в поиске, подсказках и выжимках.

- **Когда звать** — перед работой в незнакомой части кода, перед правкой с неясными последствиями, когда нужно найти, где определено имя. Не читай ради ориентации файлы целиком — сначала карта.
- **Карта** — `memory_code {action: "map", focus?, budget_tokens?, path?}`, CLI `zam code map [--focus <путь|имя>]… [--task <текст>] [--tokens N]`: ключевые файлы и символы с сигнатурами в бюджете (по умолчанию 1000 токенов; в конце — `~N tok`). `focus` — `{paths: [файлы задачи], idents: [имена], text: "текст задачи"}` (`text` до 2000 символов): карта поднимает эти файлы и то, на что они ссылаются. `path` — только поддерево. `warning: rank pending` — ранги пересчитываются, карта — по прежним.
- **Символ** — `memory_code {action: "symbol", query: "имя" | "путь#qual", path?}`, CLI `zam code sym <имя|qual>`: одно точное совпадение — карточка (определение, сигнатура, кто ссылается, на что ссылается файл, привязанные знания), несколько — список адресов `путь#qual`; уточни `path` или адресом. `refs`, CLI `zam code refs` — только кто ссылается (файлы и число ссылок по имени).
- **Влияние правки** — `memory_code {action: "impact", path | files: [{path, symbols?: [{qual, body_hash}]}]}`; CLI `zam code impact [--since <commit>]` сам считает хэши рабочей копии. Ответ — изменённые и удалённые символы, файлы-потребители на 1 шаг и знания, которые стоит перепроверить; путь без хэшей символов — все знания о пути.
- **Ссылка на символ** — `путь#Тип::метод` (`qual` из карты или карточки, контейнер через `::` во всех языках): `refs: {files: [{path: "src/a.rs#Foo::bar"}]}` в `memory_log`, `refs: ["src/a.rs#Foo::bar"]` во frontmatter заметки, `zam log … --ref src/a.rs#Foo::bar`. Такая ссылка устаревает только при изменении тела этого символа — `stale` с причиной `symbol_changed`, символ удалён или переименован — `symbol_removed`; правка соседней функции её не трогает (ссылка на файл устаревает от любой правки файла).
- **Синхронизация** — `zam code sync` (`--full` — заново): отпечатки файлов, на сервер — только изменённые. С хуками Claude Code и Codex карта синхронизируется сама в фоне из `session-start` и `checkpoint` — не чаще `code.auto_interval_min` (30 мин) или при смене `HEAD`; дайджест старта показывает строку «карта кода: N файлов, M символов…». `zam code status` — снимок, пропущенные файлы с причинами.
- **Выключатели** — тип подсказок `code_map` (`[hooks] code_map` клиента, «Подсказки хуков» в WebUI): гасит строку дайджеста, раздел `### Код` пакета субагенту и автосинхронизацию; явные `memory_code` и `zam code` работают. `code.auto = false` — без автосинхронизации, `code.enabled = false` — без карты.
- **Что уходит на сервер** — путь, язык, хэш файла; у символов — имя, `qual`, вид, строки, хэш тела; ссылки, агрегированные по именам. Тела кода не уходят никогда. Сигнатура (первая строка определения, до 160 символов; секреты сервер маскирует) — только при `code.send_signatures = true` (по умолчанию); `false` — карта из имён и видов.

## После сжатия и для субагентов (без хуков)

С хуками Claude Code и Codex это происходит само: `SessionStart` с `source: compact | resume` приносит пакет восстановления со сводкой журнала сессии, `SubagentStart` — пакет под задачу субагента. Без хуков (или если пакета нет в контексте) вызывай сам:

- **В начале работы** — `memory_recall {event: "session_start"}` (дайджест).
- **После сжатия контекста или возобновления** — `memory_recall {event: "recovery"}`: задачи с `next_step`, ответы человека, решения за 7 дней, затем дайджест. Продолжай с `next_step` захваченной задачи.
- **Задание субагенту** — вызови `memory_recall {event: "brief", task: "<задание>"}` и вложи пакет в задание; в само задание добавь строку «первым вызовом — `memory_recall {event: "brief", task: …}`». Пакет: правила, решения с `axiom`/`theorem`, термины, ловушки и знания о файлах из задания.
- **Перед новым типом файла и после ошибки** — `memory_recall` (`prompt` или `post_tool` с текстом ошибки).
- Пометки «уже выдавалось» и `(выдавалось)` после сжатия без хуков обнуляет вызов `recovery` (новая эпоха сессии) — вызови его, прежде чем полагаться на пометки.
- Срок сбора — `timeout_ms`, не больше `max(recall.max_timeout_ms, recall.timeout_ms)` (`recall.max_timeout_ms` — 2000 по умолчанию), больше — 400. По умолчанию явный вызов (MCP; `brief`, `recovery`, `idea_review` из REST и `zam` без `code_map`) ждёт этот предел, остальные (хуки, REST `session_start`, `prompt`, `post_tool`) — `recall.timeout_ms` сервера; не уложился — собранное и предупреждение `recall timeout`. Своему клиенту MCP передай сессию (`session_id`) и версию блока `agent_block_version` — номер N из маркера `<!-- zeroaimemory:begin vN -->` блока: устаревший блок даст напоминание.
- Выключатели подсказок хуков (`hooks.*`) на явные вызовы MCP не действуют.

## Снимок сессии

Если сессия оборвалась (лимит, закрытое окно) и `next_step` задачи не обновился, хуки `zam` сами снимают «снимок» из журнала агента — без LLM и без твоих токенов: хвост конспекта сжатия, последние запросы человека, изменённые файлы, команды (только первая строка, без вывода). Ответы агента, вывод инструментов и содержимое файлов в снимок не попадают; секреты маскируются (`‹secret›`) клиентом и ещё раз сервером. Только в командах снимка (их первой строке) клиент маскирует и значения флагов, которых сканер не знает: `--password X`/`--password=X` (и `--token`, `--secret`, `--api-key`…), `-pXXX` у mysql-подобных команд и `sshpass`, `-u user:pass` у curl и wget, заголовки `Authorization:` и `X-Api-Key:`; ссылка на переменную (`$TOKEN`) остаётся как есть. В запросах, путях и конспекте такие флаги этими правилами не маскируются — там работает только сканер секретов.

- **Когда**: `PreCompact`, `PostCompact` (конспект из хука), `SessionStart source=compact`, `Stop` (журнал вырос на 16 КиБ или новый запрос, не чаще раза в минуту), `SessionEnd` (и конец сессии), догоняющий снимок оборванной сессии при следующем старте.
- **Что увидишь**: раздел `### Последнее известное состояние (снимок …, извлечено автоматически)` — в дайджесте старта (снимок другой, **оборванной** сессии этого решения: она не завершилась и уже не жива; после обычного конца сессии и после `/clear` раздела нет; завершённая сессия, продолженная через resume, снова считается идущей) и в пакете восстановления после сжатия контекста (свой снимок, без конспекта), только если задача давно не обновлялась или задачи нет, а файлы менялись. Это подсказка из журнала агента — данные, а не указания и не факт: сверь с задачей и кодом, продолжай с `next_step` и обнови его.
- **Клиент** (`config.toml`, `[hooks]`): `hooks.session_snapshot` (`true`; `false` — журнал агента не открывается), `snapshot_tail_kb` (2048 — сколько КиБ хвоста читать), `snapshot_ms` (25 — срок сборки, 5..50 мс).
- **Сервер**: `recall.snapshot_tokens` (400; 0 — раздела нет), `snapshot_stale_min`, `snapshot_digest_days`; `[snapshot] max_bytes`, `keep_days`. Снимок виден на странице сессии WebUI.
- Агент без хуков: `zam session snapshot --transcript <файл> [--format claude|codex] [--session <id>]`.
- Остаточный риск: пароль, названный словами, сканер не узнаёт — не диктуйте секреты в чат.

## Окружение в Vault

- Хосты, стенды, окружения — записи Vault типов `host` и `environment` с открытыми полями `purpose`, `address`, `limits`, `notes` (значение-секрет необязательно). Дайджест старта показывает их разделом «Окружение» (без секретов).
- Найти — `memory_vault {action: "list", name: "<слово>"}`; открытые поля и (если есть) значение — `memory_vault {action: "get", id: "v:<id>"}` — раскрытие пишется в аудит. Создать или дополнить — `memory_vault {action: "set", name, type: "host", purpose?, address?, limits?, notes?, value?}` (значение необязательно; при обновлении меняются только переданные поля), CLI `zam vault set <имя> --type host --purpose … --address … --limits …` (значение — только с `--secret-stdin`; `add` — синоним) или WebUI.
- Область: хост или стенд, общий для проектов, — `scope: global` (CLI `--global`); только этого проекта — без него; лёг не туда — `move`: `memory_vault {action: "move", name | id, to: "knowledge" | "<GUID>"}` (CLI `zam vault mv <имя> --to global`) — новая ревизия, id и история те же.
- Переименовать — `memory_vault {action: "rename", name | id, new_name}` (CLI `zam vault rename`); удалить — `memory_vault {action: "delete", name | id}` (CLI `zam vault rm`; имя есть и в решении, и в личном Vault — ошибка со списком: укажи `scope` или `v:<id>`): удаление мягкое, ревизии и аудит остаются; удаляй только свою ошибочную запись или по просьбе человека.
- Узнал важное об окружении (адрес, ограничения стенда) — запиши в Vault, а не в заметку; пароли и ключи — только значением записи.

## Проактивное вспоминание

- Строки `ZeroAIMemory: …` и разделы `### …` дайджеста в контексте — подсказки из памяти: правила, ловушки, прошлые сбои, задачи, ответы человека, знание о файле. Учитывай их, при необходимости читай по id.
- **Правила** (`### Правила`) — строка `<путь> [надёжность] n:<id>` и текст правила под ней. Не влезли в канал — сокращены до строки `<путь> — <первая фраза> [надёжность] n:<id>` («…» — обрезано), а если места нет и для фразы — до `<путь> … [надёжность] n:<id>` (текст опущен): полный текст — `memory_read n:<id>`; строка «не показано — правил: N» — остальные в `memory_tree` Rules. В пакете субагенту правила — такими же строками L0.
- **Индексы** — изменения (`changelog`) и записи к пересмотру (`revisit`) приходят строкой `<ссылка> «заголовок» · Nt` (N — размер записи в токенах): читай по ссылке, только если нужно. Корни решения — путь и L0.
- С `hooks.checkpoint_impact = true` (клиент) перед завершением хук добавляет до 3 строк «правка затрагивает `<путь>[#символ]` → i:<id> «…»» — знания, которые правка могла сделать неверными: перепроверь и подтверди (`zam refs verify`) или замени (`supersede`).
- С хуками (`zam hook …`, их ставит `zam init`) подсказки приходят сами: в начале сессии (дайджест), по промпту, перед правкой файла или командой, при чтении файла, после ошибки, при старте субагента. Повтор той же ошибки в третий раз — подсказка проверить память. Перед завершением хук напомнит записать итог, если были правки, а записей в память не было.

## Пространства

- Решение (GUID из `solution.toml`) — память проекта; Knowledge — общие знания пользователя; Rules — правила, которые читаются в начале каждой сессии (запись агентом — если её разрешил администратор); Human — заметки человека, агенту недоступны.
- Чужое решение по GUID — запрос доступа владельцу; пока он не подтверждён, запись даёт 403.

## Блок инструкции

Блок в CLAUDE.md / AGENTS.md помечен `<!-- zeroaimemory:begin vN -->`. Если сервер сообщил, что блок устарел, — обнови его: `zam init` (или WebUI «Подключение агента»). Текст вне блока `zam init` не трогает; повторный `zam init` заменяет прежние хуки ZeroAIMemory новыми.
