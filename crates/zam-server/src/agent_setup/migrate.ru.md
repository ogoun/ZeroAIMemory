# Задание: перенести проект в память ZeroAIMemory

Перенеси в память всё, что накоплено по проекту: память агента, историю сессий, указания и решения владельца, ловушки, задачи, термины, документацию, карту кода, — чтобы новая сессия любого агента продолжала работу по памяти. Решение: {solution}. Сервер: `{url}`. Работа долгая и дорогая по токенам: читай целенаправленно, пиши пачками; вопросы владельцу копи для отчёта, не останавливайся.

## 1. Подключение

- Сначала — `zam guide`: протокол (виды записей, поля, ошибки); задание на него опирается.
- `zam status` из корня проекта показывает решение и блок — проект подключён, переходи к п. 2. Иначе — `{init}`. Адрес и токен `zam` берёт из `~/.zeroaimemory/config.toml`; в задании токена нет: не найден — попроси владельца выполнить `zam init` со страницы «Подключение агента» или задать `ZAM_TOKEN`.
{?claude}- Существующий `CLAUDE.md` сохраняется: `zam init` добавляет только блок. Адрес сервера не должен попасть в git — `--url-to local` (адрес — в `CLAUDE.local.md`, его `zam init` исключает из git сам).
{?codex,agents}- Существующий `AGENTS.md` сохраняется: `zam init` добавляет только блок. Адрес сервера не должен попасть в git — `--url-to home` (адрес — в `~/.zeroaimemory/config.toml`).
{?claude}- В `.git/info/exclude` — неотслеживаемые `/.mcp.json`, `/.claude/settings.json`, `/.zeroaimemory/`. Отслеживаемый файл, изменённый `zam init` (`CLAUDE.md`, `.claude/settings.json`), не коммить — вопрос владельцу.
{?codex}- В `.git/info/exclude` — неотслеживаемые `/.codex/hooks.json`, `/.zeroaimemory/`. Отслеживаемый файл, изменённый `zam init` (`AGENTS.md`, `.codex/hooks.json`), не коммить — вопрос владельцу. MCP Codex — в `~/.codex/config.toml`, образец печатает `zam init`.
{?agents}- В `.git/info/exclude` — неотслеживаемый `/.zeroaimemory/`. Изменённый `zam init` отслеживаемый `AGENTS.md` не коммить — вопрос владельцу. MCP своего агента подключи по `zam guide` («Подключение»).
- Инструменты MCP `memory_*` появляются при старте сессии. Нет их — CLI `zam` (`zam <команда> --help`) или пачка через stdio `zam mcp` из корня: строки JSON-RPC `initialize` (`protocolVersion` `2025-03-26`), `notifications/initialized`, затем `tools/call` `{name, arguments}` по строке на вызов; ответ — строка с тем же `id`. Вызовы пачки идут параллельно: зависимые (связи с новыми записями) — следующей пачкой. Каждой записи — `idempotency_key` (CLI `--key`) вида `migrate-<вид>-<метка>`: повтор после сбоя не создаст дублей.

## 2. Опись источников

Сначала опись без записи: источник, число файлов, объём, период.
{?claude}- **Память Claude Code** — `~/.claude/projects/<папка>/memory/` (индекс `MEMORY.md`); `<папка>` — путь корня, где всё, кроме латинских букв и цифр, заменено на `-` (`C:\Work\Proj` → `C--Work-Proj`); папки с тем же началом (worktree) — тоже. В репозитории — `CLAUDE.md`, `CLAUDE.local.md`, `.claude/`.
{?claude}- **Журналы сессий** — `*.jsonl` в той же папке, файл — сессия.
{?codex}- **Память Codex** — `AGENTS.md` проекта и вложенные, `~/.codex/AGENTS.md` (общие указания владельца — кандидаты в Rules), заметки и планы в репозитории.
{?codex}- **Журналы сессий** — `~/.codex/sessions/ГГГГ/ММ/ДД/rollout-*.jsonl`, у которых `session_meta.payload.cwd` (первая строка) — внутри проекта.
{?agents}- **Память агента** — `AGENTS.md` (и вложенные), правила и заметки агента в репозитории (`.cursor/rules/`, `.github/copilot-instructions.md`, `GEMINI.md`, `.clinerules` и т. п.), планы.
{?agents}- **Журналы сессий** — если агент хранит их файлами; `zam sessions snapshot` читает только Claude Code и Codex, прочие — скриптом (п. 4).
- **Документация** — README, `docs/`, ADR, CHANGELOG, планы, отчёты исследований и аудитов; **git** — `git log` по вехам (теги, слияния).
- **Уже в памяти** — `zam tree`, `memory_search` по ключевым темам: есть — не дублируй, дополняй.

## 3. Раскладка по видам памяти

Одно знание — одна запись: дубли сливай; при противоречии побеждает новее и надёжнее, спорное — вопрос владельцу. Тексты источников пиши с `reject_secrets: true` (`memory_write`; `zam write|import --reject-secrets`): текст с секретом не ляжет даже ревизией — убери значение и повтори. У записей журналов (`insight`, `task`, `term`, `changelog`) флага нет — секреты из их текста убирай сам.
- **Указания и решения владельца** — `insight` с `certainty: theorem` и `data: {kind: "decision", decision: {context, chosen, rationale, decided_by: "human"}, evidence: {checked: "<источник>", method: "перенос памяти агента", result: "<суть>"}}`; не `axiom` — её ставит только владелец. Отвергнутый подход — `decision` с `options` или `failure`.
- **Правила для всех проектов** (поведение, не факт проекта) — кандидатами в Rules: `memory_write {path: "rules:/<путь>", content, candidate: {reason, basis}}` (`zam rules candidate`); принимает человек в WebUI. Правила из дайджеста не дублируй.
- **Ловушки и сбои** — `insight` `gotcha`/`failure` с триггерами (`file_glob` — маска пути от корня, `error_regex`, `command_regex`, `keyword` — слово целиком: «комиссия» не совпадёт с «комиссию») и `refs.files`. Широкий триггер (`**/*`, частое слово) — шум.
- **Архитектура, развёртывание, исследования, аудиты, обзоры** — заметки в папках по смыслу (`архитектура/`, `исследования/`…), дата — в имени (`2026-10-03-контур`), `l0` (сводка строкой) во frontmatter, связи — `[[путь]]` и `memory_link` (`zam link`). Папку .md удобно загрузить `zam import <каталог> --reject-secrets` (сначала `--dry-run`); заметка и папка с одним именем несовместимы.
- **Заметки входа** — `обзор` (что за проект, где что), `статус` (сделано, в работе), `окружение` (сборка, тесты, запуск; проверенные команды — с `verified_at: ГГГГ-ММ-ДД`) — в корне решения: дайджест показывает до 10 корней, заметки раньше папок.
- **Открытые работы** — `task` (план в `body`, `data.next_step`; ждёт владельца — `owner: human`), идущие — затем `status: in_progress`. Законченное — `changelog` (`data.kind`: `feat|fix|refactor|docs|research|ops|other`, дата — в начале заголовка: `ГГГГ-ММ-ДД: …`).
- **Термины** — `term`: `definition` до 300 символов, `aliases` (аббревиатуре — и строчными), `not_to_confuse` — массив.
- **Хосты, адреса, учётные данные** — только Vault: `zam vault set <имя> --type host --purpose … --address …`, секрет — `--secret-stdin`, общий для проектов — `--global`. В заметках — имя записи, без адресов и секретов.

## 4. Сессии

- Журналы не читай целиком (бывают в сотни мегабайт). По каждому, кроме журнала этой сессии, — `zam sessions snapshot --transcript <файл>` (длинный — `--tail-kb 16384`): снимок без LLM, с маскировкой секретов, — на сервер; прочитать — `zam sessions show <id>`. В снимке только хвост (5 запросов, 20 файлов, 10 команд, конспект); «снимать нечего» — пустой журнал.
- История — скриптом, построчно, с выводом в файл временного каталога, не в контекст: даты, запросы владельца, файлы правок, число команд; секреты и адреса маскируй сразу.
{?claude}  Запрос — строка `type: "user"` с текстом `message.content`, без `isMeta`, `isSidechain`, `tool_result` и `<command-…>`/`<system-reminder>`; время — `timestamp`; правки — `tool_use` `Edit`/`Write` с `input.file_path`.
{?codex}  Запрос — `event_msg` с `payload.type: "user_message"` (`payload.message`); время — `timestamp`; правки — `apply_patch`, команды — `function_call`.
- По выписке — заметки `история-работ/ГГГГ-ММ` (по дням: о чём просил владелец, что сделано, итог) и `история-работ/обзор`; чего нет в памяти агента — в решения, ловушки, задачи (п. 3).

## 5. Карта кода

- `zam code sync` из корня, затем `zam code status`: файлы по языкам, символы, пропуски — в отчёт.
- Чужой код (вендорный, сгенерированный) в «центральных» символах — маски `exclude` в `[code]` файла `.zeroaimemory/config.toml` и `zam code sync` снова; `.gitattributes` — только с согласия владельца.
- Знание об одной функции — ссылка `путь#Тип::метод` в `refs`.

## 6. Проверка

- Дайджест — `memory_recall {event: "session_start"}`: обзор и статус, задачи с `next_step`, окружение, правила, ловушки.
- 3–5 поисков по ключевым темам (`zam search "<тема>"`): нужное — в первых местах, иначе уточни `l0`, термин, псевдоним.
- Ловушка: `zam triggers sync`, затем из корня в stdin `zam hook pre-tool` — `{"hook_event_name":"PreToolUse","session_id":"migrate-check","tool_name":"Edit","tool_input":{"file_path":"<полный путь файла с ловушкой>"}}`: в ответе `ZeroAIMemory: для <маска>: …`; и `memory_recall {event: "brief", task: "<задача про этот файл>"}` — ловушка в `### Ловушки`.

## 7. Отчёт владельцу

`zam report <файл.md> --title "Перенос проекта в память"` — ссылку владельцу; себе — `changelog` (`data.kind: docs`). В отчёте:
- сколько перенесено: заметки, решения, ловушки (триггеры), задачи, changelog, термины, кандидаты в Rules, Vault, связи, карта кода;
- сессии: журналов всего, с работой, пустых, снимков, период; итог проверки;
- риски: секреты, найденные в истории, — где и совет сменить; что не перенесено и почему;
- вопросы: коммитить ли блок в `{agent_file}` и файлы подключения (память подключится в других клонах), кандидаты в Rules (WebUI «Предложения»), спорные решения;
- неудобства ZAM (команда — ожидал — получил).

## 8. Правила работы

- Не трогай незакоммиченную работу владельца и отслеживаемые файлы, кроме файлов подключения; удаляй только свои временные файлы.
- Временные файлы и скрипты — только в каталоге проекта, исключённом из git (например, `.zeroaimemory/migrate/`); системные временные каталоги — нет.
- Экономно: опись до чтения, большое — скриптом и частями, запись — пачками.
- Секреты — никогда в заметки, записи и вывод: значение — только в Vault через stdin.
- `axiom` не ставь: указания из памяти — `theorem`; аксиома — только по прямому слову владельца.
