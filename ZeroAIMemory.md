Создаем новый проект, максимально быстрый, легкий.
Цель - централизованная, человекочитаемая память для AI агентов.
Общий вид - аналог notion, obsidian, есть иерархическое дерево с записями.
Общий план решения:
- записи в формате markdown лежат в sqlite базе
- blob данные (изображения, документы, видео), хранятся в виде файлов, в записях где они отображаются - относительные ссылки в файловой системе на них
- все текстовые записи и документы разбиваются на семантические чанки, энкодятся через user-bge-m3 и сохраняются в qdrant для последующего RAG поиска, rag иерархический
- отдельные пользователи, для отдельного пользователя - отдельная sqlite база, плюс системная sqlite база с пользователями и глобальными параметрами
- админ видит все базы и записи
- Для каждой сесиии втроенные заметки:
	- changelog  - история изменений с датами
	- releaslog - история релизов со сравнением с прошлым релизом, если релизы есть
	- insights - открытия и провалы, сверяться в исследованиях с тем что уже опробовано, возможно, с пересмотром при новых идеях
	- vault - креды, пароли, токены, ссылки на репозитории и т.п.

### API
- все запросы с добавлением bearer токена, токен задается в настройках, и на клиенте в CLAUDE.md или AGENT.md
- контроллер для регистрации и входа
- запрос чанков и документов по поиску без саммаризации
- запрос документов по их идентификатору
- запрос вложений (blob данных)
- добавление записей в базу

Пример записи кредов для авторизации в CLAUDE.md или AGENT.md
```plaintext
ZeroAIMemoryToken=111  
ZeroAIMemoryLogin=test  
ZeroAIMemoryPassword=test
```


### WebUI
- авторизация через логин пароль, регистрироваться нельзя
- слева панель с деревом заметок, справа просмотр выбранного
- поддержка md формата
- если авторизован админ, то в панели он видит всех пользователей, по которым раскрываются их поддеревъя заметок


## На уровне агентов
В CLAUDE.md или AGENT.md прописываются правила работы с памятью, креды доступа.
В каталоге где идет работа создается каталог claude_solution_id с guid'ом, который используется как идентификатор для заметок на стороне сервисов, который объединяет их в единую группу. Соотвественно, если в claude_solution_id в разных каталогах идентификатор совпадает, для них будет общая группа, и как следствие общая память.

### Сервис
Кроме заметок разбитых по группам, есть еще общие группы для всех. Это Rules, в которой описываются какие либо дополнительные правила работы, Human - общие сведения, в ней пользователь может записывать свои заметки, эта группа только для пользователя, поиск для агентов в ней не работает. Эти группы всегда в топе панели.

### Сценарии

**Работа над проектом**
Есть рабочее решение на C#, а также набор python сервисов. Все это связано в едином рабочем проекте.
По отдельным python сервисам и по проектам C# создаются сессии, в которых производится доработка, исследования, аудит кода и т.п.

Запрос памяти - раг - чанки и источники - реранк - выжимка и саммаризация - кэш сессии - использовать в работе
Про кэш в оптимизациях далее.
### Оптимизации
Нужен кэш по сессии, в котором хранится запрос и саммаризованный ответ, если в кеше есть относительно свежее, использовать его, инвалилация кэша по ходу работы, при обновлении источников. То есть в записи кэша хранить id источников, если в них есть изменения - запись перестает быть валидной
